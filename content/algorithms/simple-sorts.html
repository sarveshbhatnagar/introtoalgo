You put five numbered books back on a shelf: 7, 3, 9, 4, 1. You take them one at a time, and each slides left past the bigger numbers until it fits. Soon the shelf reads 1, 3, 4, 7, 9.

That habit is insertion sort. With its cousins, selection sort and bubble sort, it makes up the "simple sorts". They are slow on big inputs, but short, need no extra memory, and one still runs inside the built-in sort of Python and JavaScript.

The idea: grow a sorted part

All three keep a sorted part at the front and an unsorted part after it. Each round moves one item into the sorted part. They differ in how they pick and place it:

  • Insertion sort takes the next item and slides it left into place.
  • Selection sort finds the smallest unsorted item and swaps it to the end of the sorted part.
  • Bubble sort swaps out-of-order neighbours, carrying the largest item to the end.

Insertion sort, traced

Watch key: it holds the book in your hand while bigger books shift right to make a gap.

That last step is the key fact: each shift fixes exactly one out-of-order pair. A sorted array has none, so insertion sort does one comparison per item and finishes in O(n). An almost sorted array is almost that fast.

function insertionSort(a) {
  for (let i = 1; i < a.length; i++) {
    const key = a[i];
    let j = i - 1;
    // shift bigger items one slot right to open a gap
    while (j >= 0 && a[j] > key) {
      a[j + 1] = a[j];
      j--;
    }
    a[j + 1] = key; // the gap is just right of j
  }
  return a;
}

insertionSort([7, 3, 9, 4, 1]); // [1, 3, 4, 7, 9]

def insertion_sort(a):
    for i in range(1, len(a)):
        key = a[i]
        j = i - 1
        # shift bigger items one slot right to open a gap
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key  # the gap is just right of j
    return a

insertion_sort([7, 3, 9, 4, 1])  # [1, 3, 4, 7, 9]

Selection sort and bubble sort

Selection sort makes at most one swap per round, so it writes very little. But its scan for the smallest item always runs to the end, so sorted input is no faster.

Bubble sort's passes carry the largest item to the end, like a bubble rising, and a pass with no swaps means it can stop early. It is easy to explain and almost never the right choice. It swaps once per out-of-order pair, like insertion sort's shifts, but a swap writes two slots where a shift writes one. And each pass compares every pair it walks over, while insertion sort stops as soon as an item fits.

function selectionSort(a) {
  for (let i = 0; i < a.length - 1; i++) {
    let min = i;
    for (let j = i + 1; j < a.length; j++) {
      if (a[j] < a[min]) min = j;
    }
    [a[i], a[min]] = [a[min], a[i]]; // one swap per round
  }
  return a;
}

function bubbleSort(a) {
  for (let end = a.length - 1; end > 0; end--) {
    let swapped = false;
    for (let j = 0; j < end; j++) {
      if (a[j] > a[j + 1]) {
        [a[j], a[j + 1]] = [a[j + 1], a[j]];
        swapped = true;
      }
    }
    if (!swapped) break; // no swaps: already sorted
  }
  return a;
}

def selection_sort(a):
    for i in range(len(a) - 1):
        smallest = i
        for j in range(i + 1, len(a)):
            if a[j] < a[smallest]:
                smallest = j
        a[i], a[smallest] = a[smallest], a[i]  # one swap per round
    return a

def bubble_sort(a):
    for end in range(len(a) - 1, 0, -1):
        swapped = False
        for j in range(end):
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                swapped = True
        if not swapped:  # no swaps: already sorted
            break
    return a

Why they are O(n²)

In the worst case, reverse order, insertion sort shifts the second item 1 slot, the third 2, and so on up to n − 1: 1 + 2 + … + (n − 1) = n(n − 1) / 2 shifts, which is O(n²). Selection sort always does that many comparisons. With 10,000 items that is about 50 million steps; with a million, about 500 billion.

All three work inside the array they are given, with O(1) extra space. Such algorithms are called in place.

Stable sorts keep ties in order

A teacher's list is in alphabetical order, and she sorts it by score: Ann 82, Ben 75, Cal 82, Dee 75. A stable sort keeps equal keys in their original order: Ben 75, Dee 75, Ann 82, Cal 82. Within each score, names stay alphabetical.

Insertion sort is stable because it only shifts an item past strictly bigger ones (a[j] > key). Selection sort is not: its long-distance swap can jump an item over an equal one. Round one swaps Ben to the front. Round two swaps Dee with Ann, throwing Ann behind Cal. The result, Ben 75, Dee 75, Cal 82, Ann 82, has the 82s out of alphabetical order.

A stable sort never reorders items that compare equal, so you can sort by one field, then another, and keep both orders.

Common mistakes

With a[j] >= key, an item slides past equal items too: ties come out reversed, the sort loses stability, and it does extra shifts. Use a strict >.

[10, 9, 1].sort() returns [1, 10, 9]: without a compare function, JavaScript compares strings, and "10" comes before "9". For numbers, use nums.sort((x, y) => x - y). Python compares numbers as numbers.

The first shift, a[j + 1] = a[j], overwrites a[i]. Copy it into key before the inner loop.

Python's built-in sort and V8's (the JavaScript engine in Chrome and Node) both use Timsort. It finds already-sorted stretches, extends short ones with insertion sort, and merges them. Insertion sort is very fast on small or nearly sorted pieces.

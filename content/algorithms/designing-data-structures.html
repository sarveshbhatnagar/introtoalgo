Your phone keeps your three most recent apps in memory, so they open instantly. Open a fourth, and it drops the one untouched for longest.

That needs three O(1) operations: find an app by name, mark it "just used", and find the least recently used. An array finds the oldest but not a name; a hash map finds a name but knows no order. Use both, wired together.

A method for design questions

"Design a structure that supports these operations" problems yield to four steps.

  1. List the operations and the cost you need for each, such as get and put in O(1). The target usually decides the design.
  2. Name the structure that makes each operation cheap. Lookup by key: hash map. Last in, first out: stack. Smallest: heap. Order with cheap removal from the middle: doubly linked list.
  3. Combine them, and decide what links them. Usually one part stores pointers or indexes into another, so you never search.
  4. Keep every part in sync. Write down the rule that must hold after every call, and check each method against it.

When a structure is slow at some operations, pair it with one that covers them, and make every operation update both.

Worked design 1: a stack that knows its minimum

You want a stack with push, pop, top and getMin, all O(1). On a plain stack, getMin is an O(n) scan.

One variable holding the smallest value handles push, but pop that value and you must scan for the new minimum: the variable forgot the history.

So store the history. For every value, record the minimum at the moment it was pushed, in a second stack that grows and shrinks with the first. Its top is always the current minimum, and popping both restores the old minimum for free.

class MinStack {
  constructor() {
    this.values = [];
    this.mins = []; // mins[i] = smallest of values[0..i]
  }
  push(x) {
    const currentMin = this.mins.length ? this.mins[this.mins.length - 1] : x;
    this.values.push(x);
    this.mins.push(Math.min(x, currentMin));
  }
  pop() {
    this.mins.pop();
    return this.values.pop();
  }
  top() { return this.values[this.values.length - 1]; }
  getMin() { return this.mins[this.mins.length - 1]; }
}

class MinStack:
    def __init__(self):
        self.values = []
        self.mins = []  # mins[i] = smallest of values[0..i]

    def push(self, x):
        current_min = self.mins[-1] if self.mins else x
        self.values.append(x)
        self.mins.append(min(x, current_min))

    def pop(self):
        self.mins.pop()
        return self.values.pop()

    def top(self):
        return self.values[-1]

    def get_min(self):
        return self.mins[-1]

The rule: mins[i] is the smallest of values[0..i], and both stacks have the same height. push and pop change both by one, so it always holds.

Worked design 2: an LRU cache

Back to the phone. An LRU cache ("least recently used") holds at most capacity key-value pairs. get(key) returns the value and counts as a use. put(key, value) adds or replaces a pair, first evicting the pair used longest ago if the cache is full. Both must be O(1).

  • Find by key: a hash map.
  • Keep order of use, move any item to the front, remove from the back: a doubly linked list. With prev and next pointers, unlinking a node you hold is O(1).
  • The link: the map stores key → node, not key → value, so get reaches a node without walking the list. Each node also stores its key, so evicting the last node can delete its map entry.

Two dummy nodes, the sentinels head and tail, are never removed, so every real node has neighbours on both sides and the code needs no empty-list case.

class LRUCache {
  constructor(capacity) { // capacity >= 1
    this.capacity = capacity;
    this.map = new Map(); // key -> node
    this.head = { next: null }; // sentinel on the newest side
    this.tail = { prev: this.head }; // sentinel on the oldest side
    this.head.next = this.tail;
  }
  unlink(node) {
    node.prev.next = node.next;
    node.next.prev = node.prev;
  }
  addFront(node) {
    node.prev = this.head;
    node.next = this.head.next;
    this.head.next.prev = node;
    this.head.next = node;
  }
  get(key) {
    const node = this.map.get(key);
    if (node === undefined) return null;
    this.unlink(node); // a get counts as a use
    this.addFront(node);
    return node.value;
  }
  put(key, value) {
    if (this.map.has(key)) {
      this.unlink(this.map.get(key));
    } else if (this.map.size === this.capacity) {
      const oldest = this.tail.prev;
      this.unlink(oldest);
      this.map.delete(oldest.key); // why the node stores its key
    }
    const node = { key, value };
    this.addFront(node);
    this.map.set(key, node);
  }
}

class Node:
    def __init__(self, key=None, value=None):
        self.key, self.value = key, value
        self.prev = self.next = None

class LRUCache:
    def __init__(self, capacity):  # capacity >= 1
        self.capacity = capacity
        self.map = {}  # key -> node
        self.head, self.tail = Node(), Node()  # sentinels
        self.head.next, self.tail.prev = self.tail, self.head

    def _unlink(self, node):
        node.prev.next = node.next
        node.next.prev = node.prev

    def _add_front(self, node):
        node.prev, node.next = self.head, self.head.next
        self.head.next.prev = node
        self.head.next = node

    def get(self, key):
        node = self.map.get(key)
        if node is None:
            return None
        self._unlink(node)  # a get counts as a use
        self._add_front(node)
        return node.value

    def put(self, key, value):
        if key in self.map:
            self._unlink(self.map[key])
        elif len(self.map) == self.capacity:
            oldest = self.tail.prev
            self._unlink(oldest)
            del self.map[oldest.key]  # why the node stores its key
        node = Node(key, value)
        self._add_front(node)
        self.map[key] = node

A JavaScript Map keeps insertion order: delete and re-set a key to mark it used; the oldest is map.keys().next().value. Python's collections.OrderedDict has move_to_end and popitem(last=False). Use them in real code; in an interview, expect to build the list yourself.

More pairings worth knowing

  • Hash map + array: insert, delete and pick a random item in O(1). The map stores each value's index; to delete, move the last item into the gap, update its index, and pop the end.
  • Two heaps: a running median. A max-heap holds the smaller half, a min-heap the larger, and the median sits on top. See Heaps and Priority Queues.
  • Hash map + heap: a top-k leaderboard with changing scores. The map holds current scores; stale heap entries are skipped when they reach the top.

Common mistakes

Evict the last node but leave its key in the map, and a later get returns a node no longer in the list. After each method, ask: is the map still exactly the keys in the list?

If get does not move the node, the cache evicts by insertion time, not last use. In the trace, it would throw out mail right after you used it.

With key → value, the map cannot tell you where the node sits, so moving it means walking the list: O(n). Store the node.

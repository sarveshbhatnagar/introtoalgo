You read a new problem once and your mind goes blank. Or you start typing, get halfway, and realise you are solving the wrong thing. Both happen to everyone.

Experienced people do not remember more tricks. They have a routine that gets them from "no idea" to working code.

The seven steps

  1. Restate the problem: input, output, size limits, and odd cases (empty input, no answer, ties).
  2. Solve a small example by hand with 5 to 8 items. What you do is a first algorithm.
  3. Write the brute force: the most obvious correct method, even if slow. Work out its cost.
  4. Find the waste. What does the brute force compute again and again, or check when it cannot matter?
  5. Pick a pattern that removes that waste. The table below helps.
  6. Write the code.
  7. Test edge cases: empty, one item, all the same, the answer at each end.

Skip steps 1 and 2 and you pay later, debugging an answer to the wrong question.

A worked problem

Your phone counts your steps each day, and your goal is 8,000. Find your longest streak: the most days in a row on which you hit the goal.

1. Restate it

Input: a list steps, one whole number per day in order, and a number goal. Output: the length of the longest run of neighbouring days with steps[i] >= goal.

Decide the odd cases before coding. Exactly 8,000 counts. No hits gives 0, and so does an empty list. Plan for up to 100,000 days.

2. Solve a small example by hand

Take a week: 8,200, 9,100, 4,000, 8,500, 10,200, 9,000, 2,500. Mark each day: ✓ ✓ ✗ ✓ ✓ ✓ ✗. The runs of ticks have lengths 2 and 3, so the answer is 3.

Your eyes did one scan, counting ticks and restarting at each cross.

3. Write the brute force

Try every day as the start of a streak, walk forward while the goal is met, and keep the longest walk.

function longestStreakSlow(steps, goal) {
  let best = 0;
  for (let start = 0; start < steps.length; start++) {
    let length = 0;
    while (start + length < steps.length && steps[start + length] >= goal) {
      length++;
    }
    best = Math.max(best, length);
  }
  return best;
}

def longest_streak_slow(steps, goal):
    best = 0
    for start in range(len(steps)):
        length = 0
        while start + length < len(steps) and steps[start + length] >= goal:
            length += 1
        best = max(best, length)
    return best

Never skip it: it takes two minutes and gives you something to test against. But if every day hits the goal, the walks total about n²/2 checks (see Math for Algorithms): 5 billion for 100,000 days. Too slow.

4. Find the waste

A walk that starts mid-streak can never beat the one from the streak's start. And each walk re-checks the same days only to stop at day 6 again.

Ask: "What do I know about today, given yesterday?" If today hits the goal, the streak ending today is yesterday's plus 1; otherwise 0. One number carried day to day replaces all the walks.

5. Pick a pattern

This is the simplest pattern: one pass, carrying a running value, like "best so far" in What Is an Algorithm. Here you carry two: the current streak and the best. It is also the simplest sliding window.

6. Write the code

function longestStreak(steps, goal) {
  let best = 0;
  let current = 0; // length of the streak that ends today
  for (const day of steps) {
    current = day >= goal ? current + 1 : 0;
    best = Math.max(best, current); // update every day
  }
  return best;
}

longestStreak([8200, 9100, 4000, 8500, 10200, 9000, 2500], 8000); // 3

def longest_streak(steps, goal):
    best = 0
    current = 0  # length of the streak that ends today
    for day in steps:
        current = current + 1 if day >= goal else 0
        best = max(best, current)  # update every day
    return best

longest_streak([8200, 9100, 4000, 8500, 10200, 9000, 2500], 8000)  # 3

7. Test the edge cases

Run each through the one-pass code. All are correct:

  • []: the loop never runs, returns 0.
  • [3000, 5000]: no day hits, returns 0.
  • [8000]: exactly the goal counts, returns 1.
  • [9000, 9000, 9000]: every day hits, returns 3.
  • [2000, 9000, 9000]: the best streak is at the end, returns 2. This one catches the most bugs.

Also run both versions on many random small lists and check they agree.

At a few hundred million simple steps per second, size limits tell you what cost you can afford:

n up to aboutAffordable cost
10O(n!): every order
20O(2ⁿ): every subset
a few thousandO(n²): every pair
1,000,000O(n log n)
100,000,000O(n), and only simple work per item
beyond thatO(log n) or O(1): you cannot read every item

Common mistakes

A first draft often updates best only when a streak ends. On [2000, 9000, 9000] the last streak never ends, so it returns 0 instead of 2. Update the best after every item, or check once more after the loop.

If n is at most 500, O(n²) is 250,000 steps: instant. Check the limits before reaching for a harder method.

Stuck at step 4? Ask what the brute force computes more than once, what it checks that cannot change the answer, and what would help to have sorted, counted or remembered.

A café offers you shifts on five days in a row, paying 5, 9, 6, 1, 4. You can never work two days in a row. Which days earn the most?

Grabbing the 9 first rules out the 5 and the 6; add the 4 and you have 13. But 5 + 6 + 4 = 15. You need to weigh every day against its neighbours, and a one-row table does exactly that.

The five steps

Use the recipe from Introduction to Dynamic Programming.

  1. State. best[i] is the most you can earn using only days 0 to i.
  2. Recurrence. On day i you rest or work. Rest and you keep best[i − 1]. Work and you earn pay[i], but day i − 1 must be free, so add best[i − 2]. Take the larger: best[i] = max(best[i − 1], pay[i] + best[i − 2]).
  3. Base cases. best[0] = pay[0], and best[1] = max(pay[0], pay[1]).
  4. Order. Each cell reads the two cells to its left, so fill left to right.
  5. Answer. best[n − 1].

The two options cover every plan. A plan that skips day i is a plan for the earlier days, best best[i − 1]. A plan that uses it is, apart from day i, a plan for days 0 to i − 2, best best[i − 2].

Fill the table by hand

To recover the days, walk back from the last cell. If a cell equals the one to its left, that day was rest: step one left. If it is bigger, that day was worked: note it and jump two left. 15 > 11, so day 4 is worked; jump to best[2]. 11 > 9, so day 2 is worked; jump to best[0], day 0.

The code, then less memory

function maxPay(pay) {
  const n = pay.length;
  if (n === 0) return 0;
  if (n === 1) return pay[0];
  const best = new Array(n);
  best[0] = pay[0];
  best[1] = Math.max(pay[0], pay[1]);
  for (let i = 2; i < n; i++) {
    const rest = best[i - 1];
    const work = pay[i] + best[i - 2];
    best[i] = Math.max(rest, work);
  }
  return best[n - 1];
}

maxPay([5, 9, 6, 1, 4]); // 15

Each step reads only the two most recent cells, so keep two variables instead of an array. Starting both at 0 removes the special cases, because "the best before any days" is 0.

function maxPayLowMemory(pay) {
  let twoBack = 0; // best up to day i - 2
  let oneBack = 0; // best up to day i - 1
  for (const p of pay) {
    const current = Math.max(oneBack, p + twoBack);
    twoBack = oneBack; // slide the window right by one day
    oneBack = current;
  }
  return oneBack;
}

def max_pay_low_memory(pay):
    two_back = 0  # best up to day i - 2
    one_back = 0  # best up to day i - 1
    for p in pay:
        current = max(one_back, p + two_back)
        two_back = one_back  # slide the window right by one day
        one_back = current
    return one_back

Write the table version first and shrink it once it works. The shrunk version cannot walk back to list the chosen days.

The same shape, counting instead

The recurrence need not take a max. Climb 6 steps with strides of 1, 2 or 3. How many stride sequences reach the top?

State: ways[i] is the number of ways to stand on step i. Recurrence: the last stride came from step i − 1, i − 2 or i − 3; these never overlap, so add them: ways[i] = ways[i − 1] + ways[i − 2] + ways[i − 3], skipping any index below 0. Base case: ways[0] = 1. Order: upward. Answer: ways[6].

function countClimbs(steps) {
  const ways = new Array(steps + 1).fill(0);
  ways[0] = 1; // standing at the bottom: one way, do nothing
  for (let i = 1; i <= steps; i++) {
    for (const stride of [1, 2, 3]) {
      if (i - stride >= 0) ways[i] += ways[i - stride];
    }
  }
  return ways[steps];
}

countClimbs(6); // 24

def count_climbs(steps):
    ways = [0] * (steps + 1)
    ways[0] = 1  # standing at the bottom: one way, do nothing
    for i in range(1, steps + 1):
        for stride in (1, 2, 3):
            if i - stride >= 0:
                ways[i] += ways[i - stride]
    return ways[steps]

count_climbs(6)  # 24

A 1D DP fits when the input is a line and the answer for the first i items builds from a few shorter prefixes. Maximise with max, minimise with min, count with a sum.

Common mistakes

"0 ways to climb 0 steps" makes every cell a sum of zeros. The empty sequence is one valid way. For counting, the base case is almost always 1: one way to do nothing.

Writing oneBack = current before twoBack = oneBack copies the new value into both. Compute into a temporary, then shift from the oldest end.

At i = 1 the recurrence asks for best[−1]. JavaScript returns undefined and the max becomes NaN; Python reads the last element. Handle the first cells as base cases, or start from 0 as the two-variable version does.

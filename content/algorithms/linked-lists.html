Picture a treasure hunt. Each clue only tells you where the next clue is hidden, until one says "this is the end".

To add a clue after the first, nobody moves anything. The new clue points where the first pointed, and the first points at the new one. Two edits, however long the hunt. That is a linked list.

Nodes and pointers

A linked list is a chain of nodes. Each holds a value and a reference to the next node, next. The last node's next is null (None in Python). You hold the first node, the head, and reach the rest by following arrows.

An array can jump to arr[1000] in one step, but inserting at the front shifts every item. A linked list makes the opposite trade: no jumping, but inserting or removing next to a node you hold rewires an arrow or two.

To walk the list, follow next from the head until null. Insert and delete are one line each, given the node before the spot.

class ListNode {
  constructor(val, next = null) {
    this.val = val;
    this.next = next;
  }
}

function printList(head) {
  const parts = [];
  for (let node = head; node !== null; node = node.next) parts.push(node.val);
  console.log(parts.join(" -> ") + " -> null");
}

function insertAfter(node, val) {
  node.next = new ListNode(val, node.next); // new node points where node pointed
}

function deleteAfter(node) {
  if (node.next !== null) node.next = node.next.next; // skip over it
}

// Build 4 -> 7 -> 2 -> 5 by adding at the front, last value first.
let head = null;
for (const v of [5, 2, 7, 4]) head = new ListNode(v, head);
insertAfter(head, 9);
printList(head); // 4 -> 9 -> 7 -> 2 -> 5 -> null

class ListNode:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

def print_list(head):
    parts = []
    node = head
    while node is not None:
        parts.append(str(node.val))
        node = node.next
    print(" -> ".join(parts) + " -> None")

def insert_after(node, val):
    node.next = ListNode(val, node.next)  # new node points where node pointed

def delete_after(node):
    if node.next is not None:
        node.next = node.next.next  # skip over it

# Build 4 -> 7 -> 2 -> 5 by adding at the front, last value first.
head = None
for v in [5, 2, 7, 4]:
    head = ListNode(v, head)
insert_after(head, 9)
print_list(head)  # 4 -> 9 -> 7 -> 2 -> 5 -> None

Order matters in insertAfter: the new node grabs node.next before node.next changes. Reverse that and you lose the rest of the list.

Reversing a list in place

Reversal drills the "save before you overwrite" rule. Flip every arrow, so 4 → 7 → 2 → 5 becomes 5 → 2 → 7 → 4, with no extra list.

As you walk, the reversed chain is behind you, held by prev, and the untouched rest is ahead, starting at current. Each step moves one node from the rest onto the front of the reversed chain.

function reverse(head) {
  let prev = null;
  let current = head;
  while (current !== null) {
    const next = current.next; // 1. save the rest of the list
    current.next = prev;       // 2. flip this node's arrow
    prev = current;            // 3. step both pointers forward
    current = next;
  }
  return prev; // the old last node is the new head
}

def reverse(head):
    prev = None
    current = head
    while current is not None:
        nxt = current.next   # 1. save the rest of the list
        current.next = prev  # 2. flip this node's arrow
        prev = current       # 3. step both pointers forward
        current = nxt
    return prev  # the old last node is the new head

An empty list needs no special case: the loop never runs.

Fast and slow pointers

A linked list cannot tell you its length or middle without a walk. But you can walk it with two pointers: slow takes one step at a time, fast takes two. It is the same-direction shape from Two Pointers, with speed as the twist.

Finding the middle in one pass

When fast reaches the end, it has gone twice as far as slow, so slow is halfway.

An even count has two middles. For 10 → 20 → 30 → 40 → 50 → 60 this loop returns 40, the second. For the first, loop while fast.next != null and fast.next.next != null and handle an empty list first.

Detecting a cycle

If a bug makes the last node point back into the list, a plain walk never ends. Run the same two pointers. Without a cycle, fast falls off the end. With one, both end up circling it, like two runners on a track. fast gains one node per round, so the gap shrinks by one each time and fast cannot jump over slow: they must land on the same node.

function middle(head) {
  let slow = head;
  let fast = head;
  while (fast !== null && fast.next !== null) {
    slow = slow.next;      // one step
    fast = fast.next.next; // two steps
  }
  return slow;
}

function hasCycle(head) {
  let slow = head;
  let fast = head;
  while (fast !== null && fast.next !== null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow === fast) return true; // fast lapped slow
  }
  return false; // fast fell off the end
}

def middle(head):
    slow = fast = head
    while fast is not None and fast.next is not None:
        slow = slow.next       # one step
        fast = fast.next.next  # two steps
    return slow

def has_cycle(head):
    slow = fast = head
    while fast is not None and fast.next is not None:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:  # fast lapped slow
            return True
    return False  # fast fell off the end

Both run in O(n) time and O(1) space: slow enters the loop within n steps, and the gap closes within another n rounds. A set of visited nodes also works, but costs O(n) memory.

A linked list trades instant indexing for cheap rewiring. Save a link before you overwrite it.

Common mistakes

Writing current.next = prev before next = current.next loses the second half of the list. Before assigning to .next, ask: "do I still need the old value?" If yes, save it first.

fast.next.next crashes if fast is null. So the loop checks fast != null before fast.next != null. Swap them and an empty or even-length list crashes.

Changing the front changes the head. If your function returns nothing, the caller keeps a stale head. Return the new head, or start from a dummy node before the real head so the front is never a special case.

An LRU cache pairs a hash map with a doubly linked list (nodes also have prev), so any item moves to the front in O(1).

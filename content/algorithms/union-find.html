You look after an office network of six computers, numbered 0 to 5. All day, someone plugs in a cable between two of them, and people ask things like "can computer 5 talk to computer 1 yet?"

A BFS or DFS per question walks the whole network every time: with 100,000 computers and 100,000 questions, billions of steps. You do not need paths, only which group each computer is in, and a way to merge two groups. A union-find structure does that in a few steps per operation.

The idea: every group has a boss

Each group has one member as its root, like a team captain. Every computer stores its parent, the computer it reports to. A root reports to itself, so at the start everyone is their own root.

  • find(x): follow parent pointers from x to a computer that is its own parent: the root. Two computers are connected exactly when they share a root.
  • union(a, b): find both roots. If they differ, make one report to the other. One pointer change merges two whole groups.

Union never touches the other members. They still report to the old root, which now reports to the new one, so their find ends at the right place, one hop later.

Two tricks that keep trees flat

The whole cost of union-find is the walk inside find. Suppose you always put the first root under the second, and cables arrive as 0–1, 1–2, 2–3, 3–4. Each union hangs the existing group under one new computer, building a chain: find(0) takes n steps, no better than searching the graph.

Union by size. Hang the smaller group's root under the bigger one's. A computer gets one hop deeper only when its group joins one at least as big, so its group at least doubles. That can happen only about log₂ n times, so no walk exceeds log₂ n hops: 20 for a million computers.

Path compression. Whenever find walks a path, point every computer on it straight at the root. The walk was happening anyway, and the next find from any of them takes one hop.

Union-find compares roots to answer "same group?". Union by size and path compression keep trees so flat that every operation is, in practice, constant time.

The code

class UnionFind {
  constructor(n) {
    this.parent = Array.from({ length: n }, (_, i) => i); // everyone is their own root
    this.size = new Array(n).fill(1);
    this.groups = n;
  }

  find(x) {
    if (this.parent[x] !== x) {
      this.parent[x] = this.find(this.parent[x]); // path compression
    }
    return this.parent[x];
  }

  union(a, b) {
    let rootA = this.find(a);
    let rootB = this.find(b);
    if (rootA === rootB) return false; // already in the same group
    if (this.size[rootA] < this.size[rootB]) [rootA, rootB] = [rootB, rootA];
    this.parent[rootB] = rootA; // smaller tree goes under the bigger one
    this.size[rootA] += this.size[rootB];
    this.groups--;
    return true;
  }
}

class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))  # everyone is their own root
        self.size = [1] * n
        self.groups = n

    def find(self, x):
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])  # path compression
        return self.parent[x]

    def union(self, a, b):
        root_a, root_b = self.find(a), self.find(b)
        if root_a == root_b:
            return False  # already in the same group
        if self.size[root_a] < self.size[root_b]:
            root_a, root_b = root_b, root_a
        self.parent[root_b] = root_a  # smaller tree goes under the bigger one
        self.size[root_a] += self.size[root_b]
        self.groups -= 1
        return True

To test "are a and b connected?", compare find(a) with find(b). The groups counter tracks how many pieces the network is in, with no search; it drops only when a union really merges.

When union returns false, the two computers were already connected, so the new cable closes a loop. That detects a cycle in an undirected graph as you read its edges, and it is the heart of Kruskal's algorithm in Minimum Spanning Trees.

"Amortized" means averaged over many operations. One find can take a few hops, but it flattens its path, so later finds are cheaper.

Common mistakes

parent[a] === parent[b] is not a connection test. Right after the 1–3 cable, parent[1] was 0 and parent[3] was 2, yet they were in one group. Compare find(a) and find(b).

parent[a] = b moves only a: the rest of its old group stays behind. Find both roots and link root to root.

Union-find can only merge; it cannot undo a union when a cable is unplugged. For removals, use a graph search, or process changes in reverse so removals become additions.

Image editors use union-find to label connected blobs of pixels, compilers to merge type variables that must be equal, and networking tools to track which machines can reach each other as links come up.

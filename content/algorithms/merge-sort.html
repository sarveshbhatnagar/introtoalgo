Two teaching assistants each sort half a stack of exam papers by score and hand you their piles, face up. To make one sorted pile, look at the top paper of each, take the lower score, and repeat. Each paper costs one glance.

That merge step is the whole trick. Merging two sorted lists is cheap, so two sorted halves give a sorted whole. To sort each half, use the same trick again.

The idea: split, sort, merge

Merge sort is recursive:

  1. Base case. A list of 0 or 1 items is already sorted. Return it.
  2. Split the list into a left half and a right half.
  3. Sort each half with merge sort.
  4. Merge the two sorted halves into one sorted list.

Step 3 calls the function you are still writing. That works because every call gets a smaller list and eventually hits the base case. The real work happens on the way back up, in the merges. Splitting a problem, solving the parts and combining them is called divide and conquer.

The code

This version returns a new sorted list and leaves the input alone.

function mergeSort(a) {
  if (a.length <= 1) return a; // base case
  const mid = Math.floor(a.length / 2);
  const left = mergeSort(a.slice(0, mid));
  const right = mergeSort(a.slice(mid));
  return merge(left, right);
}

function merge(left, right) {
  const out = [];
  let i = 0, j = 0;
  while (i < left.length && j < right.length) {
    // <= takes from the left on ties: that keeps the sort stable
    if (left[i] <= right[j]) out.push(left[i++]);
    else out.push(right[j++]);
  }
  // one half is empty; the rest of the other is already sorted
  while (i < left.length) out.push(left[i++]);
  while (j < right.length) out.push(right[j++]);
  return out;
}

mergeSort([6, 2, 9, 5, 1, 8, 3, 7]); // [1, 2, 3, 5, 6, 7, 8, 9]

def merge_sort(a):
    if len(a) <= 1:  # base case
        return a
    mid = len(a) // 2
    left = merge_sort(a[:mid])
    right = merge_sort(a[mid:])
    return merge(left, right)

def merge(left, right):
    out = []
    i = j = 0
    while i < len(left) and j < len(right):
        # <= takes from the left on ties: that keeps the sort stable
        if left[i] <= right[j]:
            out.append(left[i])
            i += 1
        else:
            out.append(right[j])
            j += 1
    # one half is empty; the rest of the other is already sorted
    out.extend(left[i:])
    out.extend(right[j:])
    return out

merge_sort([6, 2, 9, 5, 1, 8, 3, 7])  # [1, 2, 3, 5, 6, 7, 8, 9]

Why it is O(n log n)

In the figure, every merge row handles all n items once: O(n) per row. You can halve n only about log₂ n times before reaching single items, so there are log₂ n rows: 3 for 8 items, about 20 for a million.

The total is n × log n = O(n log n). For a million items, that is about 20 million steps against about 500 billion for the simple sorts. Unlike insertion sort, the input's order does not matter: sorted, reversed or random, the work is about the same.

The price is memory. The merge writes into a new list, so merge sort needs O(n) extra space. The recursion only goes log n calls deep.

Merging two sorted lists takes one pass. Merge sort is about log n rounds of merging: O(n log n) on any input.

Stable, if you write it right

On a tie, the code takes the left item, which came first in the original list. So equal items keep their order, making merge sort stable: the usual choice for sorting records by several fields.

Common mistakes

With left[i] < right[j], a tie takes the right item first, so equal items swap order and the sort is not stable. Write <=.

The main loop stops when one half runs out. Forget to copy the rest of the other half and those items vanish, like the 9 in the trace.

With only a.length === 1 as the base case, an empty input recurses forever. Use <= 1. Split at mid = floor(n / 2) into [0, mid) and [mid, n), so both halves are smaller whenever n is 2 or more.

Merge sort shines when data does not fit in memory. A database sorting a 100 GB table sorts chunks that fit in RAM, writes them to disk, then merges them front to back. It suits linked lists too, since merging only walks forward.

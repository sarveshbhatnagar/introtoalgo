A café records its takings each day: 5, 2, 6, 3, 1, 4. The owner keeps asking: how much from day 3 to day 5? Day 1 to day 4? Each answer means adding up a stretch of numbers again.

A car's odometer has the answer. To know how far you drove between two towns, you read the odometer at each and subtract. Keep a running total of the takings, and every "how much between here and there?" becomes one subtraction.

The idea: running totals, then subtract

Build an array prefix where prefix[i] is the sum of the first i items. It starts with prefix[0] = 0, the sum of no items, so it is one longer than the input.

Number the days from 0, so days 3 to 5 are items 2 to 4. The sum of items l to r, both included, is everything up to r minus everything before l:

sum(l..r) = prefix[r + 1] − prefix[l]

function buildPrefix(nums) {
  const prefix = [0];
  for (let i = 0; i < nums.length; i++) {
    prefix.push(prefix[i] + nums[i]);
  }
  return prefix;
}

// Sum of nums[l..r], both ends included.
function rangeSum(prefix, l, r) {
  return prefix[r + 1] - prefix[l];
}

const prefix = buildPrefix([5, 2, 6, 3, 1, 4]); // [0, 5, 7, 13, 16, 17, 21]
rangeSum(prefix, 2, 4); // 10

def build_prefix(nums):
    prefix = [0]
    for i in range(len(nums)):
        prefix.append(prefix[i] + nums[i])
    return prefix

# Sum of nums[l..r], both ends included.
def range_sum(prefix, l, r):
    return prefix[r + 1] - prefix[l]

prefix = build_prefix([5, 2, 6, 3, 1, 4])  # [0, 5, 7, 13, 16, 17, 21]
range_sum(prefix, 2, 4)  # 10

Pay O(n) once for running totals, and any range sum is one subtraction: prefix[r + 1] − prefix[l].

Counting runs with a given total

Add a hash map and prefix sums can count runs. Given daily profits and losses, [2, −1, 3, −2, 2]: how many runs of days in a row add up to exactly 2?

Checking every run is O(n²), and a sliding window fails because the losses are negative. But a run ending here sums to 2 exactly when an earlier running total equals current running total − 2. So walk once, keeping the running total and a map of how often each total has appeared. At each day, look up how many earlier totals make a run of 2.

function countRunsWithSum(nums, k) {
  const seen = new Map([[0, 1]]); // the empty start
  let running = 0;
  let count = 0;
  for (const x of nums) {
    running += x;
    count += seen.get(running - k) ?? 0;
    seen.set(running, (seen.get(running) ?? 0) + 1);
  }
  return count;
}

countRunsWithSum([2, -1, 3, -2, 2], 2); // 5

def count_runs_with_sum(nums, k):
    seen = {0: 1}  # the empty start
    running = 0
    count = 0
    for x in nums:
        running += x
        count += seen.get(running - k, 0)
        seen[running] = seen.get(running, 0) + 1
    return count

count_runs_with_sum([2, -1, 3, -2, 2], 2)  # 5

Common mistakes

The prefix array is one longer than the input, so indexes shift by one. prefix[r] − prefix[l] leaves out item r. Test with one item: prefix[l + 1] − prefix[l] must equal nums[l].

Without seen = {0: 1}, runs that start at the first item are never counted. The example would give 3 instead of 5.

If one value changes, every running total after it is wrong, and fixing them is O(n). Prefix sums suit data read often and changed rarely. For frequent updates, see Segment and Fenwick Trees.

It works on a grid too. Store, for every cell, the total of the rectangle from the top-left corner to it. Any rectangle's sum then takes four lookups.

Dashboards that answer "revenue between any two dates" instantly often store cumulative daily totals and subtract, instead of adding up raw rows per request.

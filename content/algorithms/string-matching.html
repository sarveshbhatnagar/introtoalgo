String matching means finding every position where a pattern of length m appears inside a text of length n. It is the operation behind a Find box, a search through DNA, and the indexOf or str.find calls in every language. This lesson covers three ways to do it: the naive scan, Knuth-Morris-Pratt (KMP), and Rabin-Karp.

The naive scan

Place the pattern at position 0 of the text and compare character by character. If every character matches, record the position. If any character differs, move the pattern one position to the right and start comparing from its first character again. The trace below searches for HHTHHH in HHTHHTHHH.

Each of the roughly n start positions can cost up to m comparisons, so the worst case is O(n·m). A text of a million H characters searched for HHHHHHHHHT is the standard bad case, because every start matches nine characters before failing on the last one. On ordinary text the first comparison usually fails, so the naive scan runs close to O(n) in practice, which is why it is acceptable when the inputs are small.

function naiveSearch(text, pattern) {
  if (pattern.length === 0) return [];
  const found = [];
  for (let start = 0; start + pattern.length <= text.length; start++) {
    let k = 0;
    while (k < pattern.length && text[start + k] === pattern[k]) k++;
    if (k === pattern.length) found.push(start);
  }
  return found;
}

naiveSearch("HHTHHTHHH", "HHTHHH"); // [3]

def naive_search(text, pattern):
    if not pattern:
        return []
    found = []
    for start in range(len(text) - len(pattern) + 1):
        k = 0
        while k < len(pattern) and text[start + k] == pattern[k]:
            k += 1
        if k == len(pattern):
            found.append(start)
    return found

KMP

The naive scan throws away what it learned. At the first mismatch in the trace, the text characters HHTHH were already known to match the start of the pattern. KMP uses that knowledge and never compares a text character twice. The suffix HH of the matched part is also a prefix of the pattern, so the pattern can slide until its first two characters sit under those two text characters, and the comparison continues from pattern position 2.

A border of a string is a proper prefix that is also a suffix. The string HHTHH has two borders, H and HH. KMP slides by the longest border, because that is the smallest slide that cannot skip a real match. Borders depend only on the pattern, so KMP computes them once, before searching, in a failure table. The entry table[i] is the length of the longest border of the first i + 1 characters of the pattern.

Building the failure table

The table is built left to right with a variable k that holds the current border length. For each new character, check whether it extends the current border, meaning pattern[i] equals pattern[k]. If it does, k grows by one. If it does not, the next shorter border that could still be extended is the border of the current border, which is table[k − 1], so k falls back to that value and the check repeats.

Searching with the table

The search has the same shape. The variable j counts how many pattern characters are currently matched. When the text character equals pattern[j], j grows. On a mismatch, j falls back to table[j − 1] and the same text character is compared again, so the text index only ever moves forward.

function buildTable(pattern) {
  const table = new Array(pattern.length).fill(0);
  let k = 0; // length of the current border
  for (let i = 1; i < pattern.length; i++) {
    while (k > 0 && pattern[i] !== pattern[k]) k = table[k - 1];
    if (pattern[i] === pattern[k]) k++;
    table[i] = k;
  }
  return table;
}

function kmpSearch(text, pattern) {
  if (pattern.length === 0) return [];
  const table = buildTable(pattern);
  const found = [];
  let j = 0; // pattern characters matched so far
  for (let i = 0; i < text.length; i++) {
    while (j > 0 && text[i] !== pattern[j]) j = table[j - 1];
    if (text[i] === pattern[j]) j++;
    if (j === pattern.length) {
      found.push(i - j + 1);
      j = table[j - 1]; // keep going: matches can overlap
    }
  }
  return found;
}

def build_table(pattern):
    table = [0] * len(pattern)
    k = 0  # length of the current border
    for i in range(1, len(pattern)):
        while k > 0 and pattern[i] != pattern[k]:
            k = table[k - 1]
        if pattern[i] == pattern[k]:
            k += 1
        table[i] = k
    return table

def kmp_search(text, pattern):
    if not pattern:
        return []
    table = build_table(pattern)
    found = []
    j = 0  # pattern characters matched so far
    for i, ch in enumerate(text):
        while j > 0 and ch != pattern[j]:
            j = table[j - 1]
        if ch == pattern[j]:
            j += 1
        if j == len(pattern):
            found.append(i - j + 1)
            j = table[j - 1]  # keep going: matches can overlap
    return found

After a full match the code sets j = table[j − 1] instead of 0, so that overlapping matches are also reported. For example, AA occurs twice in AAA.

The inner while loop does not make the search O(n·m). The value of j rises by at most 1 per text character, and each fallback lowers it, so the total number of fallbacks cannot exceed the total number of increases, which is at most n. The search therefore does at most about 2n steps, and the table construction follows the same argument for m.

Setting j = 0 after a mismatch instead of j = table[j − 1] discards the border, so KMP misses matches that start inside the part it already matched. In the search trace above, resetting at i = 5 means the match that begins at index 3 is never found.

After j reaches the pattern length, the code must set j = table[j − 1] before reading the next character. Leaving j at m would read past the end of the pattern, and resetting it to 0 would miss overlapping matches.

Rabin-Karp

Rabin-Karp compares numbers instead of strings. It converts every window of m characters in the text into a number called a hash and compares it with the pattern's hash. Comparing two numbers takes O(1), and the method works because each window's hash can be computed from the previous window's hash in O(1) instead of from scratch.

The idea is easiest to see with digits. To search for 265 in 31415926535, the first window is 314. To move one position right, remove the leading digit by subtracting 3 × 100, shift the rest left by multiplying by 10, and add the new digit: (314 − 300) × 10 + 1 = 141.

For real text, treat each character code as a digit in base 256, and keep every value modulo a large prime such as 1,000,000,007 so the numbers stay small. The modulo creates a cost, because different windows can now have the same hash. With modulo 7, for example, both 314 and 265 leave remainder 6. An equal hash therefore only means that the window might match, and the code must compare the actual characters before reporting it. A different hash proves the window does not match, and that is what lets most windows be skipped.

function rabinKarp(text, pattern) {
  const n = text.length, m = pattern.length;
  const BASE = 256, MOD = 1_000_000_007;
  if (m === 0 || m > n) return [];
  let high = 1; // BASE^(m-1) % MOD: the weight of the leading character
  for (let i = 0; i < m - 1; i++) high = (high * BASE) % MOD;
  let target = 0, h = 0;
  for (let i = 0; i < m; i++) {
    target = (target * BASE + pattern.charCodeAt(i)) % MOD;
    h = (h * BASE + text.charCodeAt(i)) % MOD;
  }
  const found = [];
  for (let start = 0; start + m <= n; start++) {
    if (h === target && text.slice(start, start + m) === pattern) found.push(start);
    if (start + m < n) {
      h = (h - (text.charCodeAt(start) * high) % MOD + MOD) % MOD; // drop the left char
      h = (h * BASE + text.charCodeAt(start + m)) % MOD;           // add the right char
    }
  }
  return found;
}

def rabin_karp(text, pattern):
    n, m = len(text), len(pattern)
    BASE, MOD = 256, 1_000_000_007
    if m == 0 or m > n:
        return []
    high = pow(BASE, m - 1, MOD)  # the weight of the leading character
    target = h = 0
    for i in range(m):
        target = (target * BASE + ord(pattern[i])) % MOD
        h = (h * BASE + ord(text[i])) % MOD
    found = []
    for start in range(n - m + 1):
        if h == target and text[start:start + m] == pattern:
            found.append(start)
        if start + m < n:
            h = (h - ord(text[start]) * high) % MOD   # drop the left char
            h = (h * BASE + ord(text[start + m])) % MOD  # add the right char
    return found

When the leading character is removed from the hash, the result can go below zero before the modulo is applied. In JavaScript -3 % 7 is -3, not 4, so the code adds MOD before taking the remainder. Python's % already returns a non-negative result.

Choosing between the methods

When to use the built-in search

For everyday work, call the language's own search function, such as indexOf in JavaScript or str.find in Python. It is already optimised and tested. Write KMP or Rabin-Karp yourself when an interviewer asks for it.

When to use KMP

Use KMP when you need a worst-case guarantee for a single pattern, or when the failure table is the point of the problem.

When to use Rabin-Karp

Rabin-Karp is the better fit when you must compare many windows at once. To find a repeated substring of a given length, put the hash of every window in a hash set and look for a hash that appears twice, then verify the candidates. Its weakness is that the O(n + m) bound is only expected: a poor hash or an adversarial input that causes many collisions pushes it back toward O(n·m).

Other algorithms for related problems

All three methods match an exact string. If the pattern is a regular expression, or if small differences must be allowed, as in spell checking, you need a regex engine or an edit-distance approach such as dynamic programming on strings. If you must search for a large set of different words in one text, running KMP once per word is slow, and a trie-based method such as Aho-Corasick is the standard answer.

Two other exact-matching algorithms come up in interviews. The Z-function gives, for every position, the length of the longest substring starting there that is also a prefix of the string, and it solves the same problems as the failure table. Boyer-Moore compares the pattern from its right end and skips several text characters after a mismatch, which makes it the fastest in practice for long patterns.

What interviewers ask about string matching

The usual form of the question is about finding one string inside another, usually phrased as "return the index of the first occurrence" or "does this string contain that one". Related forms are a prefix that is also a suffix, a string built by repeating a shorter one, or a repeated substring. If the constraints allow O(n·m), for example when both strings are under a few thousand characters, the naive scan is acceptable, and you should say so before you offer anything more complex.

Questions to expect:

  • "What is the naive approach and when does it get slow?" It tries every start position and compares up to m characters at each, so it takes O(n·m).
  • "What does the failure table store?" For each prefix of the pattern, it stores the length of the longest proper prefix that is also a suffix of that prefix. On a mismatch after j matched characters, that length tells KMP how many of those characters are still a valid match, so the search resumes at table[j − 1] without moving back in the text.
  • "Why is KMP O(n + m) when it has a loop inside a loop?" The pattern index j increases by at most one per text character, and every fallback decreases it. The total number of fallbacks is therefore at most the total number of increases, which is at most n. The table build follows the same reasoning.
  • "What is the worst case for Rabin-Karp?" It is O(n·m). If many windows have the same hash as the pattern, the algorithm compares characters for each of them. With a good modulus and base that is unlikely on ordinary input, which is why the expected time is O(n + m).
  • "How would you check whether a string is made of a shorter string repeated?" Build the failure table and let L = n − table[n − 1]. If table[n − 1] is greater than 0 and L divides n, the first L characters repeat to form the string.
  • "Why not just use indexOf?" In production you should. The interviewer is asking whether you understand what it does, so be ready to explain the failure table and the O(n + m) guarantee, and to say that the built-in version may use a different algorithm.
  • "How do you make Rabin-Karp reliable?" Use a large prime modulus and always compare the characters when the hashes are equal. To make collisions harder for an adversary to construct, pick the base at random or use two different moduli.

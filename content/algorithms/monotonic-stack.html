Six buildings stand in a row, 5, 3, 1, 4, 6 and 2 floors tall from west to east. For each, you want the first taller building to its east, the one that blocks its sunrise. Building 1 (3 floors) is blocked by building 3 (4 floors). Building 4 (6 floors) is blocked by nothing.

Walking east from each building is O(n²): on a street that keeps getting shorter, every walk goes to the end. With 100,000 buildings that is about 5 billion steps. A stack does it in one pass.

The idea: a line of buildings still waiting

Walk west to east with a stack of buildings still waiting for an answer. While the new building is taller than the top, it is that building's answer: pop and record it. Then push the new building to wait for its own answer.

Everything shorter is popped before a push, so heights on the stack always go down from bottom to top. A stack kept in sorted order like this is a monotonic stack, here a decreasing one.

Popping is safe: the popped building's answer is the first taller building, which is this one, so it is never needed again.

The code

// For each building, the index of the first taller one to its right, or -1.
function nextTaller(heights) {
  const answer = new Array(heights.length).fill(-1);
  const stack = []; // indexes still waiting; heights decrease bottom to top
  for (let i = 0; i < heights.length; i++) {
    while (stack.length > 0 && heights[stack[stack.length - 1]] < heights[i]) {
      answer[stack.pop()] = i; // i is the first taller one for the top
    }
    stack.push(i); // i waits for its own answer
  }
  return answer; // anything still waiting keeps -1
}

nextTaller([5, 3, 1, 4, 6, 2]); // [4, 3, 3, 4, -1, -1]

# For each building, the index of the first taller one to its right, or -1.
def next_taller(heights):
    answer = [-1] * len(heights)
    stack = []  # indexes still waiting; heights decrease bottom to top
    for i, h in enumerate(heights):
        while stack and heights[stack[-1]] < h:
            answer[stack.pop()] = i  # i is the first taller one for the top
        stack.append(i)  # i waits for its own answer
    return answer  # anything still waiting keeps -1

next_taller([5, 3, 1, 4, 6, 2])  # [4, 3, 3, 4, -1, -1]

The stack stores indexes: you need them to write into answer, and they give the height and the distance, i - index.

The while inside the for looks like O(n²). But each pop removes an index for good, and only n are pushed, so all the while loops together pop at most n times. It is the "count the total moves" argument from Two Pointers.

Four questions, one pattern

Flip the comparison for "next smaller": pop while the top is bigger, and the stack stays increasing. For "previous" questions, the answer goes the other way: after popping stops, the item left on top answers the new item. Pop equal items too, so what is left is strictly bigger or smaller.

QuestionPop while the top is…Who gets the answer
Next greatersmaller than the new itemeach popped item gets the new one
Next smallerbigger than the new itemeach popped item gets the new one
Previous greatersmaller than or equal to the new itemthe new item gets whatever is left on top
Previous smallerbigger than or equal to the new itemthe new item gets whatever is left on top

A monotonic stack holds items still waiting for an answer. A new item answers every waiting item it beats, and those leave for good, so the pass is O(n).

The deque version: the biggest in every window

A cousin asks for the largest value in every run of k neighbouring items. For [4, 2, 12, 3, 8, 7, 1] and k = 3, the answers are 12, 12, 12, 8, 8.

Keep a decreasing list of indexes as before: a new item pops every item not bigger than it off the back, since those can never again be a window's biggest. The biggest is then at the front, and when its index slides out of the window, remove it from the front. Both ends means a deque; the JavaScript version uses a head index.

function windowMax(nums, k) {
  const dq = []; // indexes; values decrease from front to back
  let head = 0;  // front of the deque
  const result = [];
  for (let i = 0; i < nums.length; i++) {
    if (head < dq.length && dq[head] <= i - k) head++; // front left the window
    while (head < dq.length && nums[dq[dq.length - 1]] <= nums[i]) dq.pop();
    dq.push(i);
    if (i >= k - 1) result.push(nums[dq[head]]); // front is the biggest
  }
  return result;
}

windowMax([4, 2, 12, 3, 8, 7, 1], 3); // [12, 12, 12, 8, 8]

from collections import deque

def window_max(nums, k):
    dq = deque()  # indexes; values decrease from front to back
    result = []
    for i, x in enumerate(nums):
        if dq and dq[0] <= i - k:
            dq.popleft()  # front left the window
        while dq and nums[dq[-1]] <= x:
            dq.pop()
        dq.append(i)
        if i >= k - 1:
            result.append(nums[dq[0]])  # front is the biggest
    return result

window_max([4, 2, 12, 3, 8, 7, 1], 3)  # [12, 12, 12, 8, 8]

Each index enters once and leaves at most once, so this is O(n), against O(n·k) for scanning every window. See also Sliding Window.

Common mistakes

With heights [3, 3, 4], < lets the first 3 wait and get index 2. <= would give it index 1, wrong for "strictly taller". Decide what a tie means, then test equal values.

With heights on the stack, you cannot tell which building was answered. Push indexes and look up values to compare.

Items left on the stack never found an answer. Fill the answer array with the "no answer" value (-1, 0, or whatever the problem asks) before the loop.

"How many days in a row has the price been at or below today's?" is previous-greater: today's index minus the previous higher day's index. The same stack finds the largest rectangle under a bar chart in O(n).

Bellman-Ford finds the cheapest route from one start node to every other node in a weighted directed graph, and it works even when some edge costs are negative. It can also tell you that a negative cycle exists, which is a loop whose total cost is below zero. Floyd-Warshall solves a different problem: it finds the cheapest route between every pair of nodes, also with negative costs allowed. You reach for these two when Dijkstra's algorithm cannot be used because of a negative cost.

Dijkstra finalises the closest unsettled node at each step, and that is only safe when no later edge can make a route cheaper. A negative edge breaks that assumption. Suppose S→A costs 1, S→B costs 2, B→A costs −4 and A→C costs 3. Dijkstra settles A at distance 1 and gives C a distance of 4, and only afterwards does it see that S→B→A costs −2, so the real distance to C is 1.

How Bellman-Ford works

Bellman-Ford does not choose a clever order. In each round it goes through every edge once, and for each edge from u to v it checks whether dist[u] + cost is smaller than dist[v]. If it is, it lowers dist[v]. This check is called relaxing an edge. The start node begins at distance 0 and every other node at infinity.

Each round extends the cheapest routes by one more edge, so after round k every node has the cost of its cheapest route that uses at most k edges. When there is no negative cycle, a cheapest route never visits a node twice, so it has at most V − 1 edges, and V − 1 rounds are enough.

The example below uses four depots S, A, B and C with five one-way legs. The leg from B to A has cost −4.

The order in which the edges are listed changes how many rounds are needed, but not the final answer. The code below stops early when a round changes nothing, and it finishes with one extra pass over the edges to detect a negative cycle.

// edges: list of [from, to, cost], one-way. nodes: list of names.
function bellmanFord(nodes, edges, start) {
  const dist = {};
  for (const node of nodes) dist[node] = Infinity;
  dist[start] = 0;
  for (let round = 1; round < nodes.length; round++) { // V - 1 rounds
    let changed = false;
    for (const [u, v, cost] of edges) {
      if (dist[u] + cost < dist[v]) {
        dist[v] = dist[u] + cost;
        changed = true;
      }
    }
    if (!changed) break; // nothing moved: every distance is final
  }
  for (const [u, v, cost] of edges) {
    if (dist[u] + cost < dist[v]) return null; // still improving: negative cycle
  }
  return dist;
}
// bellmanFord(["S", "A", "B", "C"], edges, "S") → { S: 0, A: -2, B: 2, C: 1 }

def bellman_ford(nodes, edges, start):
    dist = {node: math.inf for node in nodes}
    dist[start] = 0
    for _ in range(len(nodes) - 1):  # V - 1 rounds
        changed = False
        for u, v, cost in edges:
            if dist[u] + cost < dist[v]:
                dist[v] = dist[u] + cost
                changed = True
        if not changed:
            break  # nothing moved: every distance is final
    for u, v, cost in edges:
        if dist[u] + cost < dist[v]:
            return None  # still improving: negative cycle
    return dist

Negative cycles

A negative cycle makes the problem unsolvable, because every extra lap around the loop lowers the cost again. In the example, adding a leg C→B with cost −2 creates the loop B→A→C→B with total cost −4 + 3 − 2 = −3.

If there is no negative cycle, no distance changes after round V − 1. So Bellman-Ford runs one more pass, and if any edge can still lower a distance, a negative cycle is reachable from the start. The function then returns null instead of wrong numbers. A negative cycle that the start node cannot reach is never touched, because its nodes stay at infinity.

Currency arbitrage is a negative cycle problem. If each exchange rate r is turned into the cost −log(r), a loop of trades that ends with more money than it started with has a negative total cost.

How Floyd-Warshall works

Floyd-Warshall keeps a table with the cheapest known cost for every pair of nodes. It starts with the direct edges and then allows the nodes as stopovers one at a time. When node k becomes allowed, each pair i, j is compared against the route that goes from i to k and then from k to j, and the smaller cost is kept.

This is correct because the best route from i to j that may use stopovers up to k either avoids k, in which case it is already in the table, or passes through k once, in which case it is the best i to k route plus the best k to j route, and both of those are also in the table.

// Places are numbered 0..n-1. edges: list of [from, to, cost], one-way.
function floydWarshall(n, edges) {
  const dist = Array.from({ length: n }, (_, i) =>
    Array.from({ length: n }, (_, j) => (i === j ? 0 : Infinity)));
  for (const [u, v, cost] of edges) dist[u][v] = Math.min(dist[u][v], cost);
  for (let k = 0; k < n; k++) {       // allow k as a stopover
    for (let i = 0; i < n; i++) {
      for (let j = 0; j < n; j++) {
        if (dist[i][k] + dist[k][j] < dist[i][j]) {
          dist[i][j] = dist[i][k] + dist[k][j];
        }
      }
    }
  }
  return dist; // a negative dist[i][i] means i is on a negative cycle
}

import math

# Places are numbered 0..n-1. edges: list of (from, to, cost), one-way.
def floyd_warshall(n, edges):
    dist = [[0 if i == j else math.inf for j in range(n)] for i in range(n)]
    for u, v, cost in edges:
        dist[u][v] = min(dist[u][v], cost)
    for k in range(n):          # allow k as a stopover
        for i in range(n):
            for j in range(n):
                if dist[i][k] + dist[k][j] < dist[i][j]:
                    dist[i][j] = dist[i][k] + dist[k][j]
    return dist  # a negative dist[i][i] means i is on a negative cycle

Variants and when each algorithm applies

Choosing between BFS, Dijkstra, Bellman-Ford and Floyd-Warshall

Use breadth-first search when every edge costs the same, because it is the fastest. Use Dijkstra when costs differ but none is negative. Use Bellman-Ford when there is one start node and some costs are negative. Use Floyd-Warshall when you need the answer for every pair of nodes, which is practical only for a few hundred nodes because of the V³ time.

Negative cycles in Floyd-Warshall

Floyd-Warshall has no separate check pass. After it finishes, a node i lies on a negative cycle if dist[i][i] is below 0. When a negative cycle exists, the other entries that route through it are not reliable either, so a problem that allows negative cycles needs this check before the table is used.

Bellman-Ford with a limit on the number of edges

Because round k covers routes of at most k edges, Bellman-Ford can answer "the cheapest route using at most k edges", as in problems about flights with at most k stops. Run exactly the allowed number of rounds, and in each round read the distances from a copy made at the start of the round. Without the copy, an update made earlier in the same round can be used again in that round, and a route ends up with more edges than allowed.

When these algorithms do not apply

If the graph is undirected, a negative edge cannot be used, because an undirected edge of cost −4 is the same as two directed edges of cost −4, and going across it and back is a negative cycle of cost −8. If a problem asks for the cheapest route that is allowed to repeat nodes and a negative cycle is reachable, the answer is minus infinity and not a number. Finding the cheapest simple path in a graph with negative cycles is a much harder problem that neither algorithm solves.

Pitfalls

The loop over the stopover k must be the outermost loop. It means "finish all routes that use stopovers up to k, then allow the next one". If k is an inner loop, an entry can be read before the routes it depends on are complete, and some answers come out too high.

If 1e9 stands for "no route", then 1e9 + (−4) is smaller than 1e9, and an unreachable node looks like it has been reached. Use a real infinity, which stays infinite when a negative number is added, or skip an edge whose start node still has an infinite distance.

Without the check pass, a graph with a negative cycle returns distances that look valid but are really just the values the loop happened to reach after V − 1 rounds. If the problem can contain negative cycles, always run the check.

In the interview

Look for a weighted directed graph where some costs can be negative, such as refunds, discounts, profits or exchange rates. The words "cheapest", "at most k stops", "detect an arbitrage" or "is there a loop that gains money" point to Bellman-Ford. A request for the shortest distance between all pairs of a small graph, such as a distance matrix or the transitive closure, points to Floyd-Warshall.

Questions to expect:

  • "Why does Dijkstra fail with a negative edge?" Dijkstra assumes that once a node is the closest unsettled one, no other route can reach it more cheaply. A negative edge later in the graph can make a longer route cheaper, but the node is already settled and is never updated.
  • "Why are V − 1 rounds enough?" Without a negative cycle, a cheapest route never repeats a node, so it has at most V − 1 edges. After round k all cheapest routes of up to k edges are correct, so after V − 1 rounds all of them are.
  • "How do you detect a negative cycle?" Run one more round after V − 1 rounds. If any edge still lowers a distance, then a negative cycle is reachable from the start. In Floyd-Warshall you check whether any dist[i][i] is negative.
  • "How would you speed up Bellman-Ford?" Stop as soon as a round changes nothing, which the code above already does. A queue-based version that only re-examines the neighbours of nodes whose distance just changed is often much faster in practice, but its worst case is still O(V × E).
  • "How do you get the actual path and not only the cost?" In Bellman-Ford, store the previous node each time a distance is lowered, then walk back from the target. In Floyd-Warshall, store for each pair the first or last node of the best route and update it whenever the table entry improves.
  • "How do you find all-pairs shortest paths on a large sparse graph with negative edges?" Johnson's algorithm runs Bellman-Ford once to compute a reweighting that makes every edge cost non-negative without changing which routes are cheapest, and then runs Dijkstra from every node. This is faster than O(V³) when the graph is sparse.
  • "When would you use Floyd-Warshall instead of running Dijkstra from every node?" Floyd-Warshall is shorter to write and handles negative costs, so it is a good choice for a small or dense graph. For a large sparse graph with no negative costs, running Dijkstra once per node is faster.

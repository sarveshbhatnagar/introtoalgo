A courier drives one-way legs between four depots: S, A, B and C. Each leg costs fuel, except B to A: it carries a paid parcel that pays 4 more than the fuel, so its cost is −4. Starting at S, what is the cheapest way to reach each depot?

Try Dijkstra's rule, "settle the closest place first". S→A costs 1 and S→B costs 2, so A settles at 1 and C gets 1 + 3 = 4. Then B reveals S→B→A at 2 − 4 = −2. But A was already "final", so C ends at 4 instead of 1. With negative costs, settling the closest first is no longer safe.

The Dijkstra lesson's heap code would push A again and patch C, but on other graphs that patching can snowball into exponential work, and a negative loop never ends.

Bellman-Ford: relax every edge, every round

Bellman-Ford drops the clever order. Each round, it relaxes every edge in a fixed order: if dist[u] + cost beats dist[v], lower dist[v]. Then it repeats.

Why that is enough: each round extends every cheapest route by one edge, so after round k, every cheapest route of up to k edges is counted. Without a negative loop, a cheapest route never revisits a place, so it has at most V − 1 edges, and V − 1 rounds finish the job.

Edge order affects speed, not correctness. The code stops early when a round changes nothing.

// edges: list of [from, to, cost], one-way. nodes: list of names.
function bellmanFord(nodes, edges, start) {
  const dist = {};
  for (const node of nodes) dist[node] = Infinity;
  dist[start] = 0;
  for (let round = 1; round < nodes.length; round++) { // V - 1 rounds
    let changed = false;
    for (const [u, v, cost] of edges) {
      if (dist[u] + cost < dist[v]) {
        dist[v] = dist[u] + cost;
        changed = true;
      }
    }
    if (!changed) break; // nothing moved: every distance is final
  }
  for (const [u, v, cost] of edges) {
    if (dist[u] + cost < dist[v]) return null; // still improving: negative cycle
  }
  return dist;
}
// bellmanFord(["S", "A", "B", "C"], edges, "S") → { S: 0, A: -2, B: 2, C: 1 }

import math

# edges: list of (from, to, cost), one-way. nodes: list of names.
def bellman_ford(nodes, edges, start):
    dist = {node: math.inf for node in nodes}
    dist[start] = 0
    for _ in range(len(nodes) - 1):  # V - 1 rounds
        changed = False
        for u, v, cost in edges:
            if dist[u] + cost < dist[v]:
                dist[v] = dist[u] + cost
                changed = True
        if not changed:
            break  # nothing moved: every distance is final
    for u, v, cost in edges:
        if dist[u] + cost < dist[v]:
            return None  # still improving: negative cycle
    return dist

# bellman_ford(["S", "A", "B", "C"], edges, "S") → {'S': 0, 'A': -2, 'B': 2, 'C': 1}

Negative cycles

Add a leg C→B with cost −2. Now B→A→C→B costs −4 + 3 − 2 = −3. One more lap is always cheaper, so no cheapest route exists.

Without a negative cycle, everything is final after V − 1 rounds. So Bellman-Ford makes one extra pass: if any edge can still lower a distance, a negative loop is to blame, and it returns null instead of wrong numbers.

Currency traders hunt negative cycles. Make each exchange rate r a cost of −log(r), and a loop of trades that ends with more money becomes a negative cycle.

Floyd-Warshall: every pair at once

Now the dispatcher wants the cheapest cost from every depot to every other. Instead of running Bellman-Ford from each, Floyd-Warshall uses three short loops and one table.

Start with a table of direct legs, then allow stopovers one depot at a time. Allowing S, check for every pair whether i → S → j is cheaper; then add A, B and C. With k allowed, the best i to j route either avoids k (already in the table) or passes through it once: best i → k plus best k → j, both in the table.

// Places are numbered 0..n-1. edges: list of [from, to, cost], one-way.
function floydWarshall(n, edges) {
  const dist = Array.from({ length: n }, (_, i) =>
    Array.from({ length: n }, (_, j) => (i === j ? 0 : Infinity)));
  for (const [u, v, cost] of edges) dist[u][v] = Math.min(dist[u][v], cost);
  for (let k = 0; k < n; k++) {       // allow k as a stopover
    for (let i = 0; i < n; i++) {
      for (let j = 0; j < n; j++) {
        if (dist[i][k] + dist[k][j] < dist[i][j]) {
          dist[i][j] = dist[i][k] + dist[k][j];
        }
      }
    }
  }
  return dist; // a negative dist[i][i] means i is on a negative cycle
}

import math

# Places are numbered 0..n-1. edges: list of (from, to, cost), one-way.
def floyd_warshall(n, edges):
    dist = [[0 if i == j else math.inf for j in range(n)] for i in range(n)]
    for u, v, cost in edges:
        dist[u][v] = min(dist[u][v], cost)
    for k in range(n):          # allow k as a stopover
        for i in range(n):
            for j in range(n):
                if dist[i][k] + dist[k][j] < dist[i][j]:
                    dist[i][j] = dist[i][k] + dist[k][j]
    return dist  # a negative dist[i][i] means i is on a negative cycle

Negative cycles show up for free as a negative number on the diagonal.

Which one to use

Common mistakes

In Floyd-Warshall, k must be the outer loop: finish all routes with stopovers up to k, then allow the next. With k inside, entries are read before their routes are done, and answers come out too high.

With 1e9 meaning "no route", 1e9 + (−4) is smaller than 1e9, and an unreachable place looks reachable. Use real infinity, or skip edges whose start is unreached.

An undirected edge with cost −4 is two one-way edges, both −4. There and back is a loop of −8: a negative cycle. Negative costs only make sense on directed graphs.

A print shop has one printer and a line of jobs. Whoever sent first gets printed first: new jobs join at the back, and the printer takes from the front.

That line is a queue, the mirror image of a stack: a stack serves the newest item first, a queue the oldest.

The idea: in at the back, out at the front

You enqueue at the back and dequeue from the front, so the first item in is the first out: first in, first out (FIFO). You can also peek at the front.

Queues handle work in arrival order: web requests, messages between programs, keystrokes. In algorithms, the big one is breadth-first search, which explores a graph level by level from a queue.

A queue in action: taking turns

Round robin shares one processor fairly. Each job gets one unit of work, then goes to the back of the line if it has work left. Short jobs finish early and no long job hogs the processor.

Three jobs arrive: A needs 3 units, B needs 1, C needs 2.

Making dequeue O(1)

The obvious queue is an array: push and shift (append and pop(0) in Python). The answers are right, but removing the first item can shift every other item left, as in Arrays. Python's pop(0) always does. JavaScript engines sometimes avoid it for shift, but not on large arrays. Then each dequeue is O(n), and emptying a queue of n items is O(n²).

Three standard fixes:

  • A head index. Remove nothing; an index head marks the front, and dequeue adds 1 to it. Fast, but used slots are never freed.
  • A linked list with a tail pointer. Dequeue removes the head, enqueue attaches after the tail, both O(1), as in Linked Lists.
  • The library's deque. Python has collections.deque. JavaScript has no built-in queue, so the head index is the usual choice.

The round robin, with a head index in JavaScript and deque in Python:

// jobs: list of [name, units of work]. Each turn gets 1 unit.
function roundRobin(jobs) {
  const queue = jobs.map(([name, left]) => ({ name, left }));
  let head = 0; // index of the front of the queue
  let time = 0;
  const finished = [];
  while (head < queue.length) {
    const job = queue[head];
    head++;                 // dequeue: O(1), nothing shifts
    job.left--;
    time++;
    if (job.left > 0) queue.push(job); // not done: back of the line
    else finished.push([job.name, time]);
  }
  return finished;
}

roundRobin([["A", 3], ["B", 1], ["C", 2]]);
// [["B", 2], ["C", 5], ["A", 6]]

from collections import deque

# jobs: list of (name, units of work). Each turn gets 1 unit.
def round_robin(jobs):
    queue = deque([name, left] for name, left in jobs)
    time = 0
    finished = []
    while queue:
        job = queue.popleft()  # dequeue: O(1)
        job[1] -= 1
        time += 1
        if job[1] > 0:
            queue.append(job)  # not done: back of the line
        else:
            finished.append((job[0], time))
    return finished

round_robin([("A", 3), ("B", 1), ("C", 2)])
# [('B', 2), ('C', 5), ('A', 6)]

Deques: both ends open

A deque (say "deck", short for double-ended queue) lets you add and remove at both ends in O(1). A stack and a queue are each a deque with some doors locked.

Most algorithms never need push front. For a full deque in JavaScript, use a ring buffer (a fixed array whose front and back indexes wrap around) or a doubly linked list.

Example: browser history capped at 50 pages. New pages go on the back, and the back button pops from the back, like a stack. Past 50, the oldest page is popped from the front, like a queue. In Python, deque(maxlen=50) does this automatically.

A queue serves the oldest item first; a deque works at both ends. Both should be O(1) per operation, which removing from the front of a plain array is not.

Common mistakes

while (queue.length) queue.shift() looks like one pass, but each shift moves everything left: O(n²), about 5 billion moves for 100,000 items. Use a head index or collections.deque.

With a head index, the array keeps dequeued items, so queue.length === 0 is never true once anything was added. The queue is empty when head === queue.length.

A head index never frees memory. Fine for one breadth-first search; not for a server queue that runs for days. Use a ring buffer or linked list, or copy the live part to a fresh array whenever head passes half the length.

Your calendar has five meetings today, in no particular order: 13–15, 9–11, 10–12, 16–17 and 14–16. A colleague asks when you are busy. They want the busy stretches: 9 to 12, and 13 to 17.

Each meeting is an interval, a start and an end, like bookings, shifts, video segments or IP ranges. Most interval problems are solved the same way: sort, then walk through once.

When do two intervals overlap

Two intervals can overlap in many ways but miss in only two: a ends before b starts, or b ends before a starts. Test those and flip the result.

// Touching counts as overlapping here. Use < instead of <= if it should not.
function overlaps(a, b) {
  return a[0] <= b[1] && b[0] <= a[1];
}

# Touching counts as overlapping here. Use < instead of <= if it should not.
def overlaps(a, b):
    return a[0] <= b[1] and b[0] <= a[1]

Whether touching intervals overlap is a rule of the problem. In a calendar, 14–16 and 16–17 make one busy stretch; for room bookings, a meeting ending at 16 does not block one starting at 16. Decide once and use the same < or <= everywhere.

The idea: sort by start, then sweep

Comparing every pair is O(n²). Sort by start instead, and keep one open block. For each next meeting: does it start before the block ends? If yes, stretch the block's end. If no, close it and open a new one.

Once sorted by start, each interval only needs comparing with the last block, because every earlier block has already ended.

 
function mergeBusy(meetings) {
  if (meetings.length === 0) return [];
  const sorted = [...meetings].sort((a, b) => a[0] - b[0]);
  const busy = [[...sorted[0]]];
  for (const [start, end] of sorted.slice(1)) {
    const last = busy[busy.length - 1];
    if (start <= last[1]) {
      last[1] = Math.max(last[1], end); // overlaps or touches: stretch
    } else {
      busy.push([start, end]);          // gap: new block
    }
  }
  return busy;
}

mergeBusy([[13, 15], [9, 11], [10, 12], [16, 17], [14, 16]]);
// [[9, 12], [13, 17]]

def merge_busy(meetings):
    if not meetings:
        return []
    ordered = sorted(meetings, key=lambda m: m[0])
    busy = [list(ordered[0])]
    for start, end in ordered[1:]:
        last = busy[-1]
        if start <= last[1]:
            last[1] = max(last[1], end)  # overlaps or touches: stretch
        else:
            busy.append([start, end])    # gap: new block
    return busy

merge_busy([[13, 15], [9, 11], [10, 12], [16, 17], [14, 16]])
# [[9, 12], [13, 17]]

The code copies the first meeting so that stretching the block does not change the caller's data.

How many at the same time

The office hosts meetings 9–12, 10–11, 11–13 and 13–14. How many rooms does it need? The most meetings running at any one moment.

Think in events: +1 when a meeting starts, −1 when it ends. Sort the events by time and sweep with a counter; its peak is the answer. On a tie, process the end first: the person leaving at 11 frees the room for the one arriving at 11.

function roomsNeeded(meetings) {
  const events = [];
  for (const [start, end] of meetings) {
    events.push([start, 1], [end, -1]);
  }
  // by time; at a tie, -1 (an end) sorts before +1 (a start)
  events.sort((a, b) => a[0] - b[0] || a[1] - b[1]);
  let inUse = 0;
  let most = 0;
  for (const [, change] of events) {
    inUse += change;
    most = Math.max(most, inUse);
  }
  return most;
}

roomsNeeded([[9, 12], [10, 11], [11, 13], [13, 14]]); // 2

def rooms_needed(meetings):
    events = []
    for start, end in meetings:
        events.append((start, 1))
        events.append((end, -1))
    # tuples sort by time, then by change, so -1 (an end) comes before +1
    events.sort()
    in_use = most = 0
    for _, change in events:
        in_use += change
        most = max(most, in_use)
    return most

rooms_needed([[9, 12], [10, 11], [11, 13], [13, 14]])  # 2

Counting rooms costs O(n log n) time for the sort and O(n) space for the 2n events. "Keep as many meetings as possible with no overlaps" sorts by end time instead; see Greedy Algorithms.

Common mistakes

last.end = end breaks when one meeting sits inside another: merging 9–17 with 10–11 shrinks the block to 9–11. Use max(last.end, end).

Without sorting, 13–15 might be closed before 9–11 arrives, and the blocks can overlap each other.

If the start at 11 is processed before the end at 11, the counter briefly reads 3 and you book a room you never needed. Choose the tie rule on purpose and check a back-to-back pair by hand.

Calendar apps merge busy times this way to show free slots. Video editors merge selected clip ranges, and network tools merge address ranges to keep firewall rules short.

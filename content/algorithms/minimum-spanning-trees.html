Six villages, A to F, want fibre internet. A trench can be dug between some pairs, each at a price. Every village must reach every other, directly or through others, for the lowest total bill.

This is not a shortest-path problem: you care about the total bill, not any one route.

The idea: the answer is a tree

Take any plan with a loop and remove the loop's most expensive cable. Every village stays connected, since the rest of the loop goes around the gap, and the bill drops. So the cheapest plan has no loop: it is a tree, and a tree on V nodes has exactly V − 1 edges. For six villages, you want five cables.

A tree that reaches every node is a spanning tree; the cheapest is the minimum spanning tree, or MST.

Both algorithms here rest on one rule. Split the villages into any two groups; at least one cable must cross between them. The cheapest cable crossing the split is always safe to take.

Why: add the cheapest crossing cable to any spanning tree that lacks it. That makes a loop, which must cross the split again through a cable costing at least as much. Remove that one: still a spanning tree, no more expensive. So you can build the tree greedily, one cheap edge at a time.

Kruskal: cheapest cables first

Sort the cables by price and walk down the list. Take a cable if its villages are not yet connected; skip it if they are, since it would close a loop. Stop at V − 1 cables.

"Already connected?" while groups merge is what Union-Find answers: union(u, v) returns false when u and v share a root, your signal to skip.

Each cable Kruskal takes is safe. Split the villages into "the group at one end of the cable" and "everything else". Every cheaper cable lies inside a group, so the cable in hand is the cheapest crossing this split.

// n villages numbered 0..n-1. edges: list of [cost, u, v].
// UnionFind: the class from the union-find lesson.
function kruskal(n, edges) {
  const sorted = [...edges].sort((a, b) => a[0] - b[0]); // cheapest first
  const uf = new UnionFind(n);
  const chosen = [];
  let total = 0;
  for (const [cost, u, v] of sorted) {
    if (uf.union(u, v)) { // false means u and v were already connected
      chosen.push([u, v, cost]);
      total += cost;
      if (chosen.length === n - 1) break; // a spanning tree has n - 1 edges
    }
  }
  return chosen.length === n - 1 ? { total, chosen } : null; // null: not connected
}

            if len(chosen) == n - 1:  # a spanning tree has n - 1 edges

    return (total, chosen) if len(chosen) == n - 1 else None  # None: not connected

Prim: grow one tree outward

Prim's algorithm grows one tree from any village. Each step takes the cheapest cable leaving the tree: the cheapest crossing the split "in the tree" versus "not yet". A min-heap holds those cables, as in Dijkstra's algorithm; cables pointing back into the tree are stale and skipped.

// graph: adjacency list, graph[u] = list of [v, cost]. Villages 0..n-1.
// heapPush / heapPop: the pair heap used in the Dijkstra lesson.
function prim(graph, start = 0) {
  const inTree = new Set();
  const heap = [[0, start]]; // [cost of the cable that reaches node, node]
  let total = 0;
  while (heap.length > 0 && inTree.size < graph.length) {
    const [cost, node] = heapPop(heap);
    if (inTree.has(node)) continue; // already joined by a cheaper cable
    inTree.add(node);
    total += cost;
    for (const [next, cableCost] of graph[node]) {
      if (!inTree.has(next)) heapPush(heap, [cableCost, next]);
    }
  }
  return inTree.size === graph.length ? total : null; // null: not connected
}

import heapq

# graph: adjacency list, graph[u] = list of (v, cost). Villages 0..n-1.
def prim(graph, start=0):
    in_tree = set()
    heap = [(0, start)]  # (cost of the cable that reaches node, node)
    total = 0
    while heap and len(in_tree) < len(graph):
        cost, node = heapq.heappop(heap)
        if node in in_tree:
            continue  # already joined by a cheaper cable
        in_tree.add(node)
        total += cost
        for nxt, cable_cost in graph[node]:
            if nxt not in in_tree:
                heapq.heappush(heap, (cable_cost, nxt))
    return total if len(in_tree) == len(graph) else None  # None: not connected

Next to Dijkstra's code, only the number pushed differs. Dijkstra pushes d + cost, the whole trip from the start; Prim pushes just cost, the price of one cable.

Pick Kruskal when the input is a plain list of edges, and Prim when you already have an adjacency list.

Common mistakes

An MST minimises the total bill, not any one trip. In this tree, A to F is A–C–B–D–E–F, costing 18; the graph's cheapest route, A–C–E–F, costs 12. For "cheapest way from X to Y", use Dijkstra.

If the graph is in two pieces, no spanning tree exists: Kruskal ends with fewer than V − 1 edges, and Prim empties its heap with villages left out. Check the count, as both functions do.

Kruskal and Prim assume two-way cables. On a directed graph, the cheapest arrows letting one root reach everything is a different problem with a different algorithm.

Laying cable, pipes or power lines is the direct use. MSTs also cluster data: build the tree over points, cut its priciest edges, and the pieces are the clusters.

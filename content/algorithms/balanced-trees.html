A sign-up service stores users in a binary search tree keyed by user ID. In testing, IDs were random and lookups were quick. In production, IDs come in order (1, 2, 3, ...), so each new user becomes the right child of the last. After a million sign-ups the tree is a stick a million levels deep.

The BST code is fine; the insert order ruined the shape. A balanced tree repairs its shape after every change, so it stays short whatever the order.

Why height matters

Search, insert and delete each walk one path from the root, so they cost O(h), where h is the height:

A balanced tree need not be perfectly short. A height within a constant factor of log₂ n makes every operation O(log n) in the worst case.

AVL trees: a strict height rule

The AVL tree, the oldest balanced BST, adds one rule:

At every node, the heights of the left and right subtrees differ by at most 1.

Each node stores its height (see Binary Trees). Left height minus right height is its balance factor, which must be −1, 0 or +1. That keeps the height below about 1.44 log₂ n.

Insert as in a normal BST. On the way back up, each node on the path updates its height and balance factor. If one is off by 2, a rotation fixes it.

Rotations

A rotation reshapes a small part of the tree and keeps the search order. In a right rotation, node x's left child y moves up and x becomes its right child.

Only B changes parent, from y to x. That is safe: everything in B lies between y and x. Three links change, so a rotation is O(1). A left rotation is the mirror image.

// Each node has val, left, right and height.
function height(node) {
  return node === null ? 0 : node.height;
}
function update(node) {
  node.height = 1 + Math.max(height(node.left), height(node.right));
}

// x's left child y moves up, and x becomes y's right child.
function rotateRight(x) {
  const y = x.left;
  x.left = y.right; // the middle subtree B changes parent
  y.right = x;
  update(x); // x is lower now, so update it first
  update(y);
  return y;  // the new top of this subtree
}
// rotateLeft is the mirror: swap every left and right.

# Each node has val, left, right and height.
def height(node):

Single and double rotations, traced

When a node is off by 2, follow the path from it toward the new value:

  • Straight line (left-left or right-right): one rotation at the node.
  • Zig-zag (left-right or right-left): rotate the child to straighten the line, then rotate the node.

Watch both while inserting 10, 20, 30, 25 and 28.

An insert needs at most one fix. A delete may rotate at several levels. Each rotation is O(1), so both stay O(log n).

Red-black trees: looser rules, fewer fixes

A red-black tree colours every node red or black and keeps these rules:

  • The root is black.
  • A red node never has a red child.
  • Every path from a node down to an empty spot passes the same number of black nodes.

So the longest path is at most twice the shortest, and the height stays below about 2 log₂ n. Lookups may take a few more steps than in AVL, but updates are cheaper: most fixes are recolourings, and an insert needs at most two rotations. Java's TreeMap and C++'s std::map (in common implementations) are red-black trees.

B-trees: wide and shallow, for disks

Binary trees assume following a pointer is cheap. On disk, each node visited can be a separate read, thousands of times slower than memory. So make the tree as shallow as possible.

A B-tree node holds many sorted keys, often hundreds, and has one more child than keys. The keys split the range of values the way one BST key splits it in two. All leaves sit at the same depth: an overflowing node splits and passes its middle key up, so the tree grows only at the root.

With 500 children per node, the fourth level already holds 500 × 500 × 500 = 125 million nodes, each full of keys. A lookup reads four nodes, fewer if the top levels are cached. A balanced binary tree needs 27 levels for just 125 million keys. So databases and file systems store indexes as B-trees, usually the B+ tree variant.

Common mistakes

Balanced trees are hard to get right, especially deletes. In Java or C++, use TreeMap or std::map. Python and JavaScript have none built in: use a sorted array with binary search if the data changes rarely, else a well-tested package.

After a rotation, update the node that moved down first. Otherwise the new top computes its height from a stale value.

An insert can unbalance any node on its path. Fix the lowest unbalanced node on the way back up. In the trace, 30 needed fixing while the root was fine.

Adding an index to a database column builds a B+ tree. The Linux kernel uses red-black trees in several places, including its process scheduler.

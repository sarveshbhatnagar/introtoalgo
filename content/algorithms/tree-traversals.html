A company stores its org chart as a tree, and three people want three things. HR wants an indented list, each manager above their team. Finance wants each team's total salary, which needs every sub-team's total first. The CEO wants who reports at each level: herself, her direct reports, then theirs.

Same tree, three orders of visiting it. Visiting every node in a fixed order is a traversal, and in many tree problems picking the right order is most of the work.

Depth first: three moments to visit a node

The Binary Trees pattern (handle the empty tree, recurse left, recurse right) goes deep down one branch before coming back, so it is called depth-first. It touches each node three times: on the way down, between its children, and on the way back up. "Visiting" means doing your real work there, such as printing the node. The question is at which moment.

  • Preorder: node, left subtree, right subtree. Parents before children: the HR outline.
  • Inorder: left subtree, node, right subtree.
  • Postorder: left subtree, right subtree, node. Children before parents: the Finance totals.

Inorder, traced

The "calls" row is the call stack: every call started but not finished. A node waits until its whole left subtree is done.

The sorted output is no accident: this is a binary search tree, where everything left of a node is smaller and everything right is bigger. The three depth-first orders on it:

The code

The three functions differ only in where one line sits.

function preorder(node, out = []) {
  if (node === null) return out;
  out.push(node.val);         // visit, then the children
  preorder(node.left, out);
  preorder(node.right, out);
  return out;
}

function inorder(node, out = []) {
  if (node === null) return out;
  inorder(node.left, out);
  out.push(node.val);         // visit between the children
  inorder(node.right, out);
  return out;
}

function postorder(node, out = []) {
  if (node === null) return out;
  postorder(node.left, out);
  postorder(node.right, out);
  out.push(node.val);         // visit after the children
  return out;
}

Without recursion

On a very deep tree the call stack can overflow, so keep your own stack. For preorder: pop a node, visit it, push its children, right first so the left comes out first.

function preorderIterative(root) {
  const out = [];
  const stack = root === null ? [] : [root];
  while (stack.length > 0) {
    const node = stack.pop();
    out.push(node.val);
    // push right first so that left is popped first
    if (node.right !== null) stack.push(node.right);
    if (node.left !== null) stack.push(node.left);
  }
  return out;
}

def preorder_iterative(root):
    out = []
    stack = [] if root is None else [root]
    while stack:
        node = stack.pop()
        out.append(node.val)
        # push right first so that left is popped first
        if node.right is not None:
            stack.append(node.right)
        if node.left is not None:
            stack.append(node.left)
    return out

Breadth first: level by level

The CEO wants everyone at depth 0, then depth 1, and so on. That is level-order (breadth-first) traversal: record the current level's values, build the next level from their children, left to right, and repeat until a level is empty.

function levelOrder(root) {
  const levels = [];
  let level = root === null ? [] : [root];
  while (level.length > 0) {
    levels.push(level.map((node) => node.val));
    const next = [];
    for (const node of level) {
      if (node.left !== null) next.push(node.left);
      if (node.right !== null) next.push(node.right);
    }
    level = next;
  }
  return levels;
}
// [[8], [3, 10], [1, 6, 14]]

def level_order(root):
    levels = []
    level = [] if root is None else [root]
    while level:
        levels.append([node.val for node in level])
        next_level = []
        for node in level:
            if node.left is not None:
                next_level.append(node.left)
            if node.right is not None:
                next_level.append(node.right)
        level = next_level
    return levels
# [[8], [3, 10], [1, 6, 14]]

This is breadth-first search on a tree. It is usually written with one queue: take from the front, add children at the back. Two lists do the same and keep levels apart for free. Breadth-First Search uses the queue form on graphs.

Depth-first finishes a branch before the next, so it uses a stack (or recursion). Breadth-first finishes a level before going deeper, so it uses a queue.

Cost

They differ in memory: depth-first holds one path, breadth-first one whole level. On a wide, shallow tree depth-first is lighter; on a long, thin one, breadth-first is.

Common mistakes

A stack returns the last thing pushed. Push left before right and preorder returns 8, 10, 14, 3, 6, 1. Push right first.

array.shift() moves every remaining item one slot left: O(n) per call, so once per node can make the traversal O(n²). Use two lists, or keep an index to the front instead of removing items.

Inorder gives sorted values only for a binary search tree. On any other tree, such as the guessing game in Binary Trees, it reads the drawing left to right, in no particular order.

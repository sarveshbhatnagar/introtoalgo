You have six podcast episodes to catch up on, in order: 40, 25, 60, 30, 45 and 20 minutes. You listen to whole episodes, never skip ahead, and want to finish in 3 days with a daily limit as small as possible. What is that smallest limit?

Finding it directly means trying every way to cut the list into 3 days. But checking a guess is easy. Say the limit is 80. Fill each day until the next episode would go over, then start a new day: 40 + 25, then 60, then 30 + 45, then 20. That is 4 days, so 80 is too small. One pass per guess. When an answer is hard to find but easy to check, binary search can do the finding.

The idea: search the answers, not the array

Line up every possible limit and ask each one: "can I finish in 3 days with this limit?"

  • Below 60 never works: the 60-minute episode would not fit in any day.
  • 220, the total, always works: everything fits in one day.
  • If a limit works, any bigger limit works too. A looser limit never needs more days.

So the answers go no, …, no, yes, …, yes: the shape from Binary Search, and you want the first "yes". The positions are candidate answers instead of array indexes, and checking one means running the day count instead of reading a[mid].

Checking all 161 candidates would work, but binary search needs at most 8 checks (log₂ 161).

The code

Split the code in two: a reusable firstYes search, and the check specific to this problem.

// Smallest x in [lo, hi] with isYes(x) true.
// isYes must go no, ..., no, yes, ..., yes, and isYes(hi) must be true.
function firstYes(lo, hi, isYes) {
  while (lo < hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    if (isYes(mid)) hi = mid; // mid works: answer is mid or smaller
    else lo = mid + 1;        // mid fails: answer is bigger
  }
  return lo;
}

// Assumes limit >= the longest episode.
function daysNeeded(episodes, limit) {
  let days = 1, today = 0;
  for (const minutes of episodes) {
    if (today + minutes > limit) { days++; today = 0; } // start a new day
    today += minutes;
  }
  return days;
}

function smallestDailyLimit(episodes, maxDays) {
  const lo = Math.max(...episodes);
  const hi = episodes.reduce((sum, m) => sum + m, 0);
  return firstYes(lo, hi, (limit) => daysNeeded(episodes, limit) <= maxDays);
}

smallestDailyLimit([40, 25, 60, 30, 45, 20], 3); // 90

# Smallest x in [lo, hi] with is_yes(x) true.
# is_yes must go no, ..., no, yes, ..., yes, and is_yes(hi) must be true.
def first_yes(lo, hi, is_yes):
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if is_yes(mid):
            hi = mid      # mid works: answer is mid or smaller
        else:
            lo = mid + 1  # mid fails: answer is bigger
    return lo

# Assumes limit >= the longest episode.
def days_needed(episodes, limit):
    days, today = 1, 0
    for minutes in episodes:
        if today + minutes > limit:  # start a new day
            days += 1
            today = 0
        today += minutes
    return days

def smallest_daily_limit(episodes, max_days):
    lo, hi = max(episodes), sum(episodes)
    return first_yes(lo, hi, lambda limit: days_needed(episodes, limit) <= max_days)

smallest_daily_limit([40, 25, 60, 30, 45, 20], 3)  # 90

How to spot it

Reach for this pattern when a problem says "the smallest speed that…", "the largest size such that…", or "minimise the biggest…". Then check three things:

  1. You can bound the answer: a lo that is the smallest possible candidate and a hi that surely works.
  2. You can check a guess quickly, often with one greedy pass like daysNeeded.
  3. The answers are monotone: if x works, x + 1 works too. Say why out loud before you code.

When you want the largest value

Some problems flip: the answers go yes, …, yes, no, …, no, and you want the last yes. Do not write a new template. Search for the first no, then subtract 1. The integer square root of 30 is the largest x with x × x ≤ 30. The first x with x × x > 30 is 6, so the answer is 5.

// Largest x with x * x <= n, for n >= 0.
function intSqrt(n) {
  // n + 1 is surely a "no": (n + 1)² > n
  return firstYes(0, n + 1, (x) => x * x > n) - 1;
}

intSqrt(30); // 5

# Largest x with x * x <= n, for n >= 0.
def int_sqrt(n):
    # n + 1 is surely a "no": (n + 1)² > n
    return first_yes(0, n + 1, lambda x: x * x > n) - 1

int_sqrt(30)  # 5

Common mistakes

Start lo at 1 and daysNeeded(…, 50) puts the 60-minute episode in a day of its own, quietly breaking the limit. The check is only right from 60 up. Set lo to the smallest answer that makes sense.

The answers must switch from no to yes once. "Can I finish in exactly 3 days?" is not monotone: a huge limit takes 1 day, so it says no again. Ask "in at most 3 days?"

A last-yes search with lo = mid and a round-down mid loops forever once hi = lo + 1. Flip the question and use firstYes, as in the square root example.

Capacity planning uses the same move: "what is the fewest servers that keep response times under 200 ms?" Each guess is a load test. More servers never make it slower, so binary search finds the answer in a handful of expensive tests instead of dozens.

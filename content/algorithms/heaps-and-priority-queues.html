A busy kitchen gets delivery orders all evening, each with a pickup time. Whenever a cook is free, they start the order due soonest. New orders keep arriving, so the list never stays in order for long.

You need three operations: add an order, look at the most urgent one, and remove it. That container is a priority queue. A plain queue hands items out in arrival order; a priority queue hands them out by urgency.

Three ways to build it

  • Unsorted array: adding is instant, but finding the most urgent means scanning them all. O(n) per removal.
  • Sorted array: the most urgent is at one end, but each new order shifts the others to make room. O(n) per insert.
  • Heap: adding and removing cost O(log n), and peeking costs O(1).

With 100,000 waiting items, O(n) is 100,000 steps; O(log n) is about 17.

A min-heap, briefly

Heap Sort introduced the max-heap: a binary tree stored in an array, children of index i at 2i + 1 and 2i + 2, every parent at least as big as its children. "Soonest first" wants a min-heap: every parent is at most as big as its children, so the smallest item is at the root, heap[0].

Two facts make it fast:

  • The tree fills level by level, left to right, so n items make only about log₂ n levels.
  • The rule only compares parents with children; siblings can be in any order. A heap is not sorted, and that loose rule is cheap to repair after each change by moving one item along one path.

Push: add at the bottom, sift up

Put the new item in the next free slot, at the end of the array, which keeps the shape. Then sift it up: while it is smaller than its parent, swap them. The parent of index i is at (i − 1) / 2, rounded down.

Pop: move the last item to the top, sift down

The root is removed. To fill the hole, move the last item to the root and shorten the array. That item is probably too big, so sift it down: swap it with its smaller child until it is no bigger than both. It is heap sort's sift-down with "bigger" turned into "smaller".

Here are both, on orders due in 2, 4, 5, 7, 8 and 9 minutes. An order due in 3 arrives, then a cook takes the most urgent.

The code

// heap is a plain array kept in min-heap order.
function heapPush(heap, x) {
  heap.push(x); // add at the end of the bottom level
  let i = heap.length - 1;
  while (i > 0) {
    const parent = Math.floor((i - 1) / 2);
    if (heap[parent] <= heap[i]) break; // parent is smaller: done
    [heap[parent], heap[i]] = [heap[i], heap[parent]];
    i = parent; // keep climbing
  }
}

# heap is a plain list kept in min-heap order.
def heap_push(heap, x):
    heap.append(x)  # add at the end of the bottom level
    i = len(heap) - 1
    while i > 0:
        parent = (i - 1) // 2
        if heap[parent] <= heap[i]:  # parent is smaller: done
            break
        heap[parent], heap[i] = heap[i], heap[parent]
        i = parent  # keep climbing

function heapPop(heap) {
  const top = heap[0];
  const last = heap.pop(); // remove the last item
  if (heap.length === 0) return top; // it was the only one
  heap[0] = last; // move it to the root and sift down
  let i = 0;
  while (true) {
    const left = 2 * i + 1, right = 2 * i + 2;
    let small = i;
    if (left < heap.length && heap[left] < heap[small]) small = left;
    if (right < heap.length && heap[right] < heap[small]) small = right;
    if (small === i) break; // smaller than both children: done
    [heap[i], heap[small]] = [heap[small], heap[i]];
    i = small;
  }
  return top;
}

const heap = [2, 5, 4, 9, 7, 8];
heapPush(heap, 3); // [2, 5, 3, 9, 7, 8, 4]
heapPop(heap);     // 2, heap is now [3, 5, 4, 9, 7, 8]

def heap_pop(heap):
    top = heap[0]
    last = heap.pop()  # remove the last item
    if not heap:  # it was the only one
        return top
    heap[0] = last  # move it to the root and sift down
    i = 0
    while True:
        left, right = 2 * i + 1, 2 * i + 2
        small = i
        if left < len(heap) and heap[left] < heap[small]:
            small = left
        if right < len(heap) and heap[right] < heap[small]:
            small = right
        if small == i:  # smaller than both children: done
            break
        heap[i], heap[small] = heap[small], heap[i]
        i = small
    return top

heap = [2, 5, 4, 9, 7, 8]
heap_push(heap, 3)  # [2, 5, 3, 9, 7, 8, 4]
heap_pop(heap)      # 2, heap is now [3, 5, 4, 9, 7, 8]

Python's heapq module has heappush(heap, x) and heappop(heap), which work on a plain list like the functions above, and heapify(list), which builds a heap in O(n). JavaScript has no built-in heap: copy these functions or use a library.

To attach data, push pairs. Python tuples like (pickup_time, order_id) compare by the first item, then the second. In JavaScript, < does not compare arrays usefully, so store [time, order] and compare heap[i][0].

The top k trick

You want the 3 highest of a million scores. Sorting costs O(n log n) and keeps all n in memory. A heap does better, and surprisingly it is a min-heap.

Keep a min-heap of the best 3 so far. Its root is the weakest of them, the score to beat. Push each new score; if the heap grows to 4, pop the smallest. At the end, the heap holds the top 3.

// Uses heapPush and heapPop from above.
function topK(nums, k) {
  const heap = [];
  for (const x of nums) {
    heapPush(heap, x);
    if (heap.length > k) heapPop(heap); // drop the smallest
  }
  return heap.sort((a, b) => a - b);
}

topK([40, 95, 12, 77, 63, 88], 3); // [77, 88, 95]

import heapq

def top_k(nums, k):
    heap = []
    for x in nums:
        heapq.heappush(heap, x)
        if len(heap) > k:
            heapq.heappop(heap)  # drop the smallest
    return sorted(heap)

top_k([40, 95, 12, 77, 63, 88], 3)  # [77, 88, 95]

The heap holds at most k + 1 items, so each push and pop costs O(log k): O(n log k) time and O(k) space. For the top 10 of a million, log k is about 3, against about 20 for a full sort.

Common mistakes

The plain heapq functions build min-heaps. Python 3.14 added max-heap versions such as heapq.heappush_max; on older versions, push -x and negate again when you pop. Forgetting the second negation is the classic bug.

[2, 5, 4, 9, 7, 8] is a valid heap but not sorted. Only heap[0] is guaranteed: heap[1] is not the second smallest, and searching for an arbitrary value takes O(n). To get items in order, pop them one at a time.

Pushing into an array and calling sort() each time passes small tests, but each sort looks at every item, so n inserts cost at least O(n²). A heap push is O(log n).

Operating systems pick the next task with priority queues. Simulations keep upcoming events in a heap keyed by time. Dijkstra's algorithm uses one to expand the closest unvisited place next.

Your app worked last week. Today it crashes, and 1,000 changes were made in between. Don't test them one by one: test change 500. If the app crashes there, the culprit is in the first half; if not, the second. One test ruled out 500 changes. Ten tests pin it down.

That is binary search. It works because the changes have a shape: fine, fine, fine, broken, broken. You are looking for the boundary.

The idea: find the first "yes"

A sorted array has the same shape. Ask of each value in [3, 8, 8, 8, 12, 15, 20, 27]: "is this at least 8?" The answers are no, then yes all the way, because the array is sorted.

The position of the first "yes" is the lower bound of 8. It is the most useful single answer binary search gives:

  • If the value there is 8, it is the first 8.
  • If not, 8 is missing, and this is where to insert it to keep the array sorted.
  • If every answer is "no", the lower bound is n, one past the end.

To find it, keep two positions. Everything left of lo is a known "no"; everything from hi on is a known "yes". The undecided positions are [lo, hi): lo included, hi not. Check the middle, then throw away the half that cannot hold the first "yes".

Lower bound, traced

Watch what happens when the search lands on an 8: it does not stop, because an earlier 8 might exist.

The template

Learn this one function well. Almost every binary search on an array is this, or a small change to the comparison.

// First index i with a[i] >= target, or a.length if there is none.
// a must be sorted from low to high.
function lowerBound(a, target) {
  let lo = 0;
  let hi = a.length; // half-open range [lo, hi)
  while (lo < hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    if (a[mid] < target) lo = mid + 1; // mid is a "no": answer is right of it
    else hi = mid;                     // mid is a "yes": answer is mid or left
  }
  return lo; // lo === hi
}

function contains(a, target) {
  const i = lowerBound(a, target);
  return i < a.length && a[i] === target;
}

lowerBound([3, 8, 8, 8, 12, 15, 20, 27], 8); // 1

# First index i with a[i] >= target, or len(a) if there is none.
# a must be sorted from low to high.
def lower_bound(a, target):
    lo, hi = 0, len(a)  # half-open range [lo, hi)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if a[mid] < target:
            lo = mid + 1  # mid is a "no": answer is right of it
        else:
            hi = mid      # mid is a "yes": answer is mid or left
    return lo  # lo == hi

def contains(a, target):
    i = lower_bound(a, target)
    return i < len(a) and a[i] == target

lower_bound([3, 8, 8, 8, 12, 15, 20, 27], 8)  # 1

Every piece is there for a reason:

  • hi = n, not n − 1. The answer can be n ("everything is smaller"), so the range has to be able to end there.
  • while lo < hi. Loop while [lo, hi) is not empty. When lo == hi, the answer is pinned.
  • mid rounds down, so lo ≤ mid < hi: always a real index inside the range.
  • lo = mid + 1 on a "no", because mid is ruled out. hi = mid on a "yes", because mid might be the answer. Either way the range shrinks, so the loop ends.

Binary search finds the boundary between "no" and "yes". Move lo past every "no" and hi onto every "yes". When they meet, lo is the first "yes".

One template, many questions

Ask "greater than target" instead of "at least target" and you get the upper bound: the first index after all copies of the target. Only < changes to <=.

// First index i with a[i] > target, or a.length.
function upperBound(a, target) {
  let lo = 0, hi = a.length;
  while (lo < hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
    if (a[mid] <= target) lo = mid + 1;
    else hi = mid;
  }
  return lo;
}

const a = [3, 8, 8, 8, 12, 15, 20, 27];
upperBound(a, 8) - lowerBound(a, 8); // 3 copies of 8
upperBound(a, 8) - 1;                // 3: the last 8
lowerBound(a, 13);                   // 5: insert 13 here

# First index i with a[i] > target, or len(a).
def upper_bound(a, target):
    lo, hi = 0, len(a)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if a[mid] <= target:
            lo = mid + 1
        else:
            hi = mid
    return lo

a = [3, 8, 8, 8, 12, 15, 20, 27]
upper_bound(a, 8) - lower_bound(a, 8)  # 3 copies of 8
upper_bound(a, 8) - 1                  # 3: the last 8
lower_bound(a, 13)                     # 5: insert 13 here

Python ships both as bisect.bisect_left and bisect.bisect_right. JavaScript has no built-in.

Common mistakes

Most binary search bugs mix styles: hi = n − 1 from one version with while lo < hi and hi = mid from another. Then searching [1, 2, 3] for 9 returns 2 instead of 3: "past the end" can never come out. Pick one template and use all of it.

With lo = 4 and hi = 5, mid is 4. If a "no" sets lo = mid, nothing changes and the loop runs forever. Use lo = mid + 1.

if a[mid] == target: return mid finds an 8, not the first: in the trace it returns 2. Fine if any match will do; for first, last or how many, use the bounds.

Write lo + (hi − lo) / 2, not (lo + hi) / 2. Both work in JavaScript and Python, but in Java, C++ and Go, lo + hi can overflow on huge arrays.

The opening story is a real tool: git bisect finds the first bad commit among thousands in a dozen tests. Databases use the same idea on sorted index pages to find a row without reading the whole table.

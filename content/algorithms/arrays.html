Picture a row of school lockers numbered from 0. Asked for locker 412, you walk straight to it without opening 0 to 411.

Now the school squeezes a new student in at locker 3, keeping number order. Everyone from locker 3 onwards moves one locker right. Reading is instant; inserting in the middle is a chore. That is an array, and those two facts explain most of it.

One block of memory, numbered from 0

An array stores its items side by side in one unbroken block of memory, every slot the same size. The computer remembers only where the block starts.

That is enough to find any item. If the block starts at address 1000 and each slot takes 4 bytes, item 3 lives at 1000 + 3 × 4 = 1012, whether the array holds 5 items or 5 million. So reading or writing arr[i] is O(1). It is also why indexes start at 0: the index is the number of slots to skip.

A JavaScript array or Python list can mix values of different sizes because each slot holds a reference: a fixed-size note saying where the real value lives. The slots are still side by side.

Inserting means shifting

Side by side means no gaps. To put a new item at index 1, every item from index 1 onwards moves one slot right first. Start from the end, so you never overwrite a value before copying it.

Deleting is the reverse: every item after the gap moves one slot left. So inserting or deleting at position i costs about n − i moves: cheap at the end, O(n) at the front.

// What arr.splice(index, 0, value) does for you.
function insertAt(arr, index, value) {
  arr.push(undefined); // make room at the end
  for (let i = arr.length - 1; i > index; i--) {
    arr[i] = arr[i - 1]; // shift one slot right
  }
  arr[index] = value;
}

const nums = [3, 8, 5, 2];
insertAt(nums, 1, 9); // nums is now [3, 9, 8, 5, 2]

# What arr.insert(index, value) does for you.
def insert_at(arr, index, value):
    arr.append(None)  # make room at the end
    for i in range(len(arr) - 1, index, -1):
        arr[i] = arr[i - 1]  # shift one slot right
    arr[index] = value

nums = [3, 8, 5, 2]
insert_at(nums, 1, 9)  # nums is now [3, 9, 8, 5, 2]

You will rarely write this loop, but know it is there. splice, unshift, insert and pop(0) all hide one behind a single name.

How an array grows

A block of memory has a fixed size, yet push and append keep working. The language keeps spare slots at the end. Slots in use are the length; slots reserved are the capacity.

When the spare slots run out, the language reserves a new block, often about twice as big, and copies every item across. That append costs O(n), but it is rare: after a full block of 8 grows to 16, the next 7 appends copy nothing.

Filling an array to 16 items by doubling from 1 copies 1 + 2 + 4 + 8 = 15 items in total, fewer than one per append. So appending is amortized O(1): an occasional append is slow, but the average is constant.

An array is fast at the end and slow at the front. Reading any index is O(1), appending is O(1) on average, and anything that shifts items is O(n).

Finding which index holds the value 42 means checking items one by one. If you ask that often, keep a hash table next to the array, or keep it sorted and use binary search.

Common mistakes

An array of length 5 has indexes 0 to 4. arr[arr.length] gives undefined in JavaScript and IndexError in Python. The last item is arr[arr.length - 1]; loop while i < arr.length, not i <= arr.length.

A loop of queue.shift() or queue.pop(0) looks like one pass. In Python, each pop(0) shifts every remaining item, so the loop is O(n²). JavaScript engines sometimes avoid the shift, but you cannot count on it. Walk an index forward instead, or use a real queue (Queues and Deques).

On [4, 6, 6, 1], a loop deleting every 6 deletes index 1, then moves to index 2. But the second 6 just slid into index 1, so it is skipped. Loop backwards, or build a new array of the items you keep.

Images are arrays of pixels and audio is an array of samples, because jumping to pixel 1,000,000 has to be instant.

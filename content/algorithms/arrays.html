Picture a long row of school lockers, numbered from 0. Someone asks you for locker 412. You do not open lockers 0 to 411 on the way. You know where 412 is, so you walk straight to it.

Now the school wants to squeeze a new student in at locker 3 and keep everyone in number order. Every student from locker 3 onwards has to move their things one locker to the right. Reading is instant. Inserting in the middle is a chore. That is an array, and those two facts explain most of what you need to know about it.

One block of memory, numbered from 0

An array stores its items side by side in one unbroken block of memory. Every slot is the same size. The computer remembers only one thing: where the block starts.

That is enough to find any item. If the block starts at address 1000 and each slot takes 4 bytes, item 3 lives at 1000 + 3 × 4 = 1012. One multiplication and one addition, whether the array holds 5 items or 5 million. This is why reading or writing arr[i] is O(1), and it is also why indexes start at 0: the index is the number of slots to skip from the start.

JavaScript arrays and Python lists hold a reference in each slot rather than the value itself, so a slot can point to a number, a string or another list. The slots themselves are still side by side, so the same arithmetic finds them.

Inserting means shifting

The flip side of "everything side by side" is that there are no gaps. To put a new item at index 1, every item from index 1 onwards must move one slot right first. Start from the end, so you never overwrite a value before you have copied it.

Deleting works the same way in reverse: every item after the gap moves one slot left to close it. So inserting or deleting at position i costs about n − i moves. At the end it is cheap. At the front it is O(n).

// What arr.splice(index, 0, value) does for you.
function insertAt(arr, index, value) {
  arr.push(undefined); // make room at the end
  for (let i = arr.length - 1; i > index; i--) {
    arr[i] = arr[i - 1]; // shift one slot right
  }
  arr[index] = value;
}

const nums = [3, 8, 5, 2];
insertAt(nums, 1, 9); // nums is now [3, 9, 8, 5, 2]

# What arr.insert(index, value) does for you.
def insert_at(arr, index, value):
    arr.append(None)  # make room at the end
    for i in range(len(arr) - 1, index, -1):
        arr[i] = arr[i - 1]  # shift one slot right
    arr[index] = value

nums = [3, 8, 5, 2]
insert_at(nums, 1, 9)  # nums is now [3, 9, 8, 5, 2]

You will rarely write this loop yourself. The point is to know it is there. splice, unshift and shift in JavaScript, and insert and pop(0) in Python, all run a loop like this one behind a single friendly name.

How an array grows

A block of memory has a fixed size. So how does push or append keep working forever? The language keeps some spare slots at the end. The number of slots in use is the length; the number reserved is the capacity.

When the spare slots run out, the language reserves a new block, often about twice as big, copies every item across, and frees the old one. That one append costs O(n). But it happens rarely: when a full block of 8 grows to 16, the next 7 appends need no copying at all.

Add it up. Filling an array to 16 items by doubling from 1 copies 1 + 2 + 4 + 8 = 15 items in total, fewer than one copy per append. That is why appending to the end is called amortized O(1): an occasional append is slow, but the average over many appends is constant.

An array is fast at the end and slow at the front. Reading any index is O(1), appending is O(1) on average, and anything that makes items shift is O(n).

Searching is the other slow one. Knowing an item's index is instant, but knowing which index holds the value 42 means checking items one by one. If you need that question answered often, keep a hash table next to the array, or keep the array sorted and use binary search.

Common mistakes

An array of length 5 has indexes 0 to 4. arr[arr.length] is not the last item. JavaScript quietly gives you undefined, Python raises IndexError. The last item is arr[arr.length - 1], and loops should run while i < arr.length, not i <= arr.length.

Processing a list with while (queue.length) queue.shift() or queue.pop(0) looks like one pass. Each removal shifts every remaining item, so the whole loop is O(n²). Walk an index forward instead, or use a real queue, as in Queues and Deques.

On [4, 6, 6, 1], a loop that deletes every 6 deletes the one at index 1, then moves on to index 2. But the second 6 just slid into index 1, so it is skipped. Loop backwards when you delete, or build a new array with only the items you keep.

Images are arrays of pixels, audio is an array of samples, and a spreadsheet column is an array of cells. They use arrays because jumping straight to pixel number 2,073,600 has to be instant.

The café from Prefix Sums now has eight days of takings: 5, 2, 6, 3, 1, 4, 7, 2. The owner still asks "how much from day 2 to day 6?" all the time. But now the bookkeeper also keeps correcting old days: a refund here, a late receipt there.

Prefix sums answer a range question in O(1), but one correction to an early day changes every running total after it: O(n) per change. A plain array has the opposite problem: changes are O(1), but every sum is a loop. You want both fast.

The idea: precompute sums of blocks

Split the days in half, and each half in half again, down to single days. Store the total of every block. Now any range is a few whole blocks glued together, and a correction to one day only touches the blocks that contain it: one per level.

That is a segment tree. It is a binary tree where every node stores the sum of a range of the array. The root covers everything. Each node's left child covers the left half of its range, the right child the right half. The leaves are the single values.

It is stored in an array the same way as a heap: the children of node i sit at 2i + 1 and 2i + 2. For our eight days, node 0 covers indexes 0 to 7 and holds 30. Node 1 covers 0 to 3 (16), node 2 covers 4 to 7 (14), and so on down to the leaves at nodes 7 to 14.

Answering a range query

To get the sum of indexes 2 to 6, start at the root and ask each node one question: how does my range overlap the query?

  • Not at all: contribute 0 and stop.
  • Completely inside: contribute the stored sum and stop. No need to look below.
  • Partly: ask both children and add their answers.

Why is this O(log n)? At each level of the tree, at most two nodes are partial: the ones containing the left and right edges of the query. Everything between them is fully inside and stops at once. So each level costs a small constant, and there are about log₂(n) levels.

Changing one value

The bookkeeper finds that index 2 was really 11, not 6. Change the leaf, then walk up to the root, recomputing each parent as the sum of its two children. Only the blocks containing index 2 change.

class SegmentTree {
  constructor(values) {
    this.n = values.length;
    this.tree = new Array(4 * this.n).fill(0);
    this.build(values, 0, 0, this.n - 1);
  }
  build(values, node, lo, hi) {
    if (lo === hi) { this.tree[node] = values[lo]; return; }
    const mid = Math.floor((lo + hi) / 2);
    this.build(values, 2 * node + 1, lo, mid);
    this.build(values, 2 * node + 2, mid + 1, hi);
    this.tree[node] = this.tree[2 * node + 1] + this.tree[2 * node + 2];
  }
  // Sum of values[left..right], both included.
  query(left, right, node = 0, lo = 0, hi = this.n - 1) {
    if (right < lo || hi < left) return 0;                 // no overlap
    if (left <= lo && hi <= right) return this.tree[node]; // fully inside
    const mid = Math.floor((lo + hi) / 2);
    return this.query(left, right, 2 * node + 1, lo, mid) +
           this.query(left, right, 2 * node + 2, mid + 1, hi);
  }
  // Set values[index] = value.
  update(index, value, node = 0, lo = 0, hi = this.n - 1) {
    if (lo === hi) { this.tree[node] = value; return; }
    const mid = Math.floor((lo + hi) / 2);
    if (index <= mid) this.update(index, value, 2 * node + 1, lo, mid);
    else this.update(index, value, 2 * node + 2, mid + 1, hi);
    this.tree[node] = this.tree[2 * node + 1] + this.tree[2 * node + 2];
  }
}

class SegmentTree:
    def __init__(self, values):
        self.n = len(values)
        self.tree = [0] * (4 * self.n)
        self._build(values, 0, 0, self.n - 1)

    def _build(self, values, node, lo, hi):
        if lo == hi:
            self.tree[node] = values[lo]
            return
        mid = (lo + hi) // 2
        self._build(values, 2 * node + 1, lo, mid)
        self._build(values, 2 * node + 2, mid + 1, hi)
        self.tree[node] = self.tree[2 * node + 1] + self.tree[2 * node + 2]

    def query(self, left, right, node=0, lo=0, hi=None):
        """Sum of values[left..right], both included."""
        if hi is None:
            hi = self.n - 1
        if right < lo or hi < left:
            return 0                      # no overlap
        if left <= lo and hi <= right:
            return self.tree[node]        # fully inside
        mid = (lo + hi) // 2
        return (self.query(left, right, 2 * node + 1, lo, mid) +
                self.query(left, right, 2 * node + 2, mid + 1, hi))

    def update(self, index, value, node=0, lo=0, hi=None):
        """Set values[index] = value."""
        if hi is None:
            hi = self.n - 1
        if lo == hi:
            self.tree[node] = value
            return
        mid = (lo + hi) // 2
        if index <= mid:
            self.update(index, value, 2 * node + 1, lo, mid)
        else:
            self.update(index, value, 2 * node + 2, mid + 1, hi)
        self.tree[node] = self.tree[2 * node + 1] + self.tree[2 * node + 2]

Nothing here is specific to sums. Store each block's minimum, combine with min, and the same code answers "smallest value from index 2 to 6". Any combine step works if blocks can be merged in any grouping: sum, min, max, greatest common divisor.

Fenwick trees: the compact version

If you only need sums, a Fenwick tree (or binary indexed tree) does the same job with one array of n + 1 numbers and two tiny loops. Each slot stores part of a running total.

The slots are numbered from 1. Slot i stores the sum of the last lowbit(i) items up to item i, where lowbit(i) is the value of the lowest 1 bit of i, written i & -i (see Bit Manipulation). Slot 6 is 110 in binary, its lowest bit is 2, so it holds items 5 and 6. Slot 7 holds one item. Slot 8 holds all eight.

Two moves do everything:

  • Total of the first i items: add slot i, then jump to i − lowbit(i), the end of the next block to the left. Repeat until 0. For 7: slots 7, 6, 4.
  • Add to item i: add to slot i, then jump to i + lowbit(i), the next bigger block that also covers item i. Repeat while inside the array. For item 3: slots 3, 4, 8.

Each jump removes or carries a 1 bit, so either loop runs at most about log₂(n) times. Here is the same correction as before, item 3 (index 2) going up by 5, followed by a query.

The code below takes 0-based indexes from the caller and shifts by one inside, so it reads like the prefix sums formula: the sum of left..right is first(right + 1) − first(left).

class Fenwick {
  constructor(n) { this.t = new Array(n + 1).fill(0); }
  add(index, delta) { // values[index] += delta
    for (let i = index + 1; i < this.t.length; i += i & -i) this.t[i] += delta;
  }
  first(count) { // sum of the first count values
    let s = 0;
    for (let i = count; i > 0; i -= i & -i) s += this.t[i];
    return s;
  }
  rangeSum(left, right) { return this.first(right + 1) - this.first(left); }
}

const fw = new Fenwick(8);
[5, 2, 6, 3, 1, 4, 7, 2].forEach((v, i) => fw.add(i, v));
fw.add(2, 5);
fw.first(7);       // 33
fw.rangeSum(2, 6); // 26

class Fenwick:
    def __init__(self, n):
        self.t = [0] * (n + 1)

    def add(self, index, delta):  # values[index] += delta
        i = index + 1
        while i < len(self.t):
            self.t[i] += delta
            i += i & -i

    def first(self, count):  # sum of the first count values
        s, i = 0, count
        while i > 0:
            s += self.t[i]
            i -= i & -i
        return s

    def range_sum(self, left, right):
        return self.first(right + 1) - self.first(left)

fw = Fenwick(8)
for i, v in enumerate([5, 2, 6, 3, 1, 4, 7, 2]):
    fw.add(i, v)
fw.add(2, 5)
fw.first(7)        # 33
fw.range_sum(2, 6) # 26

Store answers for blocks of the array, arranged so any range is a few blocks and any item sits in a few blocks. That gives O(log n) for both questions and changes.

Which to pick? Use a Fenwick tree for sums and counts: less code, less memory. Use a segment tree when the combine step is min, max or anything that cannot be undone by subtraction, since the Fenwick range trick relies on subtracting two prefixes.

Common mistakes

add takes a change, not a new value. To set item 2 from 6 to 11, call add(2, 5), not add(2, 11). Keep a plain copy of the values so you can compute new − old.

0 & -0 is 0, so a loop that starts at slot 0 never moves and runs forever. That is why the slots start at 1 and the code shifts every index by one.

For lengths that are not a power of 2, heap-order indexes can go past 2n. With 10 items, index 24 is used. Allocate 4n.

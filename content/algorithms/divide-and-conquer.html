You and a friend each rank the same six films. To measure how much you disagree, count the pairs of films you put in opposite order.

Number the films 1 to 6 in your order, then write your friend's list using your numbers: [3, 6, 5, 1, 4, 2]. A disagreement is any bigger number before a smaller one. Checking every pair takes n(n − 1) / 2 comparisons, about 45 billion for 300,000 films. Divide and conquer does it in O(n log n).

The idea: split, solve, combine

Binary search and merge sort both follow three steps:

  1. Divide the input into smaller parts, usually two halves.
  2. Conquer each part by calling the same function on it.
  3. Combine the answers for the parts into the answer for the whole.

The first two steps are almost free to write. The thinking goes into the combine: once both halves are solved, what work is left that crosses the split, and how do you do it cheaply?

Counting disagreements

Split into [3, 6, 5] and [1, 4, 2]. A disagreement is inside the left half, inside the right half, or crosses the middle. The recursive calls count the first two. The combine counts only the crossing pairs.

The trick: the crossing count does not depend on the order inside each half. So each half can come back sorted, for free, since merging is what merge sort does anyway.

Every left item came before every right item in the list. So when a right item is smaller than the front of the left half, it is smaller than everything still waiting there. Add how many are waiting, in one step.

// Returns [sorted copy of a, number of disagreements in a].
function sortAndCount(a) {
  if (a.length <= 1) return [a, 0];
  const mid = Math.floor(a.length / 2);
  const [left, leftCount] = sortAndCount(a.slice(0, mid));
  const [right, rightCount] = sortAndCount(a.slice(mid));
  const merged = [];
  let i = 0, j = 0, cross = 0;
  while (i < left.length && j < right.length) {
    if (left[i] <= right[j]) {
      merged.push(left[i++]);
    } else {
      cross += left.length - i; // right[j] jumps every waiting left item
      merged.push(right[j++]);
    }
  }
  while (i < left.length) merged.push(left[i++]);
  while (j < right.length) merged.push(right[j++]);
  return [merged, leftCount + rightCount + cross];
}

sortAndCount([3, 6, 5, 1, 4, 2])[1]; // 10

# Returns (sorted copy of a, number of disagreements in a).
def sort_and_count(a):
    if len(a) <= 1:
        return a, 0
    mid = len(a) // 2
    left, left_count = sort_and_count(a[:mid])
    right, right_count = sort_and_count(a[mid:])
    merged = []
    i = j = cross = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i])
            i += 1
        else:
            cross += len(left) - i  # right[j] jumps every waiting left item
            merged.append(right[j])
            j += 1
    merged.extend(left[i:])
    merged.extend(right[j:])
    return merged, left_count + right_count + cross

sort_and_count([3, 6, 5, 1, 4, 2])[1]  # 10

The <= takes the left item first on a tie, because equal values are not a disagreement.

Reading the cost of any split

To price a divide and conquer algorithm, draw the call tree and add up the work level by level. Two things decide it: how many smaller calls each call makes, and what the combine costs.

Each call makesCombine costsTotalExample
1 call on halfO(1)O(log n)binary search, fast power below
1 call on halfO(n)O(n)quickselect: partition as in quicksort, keep only the side holding the median; on average n + n/2 + n/4 + … ≈ 2n
2 calls on halvesO(1)O(n)largest value by splitting in two
2 calls on halvesO(n)O(n log n)merge sort, counting disagreements

One half is enough: fast power

When both halves are the same problem, solve it once. 3¹³ = 3⁶ × 3⁶ × 3, and 3⁶ = 3³ × 3³, and so on. Each call halves the exponent and does one or two multiplications.

// x to the power n, for a whole number n >= 0
function power(x, n) {
  if (n === 0) return 1;
  const half = power(x, Math.floor(n / 2)); // solve the half once
  return n % 2 === 0 ? half * half : half * half * x;
}

power(3, 13); // 1594323

# x to the power n, for a whole number n >= 0
def power(x, n):
    if n == 0:
        return 1
    half = power(x, n // 2)  # solve the half once
    return half * half if n % 2 == 0 else half * half * x

power(3, 13)  # 1594323

The exponent goes 13, 6, 3, 1, 0: five calls and 7 multiplications, where a plain loop needs 12. An exponent of a billion takes 31 calls: O(log n), the table's first row.

Common mistakes

Counting crossing pairs with a nested loop makes the combine O(n²), and the whole algorithm is O(n²) again. The speed comes entirely from the cheap combine.

power(x, Math.floor(n / 2)) * power(x, Math.floor(n / 2)) makes two calls where one would do, and the cost climbs back to O(n). Store the result and reuse it.

With one item, mid is 0, so one "half" is empty and the other is the whole list again. Without the length <= 1 base case, the function calls itself on the same list forever.

If the parts overlap, so the same smaller problem is solved many times, divide and conquer can turn exponential, like the naive Fibonacci in Recursion. Switch to dynamic programming.

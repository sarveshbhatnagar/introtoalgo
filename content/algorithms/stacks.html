You type a word, make a line bold, then delete a paragraph. Press undo three times: the paragraph comes back, then the bold goes, then the word. Undo always reverses the most recent change not yet undone.

The editor does not search its history. It puts each change on top of a pile and takes from the top on undo. That pile is a stack.

The idea: one open end

A stack lets you touch only one end, the top, like a stack of plates. The last plate in is the first out: last in, first out (LIFO).

It has three operations, each O(1):

  • push: put an item on top.
  • pop: remove the top item and return it.
  • peek: look at the top item without removing it.

You rarely need a special class. The end of an array is a perfect top, because nothing shifts there:

  • JavaScript: push, pop, and stack[stack.length - 1] to peek.
  • Python: append, pop, and stack[-1] to peek.

Push is amortized O(1): now and then the array grows and copies itself, but the average stays constant. The head of a linked list also works as a top.

When to reach for a stack

Use a stack when the newest unfinished thing must be finished before anything older. That is the shape of anything nested: brackets, folders, function calls.

A code editor warns about broken brackets. {x: [1, (2)]} is fine. ([)] is not: the [ opened after the (, so it must close first.

Read the text left to right and push every opener. At a closer, its partner must be the most recent unclosed opener, which is the top of the stack. Pop it and compare.

The check fails in three ways:

  • A closer meets an empty stack: it closes nothing, as in ()).
  • A closer does not match the top: wrong order, as in ([)].
  • Openers are left at the end: never closed, as in ((.
const PAIRS = { ")": "(", "]": "[", "}": "{" };

function isBalanced(text) {
  const stack = [];
  for (const ch of text) {
    if (ch === "(" || ch === "[" || ch === "{") {
      stack.push(ch); // an opener waits for its closer
    } else if (ch in PAIRS) {
      if (stack.length === 0) return false;        // closes nothing
      if (stack.pop() !== PAIRS[ch]) return false; // wrong kind
    }
  }
  return stack.length === 0; // anything left was never closed
}

isBalanced("{x: [1, (2)]}"); // true
isBalanced("([)]");          // false

PAIRS = {")": "(", "]": "[", "}": "{"}

def is_balanced(text):
    stack = []
    for ch in text:
        if ch in "([{":
            stack.append(ch)  # an opener waits for its closer
        elif ch in PAIRS:
            if not stack:
                return False  # closes nothing
            if stack.pop() != PAIRS[ch]:
                return False  # wrong kind
    return not stack  # anything left was never closed

is_balanced("{x: [1, (2)]}")  # True
is_balanced("([)]")           # False

Run the bracket check by hand on [(]). Write down the stack after each character, and the character where the check returns false.

After [ the stack is [. After ( it is [ (, with ( on top. Then ] pops (, but needs [. Return false at index 2.

The last ) is never read: nothing later can fix the order.

Stacks you already use

  • The call stack. Each function call is pushed; returning pops it, as Recursion traced. Too deep, and you get a "stack overflow".
  • Undo and the back button. The newest action or page comes back first.
  • Depth-first search. Keep the places still to explore on a stack to go as deep as possible before backing up. See Depth-First Search.
  • Recursion as a loop. If recursion would go too deep, push the pending work onto your own stack and loop until it is empty.

A stack answers "what is the most recent thing still open?" in O(1). Whenever a problem keeps asking that, as nesting does, use a stack.

Common mistakes

In Python, [].pop() raises an error. In JavaScript it quietly returns undefined and the bug shows up elsewhere. Check the stack is not empty before every pop or peek.

Matching every closer is not enough: (( never fails inside the loop. Return "the stack is empty", not just true.

unshift and shift in JavaScript, or insert(0, x) and pop(0) in Python, move every other item, making each operation O(n). Push and pop at the end.

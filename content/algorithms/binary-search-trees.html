A game server keeps players sorted by score, so it can show each one the rival ranked just above. In a sorted array, binary search finds any score in about 20 steps among a million players. But new scores arrive all the time, and each insert shifts every later item one slot right: up to a million moves.

A binary search tree gives you the fast search without the shifting, as long as it keeps a sensible shape.

The rule: smaller left, bigger right

A binary search tree (BST) is a binary tree with one rule at every node:

  • every value in the node's left subtree is smaller than the node's value, and
  • every value in its right subtree is bigger.

So one comparison at the root throws away a whole side of the tree. That is binary search, built into the shape of the data instead of array indexes.

It also means an inorder traversal (left, node, right) reads the whole tree in sorted order.

Search and insert follow one path

To find a value, start at the root and compare. Equal: found. Smaller: go left. Bigger: go right. Step onto an empty child and the value is not there.

Insert is the same walk: when you fall off the tree, the empty spot is where the new value belongs. No other node moves.

// TreeNode is the same class as in Binary Trees.
function contains(node, val) {
  while (node !== null) {
    if (val === node.val) return true;
    node = val < node.val ? node.left : node.right; // throw away one side
  }
  return false;
}

// Returns the root of the tree with val added.
function insert(node, val) {
  if (node === null) return new TreeNode(val); // found the empty spot
  if (val < node.val) node.left = insert(node.left, val);
  else if (val > node.val) node.right = insert(node.right, val);
  return node; // a duplicate is ignored
}

let root = null;
for (const v of [40, 20, 60, 10, 30, 50, 70, 35]) root = insert(root, v);
contains(root, 35); // true
contains(root, 33); // false

insert returns the updated subtree's root, and the parent stores it with node.left = …. That handles the empty tree, where the new node becomes the root, with no special case.

The smallest value is the leftmost node; the largest is the rightmost.

Delete: three cases

Delete is the tricky one, because the tree must stay valid. Find the node, then count its children.

  1. No children: just remove it.
  2. One child: the child moves up into its place. Everything under it is already on the correct side of the parent.
  3. Two children: you cannot leave a hole with two subtrees hanging from it. Find the next bigger value, the successor: the leftmost node of the right subtree. Copy it into this node, then delete it from the right subtree. The successor has no left child, so that second delete is case 1 or 2.
// Returns the root of the tree with val removed.
function remove(node, val) {
  if (node === null) return null; // val is not in the tree
  if (val < node.val) node.left = remove(node.left, val);
  else if (val > node.val) node.right = remove(node.right, val);
  else {
    if (node.left === null) return node.right; // 0 or 1 child:
    if (node.right === null) return node.left; // the child moves up
    let next = node.right;                     // 2 children: find the
    while (next.left !== null) next = next.left; // next bigger value
    node.val = next.val;                       // copy it here
    node.right = remove(node.right, next.val); // and remove the copy
  }
  return node;
}

Cost depends on the height

Search, insert and delete each walk one path down, so each costs O(h), where h is the height. In a bushy tree h is about log₂ n: 20 levels for a million values. That beats a sorted array's O(n) insert.

The catch: shape depends on insert order. Insert 10, 20, 30, 40, 50 and each value goes right, building the stick from Binary Trees with height n. Searching it is no faster than scanning a list.

Every BST operation walks one root-to-leaf path. It is fast exactly when the tree is short. Balanced trees reshape themselves after each change to keep the height O(log n).

Common mistakes

A tree can pass "left child smaller, right child bigger" at every node and still break the rule. Below, 45 is a fine right child of 20, but it sits left of 40. A search for 45 goes right at the root and never finds it. To validate, pass down the allowed range (going left lowers the upper limit, going right raises the lower one), or check that inorder is strictly increasing.

insert(node.left, val) without node.left = … builds the new node and drops it. Likewise, without root = insert(root, val), the first insert into an empty tree is lost.

The code ignores a value already there, which suits a set. For counts, store a count in each node. Never send equal values to either side at random, or searches will miss them.

At work you rarely write a BST by hand. Java's TreeMap and C++'s std::map are balanced BSTs underneath. Reach for one when a sorted collection changes often and you ask things like "smallest key above 500".

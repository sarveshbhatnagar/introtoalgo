You have 300 quiz papers, each scored from 0 to 10, to put in order. Set out 11 trays labelled 0 to 10, drop each paper in the tray for its score, and stack the trays. One look per paper, no comparisons. That is counting sort. It beats every earlier sort, but only because the scores are small whole numbers in a known range.

The O(n log n) wall

Merge sort, quicksort and heap sort all learn the order by asking "is this item smaller than that one?" Such sorts can never beat O(n log n) in the worst case.

Why: n items have n × (n − 1) × … × 1 possible orders, and the sort must tell them apart. Each comparison at best halves them, and halving down to one takes about n log₂ n comparisons. For 10 items, 3,628,800 orders need at least 22 comparisons.

Counting sort never compares items. It uses each key as an array index.

The idea: count, then place

Say every key is a whole number from 0 to k − 1.

  1. Count how many items have each key.
  2. Work out where each key starts in the output. 0s start at position 0, 1s right after the 0s, 2s right after the 0s and 1s. That running total is a prefix sum of the counts.
  3. Place each item, in input order, at its key's start position, then move that start one step forward.

Step 3 walks the input in order, so equal keys keep their input order: counting sort is stable. Radix sort needs that.

In the trace, letters tell equal keys apart: 3a and 3b both have key 3, and 3a came first.

A key function turns each item into its whole-number key, so the code can sort records too.

// key(item) must be a whole number from 0 to k - 1
function countingSortBy(items, key, k) {
  const count = new Array(k).fill(0);
  for (const item of items) count[key(item)]++;
  const start = new Array(k).fill(0); // start[v] = items with key < v
  for (let v = 1; v < k; v++) start[v] = start[v - 1] + count[v - 1];
  const out = new Array(items.length);
  for (const item of items) {
    out[start[key(item)]++] = item; // input order: stable
  }
  return out;
}

countingSortBy([3, 1, 3, 0, 2, 1], (x) => x, 4); // [0, 1, 1, 2, 3, 3]

# key(item) must be a whole number from 0 to k - 1
def counting_sort_by(items, key, k):
    count = [0] * k
    for item in items:
        count[key(item)] += 1
    start = [0] * k  # start[v] = items with key < v
    for v in range(1, k):
        start[v] = start[v - 1] + count[v - 1]
    out = [None] * len(items)
    for item in items:  # input order: stable
        out[start[key(item)]] = item
        start[key(item)] += 1
    return out

counting_sort_by([3, 1, 3, 0, 2, 1], lambda x: x, 4)  # [0, 1, 1, 2, 3, 3]

Radix sort: one digit at a time

Counting sort needs one counter per possible key: 11 for quiz scores, a billion for order numbers up to a billion.

Radix sort works one digit at a time, so each pass is a counting sort with 10 counters. The surprise is the order: start with the last digit (ones), then tens, then hundreds.

Why it works: the last pass sorts by the most important digit, and numbers that tie on it keep the order the earlier passes gave them, which is correct for the lower digits.

// non-negative integers; uses countingSortBy from above
function radixSort(nums) {
  const biggest = nums.reduce((m, x) => Math.max(m, x), 0);
  for (let place = 1; place <= biggest; place *= 10) {
    nums = countingSortBy(nums, (x) => Math.floor(x / place) % 10, 10);
  }
  return nums;
}

radixSort([512, 38, 407, 223, 95, 340, 18]);
// [18, 38, 95, 223, 340, 407, 512]

# non-negative integers; uses counting_sort_by from above
def radix_sort(nums):
    biggest = max(nums, default=0)
    place = 1
    while place <= biggest:
        nums = counting_sort_by(nums, lambda x: x // place % 10, 10)
        place *= 10
    return nums

radix_sort([512, 38, 407, 223, 95, 340, 18])
# [18, 38, 95, 223, 340, 407, 512]

Common mistakes

Ten numbers up to 1,000,000,000 need a billion counters. Check the range first; if it is big, use radix sort or a comparison sort.

Each digit pass must be stable. If the hundreds pass reordered 018, 038 and 095 freely, the first two passes would be wasted and the result wrong.

−3 is not a valid array index. Use x − min as the key, or sort negatives separately.

Radix sort shines on millions of fixed-size keys, like 32-bit integers on a GPU or dates written as YYYYMMDD.

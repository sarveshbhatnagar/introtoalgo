Your step counter logged a week, in thousands of steps: 4, 2, 7, 1, 8, 3, 5. You want your best 3 days in a row. The obvious way adds up days 1 to 3, then 2 to 4, then 3 to 5, each from scratch.

But days 1 to 3 (4 + 2 + 7) and days 2 to 4 (2 + 7 + 1) share the 2 + 7. Only one day left and one arrived. So take the old sum, subtract the day that left, and add the day that arrived.

The idea: a frame that slides

A window is a frame over a run of neighbouring items, with a summary of what is inside: a sum, a count or a set. Each slide right lets one item in and at most one out, so two small updates replace a rebuild.

Fixed-size windows

When the size k is fixed, add up the first k items. Then, for each new item, add it and subtract the item k places behind it.

// Largest sum of k neighbouring items. Assumes 1 <= k <= nums.length.
function bestWindowSum(nums, k) {
  let sum = 0;
  for (let i = 0; i < k; i++) sum += nums[i];
  let best = sum;
  for (let right = k; right < nums.length; right++) {
    sum += nums[right] - nums[right - k]; // one in, one out
    best = Math.max(best, sum);
  }
  return best;
}

bestWindowSum([4, 2, 7, 1, 8, 3, 5], 3); // 16

# Largest sum of k neighbouring items. Assumes 1 <= k <= len(nums).
def best_window_sum(nums, k):
    total = sum(nums[:k])
    best = total
    for right in range(k, len(nums)):
        total += nums[right] - nums[right - k]  # one in, one out
        best = max(best, total)
    return best

best_window_sum([4, 2, 7, 1, 8, 3, 5], 3)  # 16

Windows that grow and shrink

Often the size is not given: you want "the longest run that obeys a rule" or "the shortest run that reaches a goal". Then the two edges move separately, like the same-direction shape in Two Pointers:

  1. Look at the next item, at right.
  2. If taking it in would break the rule, move left forward, removing items, until it would not.
  3. Take the item in and record the window's length if it is the best so far.

Example: the longest run of letters in "streets" with no repeats. The summary is a set of the window's letters, so "is this letter already inside?" costs O(1).

function longestNoRepeat(s) {
  const inWindow = new Set();
  let left = 0;
  let best = 0;
  for (let right = 0; right < s.length; right++) {
    while (inWindow.has(s[right])) { // shrink until the rule holds
      inWindow.delete(s[left]);
      left++;
    }
    inWindow.add(s[right]);
    best = Math.max(best, right - left + 1);
  }
  return best;
}

longestNoRepeat("streets"); // 4

def longest_no_repeat(s):
    in_window = set()
    left = 0
    best = 0
    for right in range(len(s)):
        while s[right] in in_window:  # shrink until the rule holds
            in_window.remove(s[left])
            left += 1
        in_window.add(s[right])
        best = max(best, right - left + 1)
    return best

longest_no_repeat("streets")  # 4

A sliding window updates a summary as items enter on the right and leave on the left. Each item enters once and leaves at most once, so the scan is O(n).

The while inside the for looks like O(n²), but left only goes forward and never passes right, so it moves at most n times in total.

Common mistakes

A window from left to right, both included, holds right - left + 1 items. right - left is always one short. Check with one item: left = right = 4 should give 1.

"Shrink while the sum is too big" works only when every number is positive, so removing an item always lowers the sum. With negatives, dropping an item can raise the sum and the window can throw away the answer. Use prefix sums instead.

sum(nums[i:i + k]) or nums.slice(i, i + k) inside the loop copies k items every time, turning the method back into O(n · k).

Rate limiters count requests in the last 60 seconds; dashboards show "average response time over the last 5 minutes". Both are windows sliding over time.

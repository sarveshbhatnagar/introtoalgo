Eight books stand on a shelf, with heights 5, 2, 8, 6, 3, 6, 9, 7. You want the books that stay to get strictly taller from left to right. You may take books off but never reorder them. What is the fewest you can remove?

Turn it around: find the most books you can keep. They form the longest increasing subsequence (LIS): values in their original order, not necessarily side by side, each bigger than the one before. Here its length is 4, for example 2, 3, 6, 9, so you remove 4 books.

Pick the state carefully

The 1D DP habit says: let best[i] be the answer for the first i books. But to decide whether book i can join, you need the last height of the sequence you are extending, and best[i] does not tell you that.

So pin the end down: make each cell about sequences that end exactly at book i. Then the last height is h[i].

  1. State. len[i] is the length of the longest increasing subsequence ending at index i.
  2. Recurrence. len[i] = 1 + max(len[j]) over all earlier j < i with smaller h[j] < h[i].
  3. Base case. If no earlier value is smaller, len[i] = 1.
  4. Order. Each cell reads cells to its left, so fill left to right.
  5. Answer. The largest value in len, since the longest sequence can end at any book.
function lisLength(heights) {
  const n = heights.length;
  const len = new Array(n).fill(1); // each value alone has length 1
  for (let i = 0; i < n; i++) {
    for (let j = 0; j < i; j++) {
      if (heights[j] < heights[i]) {
        len[i] = Math.max(len[i], len[j] + 1); // extend the run ending at j
      }
    }
  }
  return len.reduce((a, b) => Math.max(a, b), 0); // best over every end
}

lisLength([5, 2, 8, 6, 3, 6, 9, 7]); // 4

def lis_length(heights):
    n = len(heights)
    length = [1] * n  # each value alone has length 1
    for i in range(n):
        for j in range(i):
            if heights[j] < heights[i]:
                length[i] = max(length[i], length[j] + 1)  # extend the run ending at j
    return max(length, default=0)  # best over every end

lis_length([5, 2, 8, 6, 3, 6, 9, 7])  # 4

Faster: keep the lowest ending for each length

Comparing every pair costs about 50 million comparisons for 10,000 values. A different record needs about 14 steps per value, around 140,000 in all. Keep a list tails, where tails[k] is the smallest last value of any increasing subsequence of length k + 1 seen so far.

Why the smallest? Of two sequences with the same length, the one that ends lower is easier to extend: anything that fits after the higher one fits after the lower one too.

For each new value x, find the first tail >= x. If there is none, append x: it makes a longer sequence. Otherwise replace that tail with x: that length can now end lower. tails stays sorted, so the search is a binary search.

function lisLengthFast(heights) {
  const tails = [];
  for (const x of heights) {
    let lo = 0;
    let hi = tails.length; // find the first tail >= x
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (tails[mid] < x) lo = mid + 1;
      else hi = mid;
    }
    tails[lo] = x; // replaces a tail, or appends when lo === tails.length
  }
  return tails.length;
}

lisLengthFast([5, 2, 8, 6, 3, 6, 9, 7]); // 4

from bisect import bisect_left

def lis_length_fast(heights):
    tails = []
    for x in heights:
        k = bisect_left(tails, x)  # first tail >= x
        if k == len(tails):
            tails.append(x)  # longer than anything so far
        else:
            tails[k] = x  # same length, lower ending
    return len(tails)

lis_length_fast([5, 2, 8, 6, 3, 6, 9, 7])  # 4

When the answer depends on where a sequence ends, put the end into the state ("the best sequence that ends here"), then take the best over all ends.

Common mistakes

len[n − 1] is only the best sequence that ends at the last value. On 1, 2, 3, 0 it is 1, but the answer is 3. Take the maximum over the whole table.

tails has the right length but is not always a sequence you could keep. On 3, 4, 5, 1 it ends as 1, 4, 5, yet the 1 is the last book on the shelf. The length, 3, is still right. To list the actual values, use the table and walk back.

"Increasing" here means strictly bigger, so the search finds the first tail >= x (bisect_left). If equal values are allowed, find the first tail > x (bisect_right) and use <= in the table version.

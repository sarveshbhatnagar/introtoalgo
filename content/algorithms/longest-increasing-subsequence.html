Eight books stand on a shelf, with heights 5, 2, 8, 6, 3, 6, 9, 7. You want the books that stay to rise from left to right, strictly taller each time, and you are only allowed to take books off, never to reorder them. What is the fewest you can remove?

Turn it around: find the most books you can keep. Those form the longest increasing subsequence (LIS): the longest list of values, in their original order but not necessarily side by side, where each one is bigger than the one before. Here it has length 4, for example 2, 3, 6, 9, so you remove 4 books.

Pick the state carefully

The 1D DP habit says: let best[i] be the answer for the first i books. Try it. To decide whether book i can join, you need to know the last height of the sequence you are extending, and "the best for the first i books" does not tell you that.

So pin the end down. Make each cell about sequences that end exactly at book i. Then the last height is simply h[i], and extending is easy to check.

  1. State. len[i] is the length of the longest increasing subsequence that ends at index i, using h[i] as its last value.
  2. Recurrence. The value before h[i] is some earlier, smaller h[j]. Take the best of those: len[i] = 1 + max(len[j]) over all j < i with h[j] < h[i].
  3. Base case. If no earlier value is smaller, len[i] = 1: the book on its own.
  4. Order. Each cell reads cells to its left. Fill left to right.
  5. Answer. The largest value anywhere in len, because the longest sequence can end at any book.

Unlike the shifts in the 1D lesson, each cell here looks back at every earlier cell, not just two.

function lisLength(heights) {
  const n = heights.length;
  const len = new Array(n).fill(1); // each value alone has length 1
  for (let i = 0; i < n; i++) {
    for (let j = 0; j < i; j++) {
      if (heights[j] < heights[i]) {
        len[i] = Math.max(len[i], len[j] + 1); // extend the run ending at j
      }
    }
  }
  return len.reduce((a, b) => Math.max(a, b), 0); // best over every end
}

lisLength([5, 2, 8, 6, 3, 6, 9, 7]); // 4

def lis_length(heights):
    n = len(heights)
    length = [1] * n  # each value alone has length 1
    for i in range(n):
        for j in range(i):
            if heights[j] < heights[i]:
                length[i] = max(length[i], length[j] + 1)  # extend the run ending at j
    return max(length, default=0)  # best over every end

lis_length([5, 2, 8, 6, 3, 6, 9, 7])  # 4

Faster: keep the lowest ending for each length

The table compares every pair, which is about 50 million comparisons for 10,000 values. A cleverer record cuts that down. Keep a list called tails, where tails[k] is the smallest last value of any increasing subsequence of length k + 1 seen so far.

Why the smallest? If two sequences have the same length, the one that ends lower is easier to extend: anything that fits after the higher one also fits after the lower one. So for each length, you only need to remember the lowest ending.

For each new value x, find the first tail that is >= x. If there is none, x is bigger than every tail and makes a longer sequence: append it. Otherwise replace that tail with x: a sequence of that length can now end lower. tails stays sorted the whole time, so the search is a binary search.

function lisLengthFast(heights) {
  const tails = [];
  for (const x of heights) {
    let lo = 0;
    let hi = tails.length; // find the first tail >= x
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (tails[mid] < x) lo = mid + 1;
      else hi = mid;
    }
    tails[lo] = x; // replaces a tail, or appends when lo === tails.length
  }
  return tails.length;
}

lisLengthFast([5, 2, 8, 6, 3, 6, 9, 7]); // 4

from bisect import bisect_left

def lis_length_fast(heights):
    tails = []
    for x in heights:
        k = bisect_left(tails, x)  # first tail >= x
        if k == len(tails):
            tails.append(x)  # longer than anything so far
        else:
            tails[k] = x  # same length, lower ending
    return len(tails)

lis_length_fast([5, 2, 8, 6, 3, 6, 9, 7])  # 4

When the answer depends on where a sequence ends, put the end into the state: "the best sequence that ends here". Then take the best over all the ends.

Common mistakes

len[n − 1] is only the best sequence that ends at the last value. On 1, 2, 3, 0 it is 1, but the answer is 3. Take the maximum over the whole table.

tails holds the right length, but it is not always a sequence you could keep. On 3, 4, 5, 1 it ends as 1, 4, 5, and the 1 comes last in the list, so 1, 4, 5 is not in order. If you need the actual values, use the table and walk back.

"Increasing" here means strictly bigger, so equal heights cannot both stay. That is why the search looks for the first tail >= x (bisect_left). If equal values are allowed, look for the first tail > x instead (bisect_right), and use <= in the table version.

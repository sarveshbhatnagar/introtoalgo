The longest increasing subsequence (LIS) of a list is the longest sequence of values, taken in their original order and not necessarily next to each other, in which each value is larger than the one before it. You use it when a problem asks how many items you can keep, or how few you must remove, so that what remains is in increasing order.

Take eight books on a shelf with heights 5, 2, 8, 6, 3, 6, 9, 7. The longest increasing subsequence has length 4, for example 2, 3, 6, 9. If you want the remaining books to rise in height from left to right, you keep those 4 and remove the other 4, which is the fewest removals possible. The brute-force approach of checking every subset takes exponential time, while dynamic programming solves the problem in O(n²) and a binary search trick in O(n log n).

Defining the state: the best sequence that ends at each position

The usual 1D DP choice is to let best[i] be the answer for the first i values. That does not work here, because to decide whether value i can extend a sequence you need to know the last value of that sequence, and best[i] does not tell you.

The fix is to define each cell as the longest increasing subsequence that ends exactly at position i. Then the last value is known: it is h[i], the height at position i.

  1. State. len[i] is the length of the longest increasing subsequence that ends at index i.
  2. Recurrence. len[i] = 1 + max(len[j]) over all earlier indexes j < i with h[j] < h[i].
  3. Base case. If no earlier value is smaller, len[i] = 1, because the value alone is a sequence.
  4. Order. Each cell reads cells to its left, so fill the table from left to right.
  5. Answer. The largest value in len, because the longest sequence can end at any position.

The O(n²) table in code

function lisLength(heights) {
  const n = heights.length;
  const len = new Array(n).fill(1); // each value alone has length 1
  for (let i = 0; i < n; i++) {
    for (let j = 0; j < i; j++) {
      if (heights[j] < heights[i]) {
        len[i] = Math.max(len[i], len[j] + 1); // extend the run ending at j
      }
    }
  }
  return len.reduce((a, b) => Math.max(a, b), 0); // best over every end
}

lisLength([5, 2, 8, 6, 3, 6, 9, 7]); // 4

def lis_length(heights):
    n = len(heights)
    length = [1] * n  # each value alone has length 1
    for i in range(n):
        for j in range(i):
            if heights[j] < heights[i]:
                length[i] = max(length[i], length[j] + 1)  # extend the run ending at j
    return max(length, default=0)  # best over every end

lis_length([5, 2, 8, 6, 3, 6, 9, 7])  # 4

The O(n log n) method: keep the smallest ending for each length

The table compares every pair of values, which is too slow for inputs of tens of thousands of values. The faster method keeps a list tails, where tails[k] is the smallest last value of any increasing subsequence of length k + 1 found so far.

The smallest last value is the useful one to keep. Of two subsequences with the same length, the one that ends lower is easier to extend, because any value that fits after the higher ending also fits after the lower one.

For each new value x, find the first tail that is greater than or equal to x. If there is none, x extends the longest subsequence, so append it. Otherwise replace that tail with x, because a subsequence of that length can now end lower. The list tails always stays sorted, so the search is a binary search, and each value costs about log n steps.

function lisLengthFast(heights) {
  const tails = [];
  for (const x of heights) {
    let lo = 0;
    let hi = tails.length; // find the first tail >= x
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (tails[mid] < x) lo = mid + 1;
      else hi = mid;
    }
    tails[lo] = x; // replaces a tail, or appends when lo === tails.length
  }
  return tails.length;
}

lisLengthFast([5, 2, 8, 6, 3, 6, 9, 7]); // 4

from bisect import bisect_left

def lis_length_fast(heights):
    tails = []
    for x in heights:
        k = bisect_left(tails, x)  # first tail >= x
        if k == len(tails):
            tails.append(x)  # longer than anything so far
        else:
            tails[k] = x  # same length, lower ending
    return len(tails)

lis_length_fast([5, 2, 8, 6, 3, 6, 9, 7])  # 4

Variants and when LIS does not apply

Non-decreasing instead of strictly increasing

The versions above require each value to be strictly larger than the one before. If equal values are allowed, as in "longest non-decreasing subsequence", change the table condition from h[j] < h[i] to h[j] <= h[i]. In the tails method, search for the first tail that is strictly greater than x (bisect_right in Python) instead of the first tail that is greater than or equal to it. Using the wrong search turns an equal value into a replacement when it should be an append, and the length comes out too small.

Returning the subsequence, not just its length

With the table, store for each index the previous index that produced its best length, then start at the index with the largest len and follow those links back. The tails method can do this too: keep the index of the value in each tail slot, and when a value is placed in slot k, record the index in slot k - 1 as its predecessor. The contents of tails are not the answer, because a later replacement can leave a list that no real subsequence matches.

Counting the longest subsequences

If the question asks how many longest increasing subsequences exist, the length table is not enough. Keep a second table count[i] that holds how many subsequences of length len[i] end at i. When extending from j gives a longer length, copy count[j]. When it gives the same length as the current best, add count[j]. This stays O(n²).

Nested pairs, such as envelopes

Problems that nest items by two dimensions, such as putting one envelope inside another only when both its width and height are strictly smaller, reduce to LIS. Sort by width ascending and, for equal widths, by height descending, then run LIS on the heights. The descending order for equal widths stops two envelopes of the same width from being counted as nested.

When LIS does not apply

LIS requires the kept values to appear in the original order. If you may reorder the items freely, you can just sort them, and the answer is the number of distinct values. If the kept values must be next to each other, the problem is a longest-run problem, solved with one pass and a counter. If the problem compares two sequences instead of one, it is closer to the longest common subsequence, covered in DP on strings.

Pitfalls and nuances

The value len[n - 1] is only the best subsequence that ends at the last value. On 1, 2, 3, 0 it is 1, but the answer is 3. Take the maximum over the whole table.

The list tails has the correct length but is not always a subsequence of the input. On 3, 4, 5, 1 it ends as 1, 4, 5, yet the 1 comes after the 4 and 5 in the input. The length, 3, is still right. To list the actual values, use the predecessor links described above.

Using bisect_right for a strictly increasing problem lets duplicates extend a subsequence. On 2, 2, 2 it returns 3 instead of 1. Test a list of equal values before you submit.

In the interview

How to recognise the problem

Look for a request to find the longest, or the number of items to remove, so that a sequence ends up increasing, without moving anything. Phrases such as "in order but not necessarily adjacent", "stacking", "nesting", "chain" or "fewest removals to make it sorted" all point to LIS. Once you see that the choice at each position depends on the last chosen value, define the state as the best sequence ending at that position.

Follow-up questions

How would you return the subsequence itself? Store a predecessor index for each position along with its length, then follow the links back from the position with the largest length. In the tails method, store the index in each tail slot and the predecessor of each value at the moment it is placed. A common mistake is to print the contents of tails.

Why is it correct to replace a tail with a smaller value? The slot only records the lowest possible ending for a subsequence of that length. A lower ending can be extended by every value that the old ending could be extended by, so no future answer is lost, and the number of slots in use is still the length of the longest subsequence so far.

Can you do better than O(n log n)? In the comparison model, O(n log n) is the best possible, so the tails method is the answer interviewers expect. They usually want you to give the O(n²) table first and then improve it.

Why does the tails list stay sorted? A new value either goes after the last tail, which keeps the order, or replaces the first tail that is at least as large. The replacement is still larger than the tail before it, because that tail was smaller than the value, and it is no larger than the tail it replaced, so the order holds. Sortedness is what makes binary search valid.

What changes if equal values are allowed? Use <= in the table, and search for the first tail strictly greater than x in the tails method. Say this out loud before coding, because it is the most common place to lose points.

How does this relate to the longest common subsequence? The LIS of a sequence equals the longest common subsequence of that sequence and its sorted version with duplicates removed. That gives an O(n²) solution through DP on strings, which is slower than the tails method but sometimes a useful way to explain the idea.

You want to count the files in your Photos folder. Inside are photos, but also folders: "2023", "2024", "Holidays". Inside "Holidays" is a folder per trip, and maybe more inside those. You do not know how deep it goes.

A plain loop needs one loop per level, and you do not know how many levels there are. But the job describes itself: "The files in a folder are the files directly in it, plus the files in each subfolder." That is recursion.

The idea: solve a smaller copy

A recursive function calls itself on a smaller piece of the problem. It has two parts:

  • Base case. A piece small enough to answer directly. A single file counts as 1.
  • Recursive case. Call yourself on each smaller piece and combine the answers. Add up the counts of everything inside the folder.

The base case stops the calls, and each call must move closer to it. A subfolder holds less than the folder around it, so the calls shrink until they hit single files.

Here a folder is a list whose items are files (strings) or folders (lists). ["a", ["b", "c"], "d"] is two files plus a subfolder holding two more.

function countFiles(item) {
  if (typeof item === "string") return 1; // base case: one file
  let total = 0;                          // recursive case: a folder
  for (const child of item) {
    total += countFiles(child);           // trust the smaller call
  }
  return total;
}

countFiles(["a", ["b", "c"], "d"]);                 // 4
countFiles(["a.jpg", ["b.jpg", ["c.jpg", []]], []]); // 3

def count_files(item):
    if isinstance(item, str):
        return 1  # base case: one file
    total = 0     # recursive case: a folder
    for child in item:
        total += count_files(child)  # trust the smaller call
    return total

count_files(["a", ["b", "c"], "d"])                  # 4
count_files(["a.jpg", ["b.jpg", ["c.jpg", []]], []])  # 3

The function never handles grandchildren. It only asks each child for its count and adds them up. Any depth works. An empty folder gives 0, because the loop does not run.

Assume the recursive call already works for the smaller input. Your only jobs are the base case and combining the smaller answers.

Trace it: the call stack

"Trust the smaller call" has a plain mechanism behind it. When a function calls another, the computer pauses the first, remembers where it was and what its variables held, and runs the new call. When that returns, the paused one carries on. Paused calls wait in the call stack: newest on top, and only the top one runs.

Step through countFiles(["a", ["b", "c"], "d"]). The top row is the call stack, oldest on the left.

Every waiting call costs a little memory. So recursion uses memory in proportion to how deep the calls go, even if you never create a list.

When recursion repeats itself

Some problems split into overlapping pieces. In the Fibonacci sequence, 0, 1, 1, 2, 3, 5, 8, each number is the sum of the two before it: fib(n) = fib(n − 1) + fib(n − 2), with base cases fib(0) = 0 and fib(1) = 1. It is correct, and very slow.

Each non-base call makes two more, so each +1 to n multiplies the calls by about 1.6. fib(30) makes 2,692,537 calls, almost all repeats. The fix is to remember answers you already worked out: the start of dynamic programming.

Recursion or a loop

Anything recursive can be rewritten as a loop with your own stack. To choose:

  • Use recursion when the data is nested: folders, trees, menus inside menus, JSON inside JSON. The code mirrors the data.
  • Use recursion when the problem splits into smaller copies, as in merge sort and divide and conquer, or when you try choices one at a time, as in backtracking.
  • Use a loop for a flat walk over a list. Summing 100,000 numbers recursively means 100,000 waiting calls. Python refuses at about 1,000 by default.

Common mistakes

Without a reachable base case, the stack fills up and the program crashes ("Maximum call stack size exceeded" in JavaScript, RecursionError in Python). Check that some case returns without calling, and every call works on something strictly smaller.

countFiles(child); on its own line discards the result, so every folder reports 0. Use the result: total += countFiles(child).

Recursion has no visible list, but it is not O(1) space. The space is the depth of the calls: O(d) for folders, O(n) for a chain of n calls.

Write the base case first. Then assume the function works on smaller inputs and ask: "Given the smaller answers, how do I build this one?"

Someone asks you what 17 × 24 is and wants the answer in one second. You blurt out something close, maybe 398. Give yourself a pencil and ten seconds and you write 17 × 20 = 340, 17 × 4 = 68, 340 + 68 = 408. Same brain. The difference is that the paper held the in-between steps.

A language model has a similar limit, and the same fix. The only paper it has is the text it writes.

The text is the model's scratch paper

A model produces its reply one token at a time. To choose each token, it runs the same fixed stack of calculations over everything before it: your prompt plus whatever it has already written. That is a limited amount of work per token. Unless a tool gives it a hidden scratch area (more on that below), it has no notebook where it can work things out first and then reply.

That has a direct consequence. If the first words of the reply must be the answer, the answer is produced with no working on the page. If the reply starts with the working, each step becomes text, and every later token, including the final answer, can build on it.

For problems with several steps, ask for the working before the answer. Reasoning written down becomes input for everything the model writes after it.

Watch it happen

Here is a small shopping problem: pens cost $9 for a pack of 12, or $1 each. What is the cheapest way to buy exactly 30 pens? Work it out yourself first. The tracer shows two illustrative replies, one asked for the price only and one asked to work it out first.

Reply A was not careless. It was asked to commit first, so it committed to the most obvious-looking number. Reply B was allowed to lay the options out, which turned a tricky question into an easy one: pick the smallest.

This does not make the model always right. Steps can still be wrong. But a wrong step written on the page is something you can see and check, which a wrong one-word answer is not.

Separate the working from the answer

Working makes replies longer. If a person or a program only needs the result, ask for the two parts in clearly marked sections.

Our team of 6 needs a meeting slot. Ana can't do mornings. Ben is out Tuesday and Wednesday. Chloe only works Monday to Wednesday. Slots: Mon 10:00, Tue 14:00, Wed 15:00, Thu 11:00. Which slot works for everyone? One word. Wednesday

Wednesday fails: Ben is out. Checking each person against each slot is several small steps, and the prompt left no room for them.

Our team of 6 needs a meeting slot. Ana can't do mornings. Ben is out Tuesday and Wednesday. Chloe only works Monday to Wednesday. Slots: Mon 10:00, Tue 14:00, Wed 15:00, Thu 11:00. Check each slot against each constraint inside tags. Then give the slot that works for everyone inside tags, or "none" if no slot works. Mon 10:00: morning, so Ana can't. Out. Tue 14:00: Ben is out Tuesday. Out. Wed 15:00: Ben is out Wednesday. Out. Thu 11:00: morning for Ana, and Chloe doesn't work Thursday. Out. none

The honest answer was "none", which the one-word prompt made very unlikely, because it implied one slot must work. The second prompt allowed for that case explicitly, a habit from Be Clear and Specific.

With the answer in tags, a program can ignore the working and pull out the result:

function extractAnswer(reply) {
  const match = reply.match(/([\s\S]*?)<\/answer>/);
  return match ? match[1].trim() : null; // null: the tag was missing
}

const reply = "Mon 10:00 ... Out.\nnone";
console.log(extractAnswer(reply)); // "none"

import re

def extract_answer(reply):
    match = re.search(r"(.*?)", reply, re.DOTALL)
    return match.group(1).strip() if match else None  # None: the tag was missing

reply = "Mon 10:00 ... Out.\nnone"
print(extract_answer(reply))  # none

Always handle the missing-tag case. A model usually follows the format, not always, and your code should notice instead of crashing.

Some models and tools have a built-in thinking or reasoning setting. With it on, the model writes working before the final reply, and you may or may not get to see it. The principle is the same. When that setting is on, adding "think step by step" helps less, but asking for working in a set structure is still useful when you want to read or check the steps.

When to skip it

Room to think helps when there are steps: arithmetic, comparing options, checking rules, debugging, planning. It adds little to a lookup ("What is the capital of Peru?") or a short creative task, and it costs time and tokens on every request. For very large tasks, a different form of room helps more: split the job into several prompts, each doing one stage, and feed each result into the next.

Try it yourself

This prompt gets a one-word pick that often ignores the commute. Rewrite it so the model compares the offers on what matters before choosing, and so the choice is easy to find in the reply.

 Which job offer should I take? Just tell me A, B or C. A: $62k, 70-minute commute each way. B: $58k, fully remote. C: $60k, 20-minute commute, 4-day week. Help me pick a job offer. I care most about time with my family, then pay. A: $62k, 70-minute commute each way, 5 days a week. B: $58k, fully remote. C: $60k, 20-minute commute each way, 4-day week. Inside tags: work out the weekly hours spent commuting for each, then compare the offers on free time first and pay second. Then give your pick inside tags as one letter, followed by one sentence explaining why.

Why it works: the model now writes the numbers it needs before deciding (A is about 11.7 hours of commuting a week, C about 2.7, B none). Stating your priorities gives it a rule for weighing them. The answer tag keeps the choice easy to find, and the one-sentence reason lets you check it against the working.

Common mistakes

"Give the answer, then explain" gets you a justification, not reasoning. The answer is fixed before any working exists. Put the working first.

Written steps make errors easier to spot, but they are not guaranteed to be correct, and they do not always reflect how the model really reached its answer. Read them, and check key numbers yourself, as Verifying AI Output explains.

"Be brief" or "one word only" on a multi-step problem quietly removes the working. If you want a short final answer, say that the final answer should be short, not the whole reply.

Someone wants 17 × 24 in one second. You blurt out maybe 398. With a pencil you write 17 × 20 = 340, 17 × 4 = 68, 340 + 68 = 408. Same brain; the paper held the steps.

A language model has the same limit and the same fix. Its only paper is the text it writes.

The text is the model's scratch paper

A model writes one token at a time, running a fixed stack of calculations over your prompt plus what it has written. That is limited work per token, and without a hidden scratch area (see below) it has nowhere to work things out first.

So if the reply must open with the answer, the answer comes with no working on the page. If the reply starts with the working, each step becomes text that every later token, including the answer, can build on.

For problems with several steps, ask for the working before the answer. Written reasoning becomes input for everything after it.

Separate the working from the answer

Working makes replies longer. If only the result is needed, ask for the two parts in marked sections.

Our team of 6 needs a meeting slot. Ana can't do mornings. Ben is out Tuesday and Wednesday. Chloe only works Monday to Wednesday. Slots: Mon 10:00, Tue 14:00, Wed 15:00, Thu 11:00. Which slot works for everyone? One word. Wednesday

Wednesday fails: Ben is out. Checking each person against each slot takes several steps, and the prompt left no room for them.

Our team of 6 needs a meeting slot. Ana can't do mornings. Ben is out Tuesday and Wednesday. Chloe only works Monday to Wednesday. Slots: Mon 10:00, Tue 14:00, Wed 15:00, Thu 11:00. Check each slot against each constraint inside tags. Then give the slot that works for everyone inside tags, or "none" if no slot works. Mon 10:00: morning, so Ana can't. Out. Tue 14:00: Ben is out Tuesday. Out. Wed 15:00: Ben is out Wednesday. Out. Thu 11:00: morning for Ana, and Chloe doesn't work Thursday. Out. none

The honest answer was "none", which the one-word prompt made unlikely by implying a slot must work. The second allowed for it, a habit from Be Clear and Specific. With the answer in tags, a program can skip the working:

function extractAnswer(reply) {
  const match = reply.match(/([\s\S]*?)<\/answer>/);
  return match ? match[1].trim() : null; // null: the tag was missing
}

const reply = "Mon 10:00 ... Out.\nnone";
console.log(extractAnswer(reply)); // "none"

import re

def extract_answer(reply):
    match = re.search(r"(.*?)", reply, re.DOTALL)
    return match.group(1).strip() if match else None  # None: the tag was missing

reply = "Mon 10:00 ... Out.\nnone"
print(extract_answer(reply))  # none

Always handle a missing tag: models usually follow the format, not always.

Some models and tools have a built-in thinking setting: the model writes working before the reply, which you may or may not see. With it on, "think step by step" helps less, but asking for working in a set structure still helps when you want to check the steps.

When to skip it

Room to think helps with steps: arithmetic, comparing options, checking rules, debugging, planning. It adds little to a lookup or a short creative task, and costs time and tokens. For very large tasks, split the job into several prompts, feeding each result into the next.

Try it yourself

This prompt gets a one-word pick that often ignores the commute. Rewrite it so the model compares the offers on what matters before choosing, with the choice easy to find.

 Which job offer should I take? Just tell me A, B or C. A: $62k, 70-minute commute each way. B: $58k, fully remote. C: $60k, 20-minute commute, 4-day week. Help me pick a job offer. I care most about time with my family, then pay. A: $62k, 70-minute commute each way, 5 days a week. B: $58k, fully remote. C: $60k, 20-minute commute each way, 4-day week. Inside tags: work out the weekly hours spent commuting for each, then compare the offers on free time first and pay second. Then give your pick inside tags as one letter, followed by one sentence explaining why.

Why it works: the model writes the numbers before deciding (A is about 11.7 hours of commuting a week, C about 2.7, B none), and your priorities say how to weigh them. The tag makes the choice easy to find.

Common mistakes

"Give the answer, then explain" gets a justification, not reasoning: the answer is fixed before any working exists.

Written steps make errors easier to spot, but they can be wrong and do not always reflect how the model reached its answer. Check key numbers yourself (Verifying AI Output).

"Be brief" or "one word only" on a multi-step problem quietly removes the working. Ask for a short final answer, not a short reply.

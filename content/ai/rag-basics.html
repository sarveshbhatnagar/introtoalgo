Two students sit an exam. One answers from memory of a textbook read a year ago. The other may bring three pages of notes, picked just before. On those topics the second wins easily, and can point to where each answer came from.

A model answering from training is the first student. Your help pages, handbook or meeting notes were never in its memory, and a real document collection is far bigger than any context window. So be the second student: look up the few passages that matter, then answer from them.

Retrieve, augment, generate

That is RAG (retrieval-augmented generation):

  1. Retrieve the passages most related to the question.
  2. Augment the prompt with them, and say to answer from them.
  3. Generate the answer, ideally citing the passages.

The model is unchanged. RAG is a context engineering technique that selects material automatically for each question.

The search usually matches meaning, not exact words, using embeddings, because people rarely use your documents' words. Someone asks "when do I get my money back?" and the answer sits under "Refund processing times".

Indexing is slow, so it happens ahead of time: each document is cut into passages called chunks (see the next lesson), each chunk becomes a vector, and the vectors are saved. At question time you only embed the question and compare.

Retrieval by hand

A bookshop's help centre has five chunks. Pretend embeddings have just three numbers: roughly "about money", "about shipping" and "about accounts". Real ones have hundreds or thousands, but the arithmetic is the same.

"When will I get my money back?" embeds to [5, 1, 0]: mostly money, a little shipping. Its length is √26 ≈ 5.10. Score each chunk with cosine similarity (Embeddings) and keep the top 2.

function topK(queryVec, chunks, k) {
  return chunks
    .map((c) => ({ ...c, score: cosine(queryVec, c.vec) }))
    .sort((a, b) => b.score - a.score)
    .slice(0, k);
}

function buildPrompt(question, passages) {
  const sources = passages.map((p, i) => `[${i + 1}] ${p.text}`).join("\n");
  return `Answer using only the sources below. Cite them like [1].
If they do not contain the answer, say "I don't know."

${sources}

Question: ${question}`;
}

import math

def dot(a, b):
    return sum(x * y for x, y in zip(a, b))

def cosine(a, b):
    return dot(a, b) / math.sqrt(dot(a, a) * dot(b, b))

def top_k(query_vec, chunks, k):
    scored = [{**c, "score": cosine(query_vec, c["vec"])} for c in chunks]
    scored.sort(key=lambda c: c["score"], reverse=True)
    return scored[:k]

def build_prompt(question, passages):
    sources = "\n".join(f"[{i + 1}] {p['text']}" for i, p in enumerate(passages))
    return (
        "Answer using only the sources below. Cite them like [1].\n"
        'If they do not contain the answer, say "I don\'t know."\n\n'
        f"{sources}\n\nQuestion: {question}"
    )

chunks = [
    {"text": "Refunds reach your card 5 to 7 days after we receive the return.", "vec": [4, 1, 0]},
    {"text": "You can return items within 30 days of delivery.", "vec": [3, 2, 0]},
    {"text": "Standard delivery takes 2 to 4 working days.", "vec": [0, 5, 1]},
    {"text": "Reset your password from the sign-in page.", "vec": [0, 0, 5]},
    {"text": "Gift cards cannot be refunded.", "vec": [2, 0, 1]},
]
best = top_k([5, 1, 0], chunks, 2)
print(build_prompt("When will I get my money back?", best))

The printed prompt, sent to a model:

Answer using only the sources below. Cite them like [1]. If they do not contain the answer, say "I don't know." [1] Refunds reach your card 5 to 7 days after we receive the return. [2] You can return items within 30 days of delivery. Question: When will I get my money back? Your refund reaches your card 5 to 7 days after the shop receives your return [1]. You need to send the item back within 30 days of delivery [2].

The "say I don't know" line matters. Without it, when retrieval finds nothing useful, the model falls back on training and gives a confident, generic answer that looks just as grounded.

When RAG is the right tool

  • Use it when the material is too big to send whole, changes often, or is private. Updating the documents updates the answers, with no retraining.
  • Skip it when the material is small. If the whole handbook fits comfortably, send all of it and avoid retrieval mistakes.
  • Do not fine-tune instead for changing facts. Fine-tuning teaches style or format; it is a poor store for facts you will correct next month.

A RAG answer is only as good as what was retrieved. When answers are wrong, check the passages before touching the prompt.

Common mistakes

If the right passage never reached the prompt, no wording will help. Log what was retrieved, and test retrieval alone with questions whose correct passage you know.

Vectors from two embedding models are not comparable, like coordinates on two different maps. If you change models, re-embed every chunk.

Retrieved text can be outdated, wrong, or written to steer the model. Keep stale documents out of the index, and treat passages as material, never as instructions.

Try it yourself

A staff assistant was asked "How many days of parental leave do we get?" It answered "Most companies offer 12 weeks." The retrieved passages were: [1] "Annual leave: 25 days per year, plus public holidays." [2] "Sick leave must be reported to your manager before 10am." Find the two separate failures and say what you would change.

Problem 1: retrieval. Neither passage is about parental leave. Either the policy is not in the index, or it was chunked or embedded badly so a generic "leave" match beat it. Check the store, then search for it directly to see where it ranks.

Problem 2: generation. The model should have said the passages did not answer the question; instead it used general knowledge. Add an instruction such as: "If the sources do not answer the question, reply: I couldn't find this in the staff handbook." Requiring citations also helps, because an answer with no source stands out.

Fixing only the prompt makes it honest but unhelpful. Fixing only retrieval leaves it free to invent answers next time. Fix both.

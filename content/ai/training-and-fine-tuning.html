Imagine a new hire who has read the whole company archive. They know how almost anything works. But on the help desk, they answer a customer's question with three more questions, because in the archive's FAQ lists a question was usually followed by more questions.

That is a language model after its first and biggest stage of training: full of text, not yet an assistant. Getting there takes a different kind of training.

Stage 1: pretraining on raw text

A model outputs chances for the next token (see What Is an LLM). Pretraining teaches it to give good chances, with no human labels:

  1. Take a piece of real text, for example "The cat slept on the mat".
  2. Hide the next token and ask the model for its chances.
  3. Measure how surprised it was by the real next token.
  4. Nudge its numbers so it would be a little less surprised next time.

Every position in every document is a free practice question, so pretraining can use vast amounts of text.

Surprise is measured as the loss: minus the natural log of the chance given to the real token. A chance of 0.9 gives a loss of about 0.11, barely surprised; 0.01 gives about 4.6. Training means making the average loss go down.

Watch one example being learned

A model predicts the last word of "The cat slept on the ___" from three options; the real answer is "mat". Softmax turns raw scores into chances, as in the attention lesson.

The nudge: for every word, subtract rate × (chance − target) from its score, where rate is the learning rate and the target is 1 for the real word, 0 for the others. The further off a chance is, the bigger its nudge. This is gradient descent, as in How Models Learn. Here we nudge three scores directly; a real model nudges the billions of parameters that produced them.

That last step matters most. Training pulls the chances toward what is common across millions of similar texts, so the model mostly ends up with good guesses, not stored documents. The exception is text repeated many times, like famous quotes, which it can memorise word for word.

The code

function softmax(scores) {
  const biggest = Math.max(...scores);
  const exps = scores.map((s) => Math.exp(s - biggest));
  const total = exps.reduce((a, b) => a + b, 0);
  return exps.map((e) => e / total);
}

// One training step on one example. Returns the new scores and the loss.
function trainStep(scores, correct, rate) {
  const chances = softmax(scores);
  const loss = -Math.log(chances[correct]); // surprise at the real word
  const newScores = scores.map((s, i) => {
    const target = i === correct ? 1 : 0;
    return s - rate * (chances[i] - target); // the nudge
  });
  return { newScores, loss };
}

let scores = [0, 1, -1]; // mat, sofa, moon
for (let step = 0; step < 4; step++) {
  const { newScores, loss } = trainStep(scores, 0, 1);
  console.log(loss.toFixed(2)); // 1.41, 0.60, 0.33, 0.22
  scores = newScores;
}

import math

def softmax(scores):
    biggest = max(scores)
    exps = [math.exp(s - biggest) for s in scores]
    total = sum(exps)
    return [e / total for e in exps]

# One training step on one example. Returns the new scores and the loss.
def train_step(scores, correct, rate):
    chances = softmax(scores)
    loss = -math.log(chances[correct])  # surprise at the real word
    new_scores = []
    for i, (s, c) in enumerate(zip(scores, chances)):
        target = 1 if i == correct else 0
        new_scores.append(s - rate * (c - target))  # the nudge
    return new_scores, loss

scores = [0, 1, -1]  # mat, sofa, moon
for step in range(4):
    scores, loss = train_step(scores, 0, 1)
    print(f"{loss:.2f}")  # 1.41, 0.60, 0.33, 0.22

Real pretraining runs this over trillions of tokens, in batches, on large clusters of specialised chips for weeks or months. That cost is why only a few organisations pretrain large models from scratch.

Stages 2 and 3: becoming an assistant

A pretrained, or base, model continues text. Ask it a question and it may continue with what often follows a question on the web.

How do I remove a stripped screw? How do I remove a rusted bolt? How do I fix a wobbly table leg? Browse our full list of 200 home repair questions below, sorted by

Two much smaller stages fix this.

Instruction tuning uses the same next-token method on a small set of carefully written conversations: a request, then a good reply. The model learns that a user turn is followed by a helpful assistant turn. It mainly teaches format and behaviour; knowledge comes from pretraining.

Preference tuning has the model write several answers to one request, which are compared by people, by a model trained on their judgements, or by automatic checks such as code tests. Training makes the preferred kinds of answers more likely. Much of an assistant's tone, caution and step-by-step reasoning comes from here.

Pretraining gives a model its knowledge and language. The smaller fine-tuning stages shape behaviour: answer the question, follow instructions, prefer rewarded kinds of answers.

Companies also fine-tune existing models on their own examples, say to always produce a house format. Same idea, smaller scale.

Common mistakes

A model's parameters are fixed after training. A correction helps for the rest of that conversation, because it is in the text the model reads, and is gone in the next. Whether a provider trains future models on conversations is a policy question; see Privacy and Security.

Fine-tuning is good at changing style, format and behaviour, but unreliable for new facts like your product catalogue: the model may blend them with what it already believed. Put specific, current information in the prompt, often with retrieval.

Pretraining text stops at some date. The model knows nothing later unless the prompt tells it, and may not know its own cut-off.

Try it yourself

For each situation, pick the best first approach: a better prompt, documents in the prompt (retrieval), or fine-tuning. Give a one-line reason.

 1. A support bot must answer questions about this month's pricing. 2. Thousands of daily replies must follow a strict, unusual house format. 3. Summaries of meeting notes come out too long and too formal.
  1. Retrieval. Prices are specific facts that change. Put the current list in the prompt; fine-tuning would bake in stale numbers.
  2. A prompt with examples first, then maybe fine-tuning. A few examples often get the format right. If it still slips at that volume, fine-tuning on many correct replies gives consistent behaviour.
  3. A better prompt. Say the length and tone: "under 100 words, plain and friendly". Training is far more work.

The pattern: prompt first, add information with retrieval, and fine-tune only for behaviour you cannot get reliably any other way.

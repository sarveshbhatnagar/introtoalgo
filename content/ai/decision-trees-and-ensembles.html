A decision tree is a model that makes a prediction by asking a series of yes-or-no questions about the input, where each answer leads to the next question until it reaches a final answer. The questions are learned from labelled examples instead of being written by hand. Trees are easy to read and need little data preparation, and large groups of trees (random forests and boosted trees) are among the most accurate models for tabular data, such as customer records, transactions and sensor readings.

A single tree on its own has a serious weakness. If you let it grow without limits it memorises the training data, and it then performs badly on new data. Ensembles exist to fix that: they train many trees and combine their answers.

How a tree makes a prediction

Each inner node of the tree asks a yes-or-no question about one feature. Each answer leads either to another question or to a leaf, which holds the prediction. To predict, you start at the top, answer the question at each node for the example in front of you, and read the prediction from the leaf you end up in.

The same structure predicts numbers as well as labels. A tree used for regression stores the average target value of the training examples in each leaf, and it scores a split by how far the examples in each group are from their group's average, instead of by counting mistakes.

A tree can express an interaction between features. In this tree, wind only matters on dry days, because the wind question exists on only one branch. The weighted sums in Regression and Classification cannot do this unless you add an interaction feature by hand.

How a tree is learned

Learning a tree means choosing the question at each node. The method is the one from What Is Machine Learning, where we tried every cut-off for one feature and kept the one with the fewest mistakes. A tree does this for every feature, keeps the best question overall, and splits the examples into the group that answers yes and the group that answers no. It then repeats the whole procedure inside each group.

To score a question, each of the two groups predicts its most common label, and the score is the total number of mistakes. The tracer below tries every question on 8 past days, which are sorted by wind speed.

The result is the tree in the figure. Choosing the best question at each step without looking ahead is a greedy strategy. It is fast but not guaranteed to find the best possible tree.

// Mistakes if a group predicts its most common label.
function mistakes(labels) {
  const yes = labels.filter((l) => l === 1).length;
  return Math.min(yes, labels.length - yes);
}

// Try the question "feature >= t" for every feature and value.
function bestSplit(rows, labels) {
  let best = null;
  for (let f = 0; f < rows[0].length; f++) {
    for (const t of new Set(rows.map((r) => r[f]))) {
      const yes = [], no = [];
      rows.forEach((r, i) => (r[f] >= t ? yes : no).push(labels[i]));
      if (no.length === 0) continue; // everyone said yes: no split
      const cost = mistakes(yes) + mistakes(no);
      if (best === null || cost < best.cost) best = { feature: f, t, cost };
    }
  }
  return best;
}

const rows = [[5, 0], [8, 1], [10, 0], [12, 1], [15, 0], [18, 0], [22, 0], [25, 1]];
bestSplit(rows, [1, 0, 1, 0, 1, 1, 0, 0]); // { feature: 1, t: 1, cost: 1 }

def mistakes(labels):
    """Mistakes if a group predicts its most common label."""
    yes = sum(labels)
    return min(yes, len(labels) - yes)

def best_split(rows, labels):
    """Try the question "feature >= t" for every feature and value."""
    best = None
    for f in range(len(rows[0])):
        for t in sorted({r[f] for r in rows}):
            yes = [l for r, l in zip(rows, labels) if r[f] >= t]
            no = [l for r, l in zip(rows, labels) if r[f] < t]
            if not no:
                continue  # everyone said yes: no split
            cost = mistakes(yes) + mistakes(no)
            if best is None or cost < best[2]:
                best = (f, t, cost)
    return best

Real libraries usually score a split with Gini impurity instead of counting mistakes. For a group in which a share p of the examples say yes, the impurity is 1 − p² − (1 − p)². It is 0 for a pure group and largest when the group is split 50/50, so unlike counting mistakes it rewards any split that makes a group purer.

Why a single tree overfits

If you do not stop it, a tree keeps splitting until every leaf is pure, which can mean one leaf for each training example. Such a tree scores 100% on its training data because it has memorised it, including the noise, and it does worse on new data. This is the problem described in Overfitting and Evaluation.

You can limit this by capping the depth of the tree (tuned on a validation set), by requiring a minimum number of examples in each leaf, or by pruning branches that do not improve accuracy on held-out data. A tree is also unstable: changing a handful of training examples can change the first question, and everything below it changes with it. Averaging many trees addresses both problems, and a group of models used together is called an ensemble.

Random forests

A random forest trains many trees, often hundreds, and combines their predictions by majority vote for classification or by averaging for regression. Two kinds of randomness make the trees different from each other. Each tree is trained on a random sample of the training examples, drawn with replacement, and at each split the tree considers only a random subset of the features.

Each tree overfits in its own way, because each saw different examples and was forced to use different features. Their individual mistakes mostly point in different directions, so voting cancels many of them, while the pattern that every tree found remains.

Use a random forest when you want a strong model with very little tuning. The default settings of most libraries work reasonably well, and adding more trees does not make the model overfit more. The cost is size and readability: a forest of hundreds of trees is slow to inspect and larger to store than one tree, and you can no longer read off a simple set of rules.

Gradient boosting

Gradient boosting builds trees one after another instead of independently. The first tree is small and makes a rough prediction. The next tree is trained on the errors that the first one still makes, so it learns what is missing. Each new tree is added to the running total, usually scaled down by a small learning rate so that no single tree changes the prediction too much.

The individual trees are kept shallow, often only a few levels deep, because each one is meant to be a small correction. Boosted trees often reach higher accuracy than random forests on tabular data, but they take more care. Unlike a forest, a boosted model does keep overfitting if you add too many trees, because each new tree fits the remaining errors, which eventually include the noise. You prevent this by watching the error on a validation set and stopping when it stops improving, which is called early stopping, and by using a small learning rate with a limited tree depth.

The two methods differ in how they reduce error. A random forest averages away the variance of deep trees that each overfit, while boosting reduces the bias of shallow trees that each underfit.

Pitfalls

A deep tree or a boosted model with too many rounds can score 100% on the training data and still be poor on new data. Always report the score on data the model did not train on, and use it to choose the depth, the number of trees and the point at which to stop boosting.

A tree predicts a value that it saw in training, so it can never predict above the largest or below the smallest value in its leaves. If prices later rise beyond the training range, a forest keeps predicting roughly the old maximum. A linear model continues the trend. For data with a strong trend, add features that remove it, such as the change from the previous period, or use a different model.

A forest can report how much each feature contributed to its splits, but this shows what the model relied on, not what causes the outcome. It is also biased towards features with many distinct values, such as an ID or a timestamp, which offer many possible cut-offs and so look useful even when they only fit noise. If two features carry the same information, the importance is split between them, and each looks less important than it is.

What this changes in practice

For tabular data, start with a random forest or a gradient-boosted model before you consider a neural network. They work on the raw columns, need no feature scaling, handle a mix of numeric and categorical features, and often give the best result for the least effort. Neural networks tend to be better for images, audio and text.

Begin with a single shallow tree when you need to explain the model to someone, since you can print its rules and check them against what you know about the problem. Move to a forest for a strong baseline with little tuning. Switch to boosting when you need the last bit of accuracy and are willing to tune the learning rate, the depth and the number of rounds on a validation set.

What to practise next

Trees only ask about the features you give them. Neural Networks learn their own intermediate features, layer by layer, which makes them strong on images and text.

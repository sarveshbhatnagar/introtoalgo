Ask an assistant to name your new bakery. Ask again in a fresh chat, same words, and you get a different name. Nothing broke. The model rolled a weighted die, and it landed somewhere else.

The toy generator in What Is an LLM always took the most likely word. Most assistants do not. Here is how they pick, and what temperature and top-p change.

Picking from the chances

Each model call gives every possible next token a raw score. Softmax turns the scores into chances that add up to 1, as in the attention lesson. Then one token is chosen.

Always taking the top token is greedy decoding. It is predictable but gives flat text and can get stuck repeating a phrase. So most systems sample: pick at random, weighted by the chances. A token with chance 0.46 is picked about 46% of the time.

To sample, draw a random number r between 0 and 1, then walk through the tokens adding up their chances. The first token whose running total passes r is the pick. Each token owns a slice of the line from 0 to 1, as wide as its chance.

Temperature: sharpen or flatten

Temperature reshapes the chances before the pick: divide every score by it, then apply softmax.

  • Below 1: gaps grow, the top token gets even more likely. Safer, more predictable text.
  • Exactly 1: the model's chances as they are.
  • Above 1: gaps shrink, unlikely tokens gain share. More varied text, more likely to go wrong.
  • 0: treated as greedy, a special case since you cannot divide by zero.

The code

The random number is passed in as r for testing; in real use, pass Math.random() or random.random().

function chancesAt(scores, temperature) {
  if (temperature === 0) { // greedy: all the chance on the top score
    const top = scores.indexOf(Math.max(...scores));
    return scores.map((_, i) => (i === top ? 1 : 0));
  }
  const scaled = scores.map((s) => s / temperature); // the only change
  const biggest = Math.max(...scaled);
  const exps = scaled.map((s) => Math.exp(s - biggest));
  const total = exps.reduce((a, b) => a + b, 0);
  return exps.map((e) => e / total);
}

// r is a random number in [0, 1).
function sample(chances, r) {
  let running = 0;
  for (let i = 0; i < chances.length; i++) {
    running += chances[i];
    if (r < running) return i;
  }
  return chances.length - 1; // guard against rounding
}

const words = ["apple", "mango", "banana", "kiwi", "durian"];
const chances = chancesAt([2, 1.5, 1, 0, -1], 1);
words[sample(chances, 0.62)]; // "mango"

The cost is tiny next to running the model: O(V) for a vocabulary of V tokens. The top-p filter below adds a sort, O(V log V), still tiny.

Top-p: cut off the long tail

A real vocabulary has tens of thousands of tokens or more. Most have tiny chances, but that "long tail" adds up, and an occasional pick from it can derail a sentence. Top-p (nucleus) sampling cuts the tail off first.

Sort tokens by chance and keep the likeliest until their chances reach at least p. Drop the rest and rescale the kept ones to sum to 1. For the fruit at temperature 1 and p = 0.9: apple 0.46, plus mango 0.74, plus banana 0.91 passes 0.9. Kiwi and durian are dropped; the survivors become about 0.51, 0.31 and 0.19.

function topP(chances, p) {
  const order = chances.map((_, i) => i).sort((a, b) => chances[b] - chances[a]);
  const kept = new Set();
  let running = 0;
  for (const i of order) { // keep the likeliest until they cover p
    kept.add(i);
    running += chances[i];
    if (running >= p) break;
  }
  return chances.map((c, i) => (kept.has(i) ? c / running : 0));
}

def top_p(chances, p):
    order = sorted(range(len(chances)), key=lambda i: -chances[i])
    kept, running = set(), 0.0
    for i in order:  # keep the likeliest until they cover p
        kept.add(i)
        running += chances[i]
        if running >= p:
            break
    return [c / running if i in kept else 0.0 for i, c in enumerate(chances)]

Top-k keeps a fixed number, say the top 40. Top-p adapts: one or two tokens when the model is sure, more when many continuations are reasonable. Systems often combine temperature with one of these.

The model gives chances; sampling turns them into a choice. Temperature reshapes the chances without changing their order, and top-p or top-k removes the unlikely tail before the pick.

Choosing settings

  • Low for one right answer: extracting fields, classifying a ticket, code to a spec.
  • Moderate for open-ended writing and brainstorming, where several good answers are worth seeing.
  • Very high rarely helps: past a point, the extra variety is mostly mistakes.

Many apps set these for you. Where you can, check the documentation: ranges and defaults differ between providers, so the same number does not mean the same thing everywhere.

Common mistakes

Greedy decoding removes the dice roll, so outputs are usually the same. But tiny numerical differences on the server can flip a near-tie between two tokens, and the text diverges from there. Do not depend on exact repeatability.

Temperature adds no knowledge or skill; it only makes less likely tokens more likely. For varied ideas, ask directly ("give 10 options that differ in style") and keep temperature moderate.

If the top choice is wrong, greedy decoding picks it every time. Low temperature reduces random slips; it cannot fix what the model does not know. Why Models Hallucinate covers what helps.

Try it yourself

For each task, choose low temperature (near 0) or moderate (around 0.7 to 1), with a one-line reason.

 1. Pull the invoice number, date and total out of 5,000 scanned invoices. 2. Suggest 20 names for a new board game. 3. Turn a bug report into a structured JSON object. 4. Write three different openings for a short story.
  1. Low. One right answer per invoice; randomness can only add errors.
  2. Moderate. You want variety. Near 0, many names would be variations of the most likely one.
  3. Low. A strict format; an unlikely token can break the JSON.
  4. Moderate. "Different" is the point. Run it several times too: sampling gives new options for free.

Rule of thumb: one correct output, go low. Options to choose from, go moderate and generate several.

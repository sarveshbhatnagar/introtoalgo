Type "See you" on your phone and the keyboard suggests "soon", "later", "tomorrow". Keep tapping the first suggestion and you get a sentence, usually a strange one.

A large language model, or LLM, works the same way: it reads the text so far and predicts what comes next. The difference is scale. It learned from an enormous amount of writing, and it reads everything you wrote, not just the last word. That is enough to draft an email, explain a bug or summarise a report.

One job: predict what comes next

Give a model some text and it returns a list of chances: for every piece of text it knows, how likely it is to come next. For "The capital of France is", "Paris" gets a very high chance and "a" a small one ("is a city of...").

To write more, run a loop:

  1. Give the model the text so far.
  2. Get the chances for the next piece.
  3. Pick one piece.
  4. Stick it on the end of the text, and go back to step 1.

Stop when the model picks a special "end" piece or the text hits a length limit. An assistant's long replies are built this way, one piece at a time.

The pieces are called tokens. They are often whole words, but not always; Tokens shows how text is cut up. For now, think of them as words.

Watch the loop by hand

This toy model is a small table mapping the last two words to chances for the next. A real model is not a table and reads the whole text, but the loop is the same. This version always takes the most likely word, called greedy picking.

The loop in code

The dictionary plays the model; the rest is the loop you just traced.

// A stand-in for the model: last two words -> chances for the next word.
const nextWord = {
  "the cat": { sat: 0.6, ran: 0.3, is: 0.1 },
  "cat sat": { on: 0.7, down: 0.2, still: 0.1 },
  "sat on": { the: 0.8, a: 0.15, my: 0.05 },
  "on the": { mat: 0.5, sofa: 0.3, roof: 0.2 },
  "the mat": { ".": 0.6, and: 0.3, today: 0.1 },
};

function generate(words, maxWords) {
  const text = [...words];
  while (text.length < maxWords) {
    const options = nextWord[text.slice(-2).join(" ")];
    if (!options) break; // the toy model has nothing to say
    let best = null; // greedy: take the most likely word
    for (const [word, p] of Object.entries(options)) {
      if (best === null || p > options[best]) best = word;
    }
    text.push(best);
    if (best === ".") break;
  }
  return text.join(" ");
}

generate(["the", "cat"], 20); // "the cat sat on the mat ."

# A stand-in for the model: last two words -> chances for the next word.
NEXT_WORD = {
    "the cat": {"sat": 0.6, "ran": 0.3, "is": 0.1},
    "cat sat": {"on": 0.7, "down": 0.2, "still": 0.1},
    "sat on": {"the": 0.8, "a": 0.15, "my": 0.05},
    "on the": {"mat": 0.5, "sofa": 0.3, "roof": 0.2},
    "the mat": {".": 0.6, "and": 0.3, "today": 0.1},
}

def generate(words, max_words):
    text = list(words)
    while len(text) < max_words:
        options = NEXT_WORD.get(" ".join(text[-2:]))
        if options is None:
            break  # the toy model has nothing to say
        best = max(options, key=options.get)  # greedy: most likely word
        text.append(best)
        if best == ".":
            break
    return " ".join(text)

generate(["the", "cat"], 20)  # "the cat sat on the mat ."

n new words take n calls, one after another, since each needs the word before it. That is why replies appear gradually.

What "large" changes

A real LLM replaces the five-row table with a neural network: billions of numbers, called parameters, that turn the text so far into chances for the next token. Attention and Transformers shows the design that lets every word take every other word into account.

The numbers are set during training: show the network huge amounts of text and nudge them so the real next token gets a higher chance each time (Training and Fine-Tuning).

At that scale, something surprising happens. Predicting a physics textbook, a recipe or a Python file well requires absorbing a lot about physics, cooking and Python. Nobody programs those skills in; they are a side effect of good prediction.

An LLM is a next-token predictor. Every ability it shows comes out of a loop that adds one likely piece of text at a time.

A chat is a document being continued

In a chat, the app joins your messages, the earlier replies and some hidden instructions into one long text, with markers showing who said what. The model continues that text with the assistant's next turn.

You are a helpful assistant. Answer briefly. What is the boiling point of water at sea level? 100°C, or 212°F.

The model does not remember earlier messages between calls. The app sends the whole conversation every time, and if a message falls out of that text, the model no longer knows it was said. What Is Context builds on this.

Common mistakes

A plain LLM has no database. A stated fact is the most plausible next text: often correct, because the fact appeared many times in training, sometimes a confident guess (Why Models Hallucinate). Apps that add search are a separate system feeding text in.

The output is committed one token at a time and never revised. A model's internal state can anticipate words further ahead, but it cannot change what it already wrote, so a bad start tends to stay. That is one reason to let the model work through a problem before its final answer; see Give the Model Room to Think.

Smooth sentences are what the model is best at, and they say nothing about whether the content is right. Check the answer.

Try it yourself

For each sentence start, write the three most likely next words with rough chances (leave some room for everything else). Which is hardest to predict, and why?

 1. "Thank you so ..." 2. "The meeting has been moved to ..." 3. "My favourite colour is ..."
  1. "much" 0.85, "very" 0.05, "kindly" 0.02. Almost certain: the phrase is extremely common.
  2. "Monday" 0.15, "Thursday" 0.15, "next" 0.15, the rest over other days, dates and "the". The kind of word is clear (a time), the exact word is not.
  3. "blue" 0.3, "green" 0.15, "red" 0.1. Many answers fit, and the text gives no clue.

A model is confident when the text pins the answer down, and spreads its chances when it does not. In case 2 the true answer is a fact about your meeting that is nowhere in the text. A model has to guess, and it will write "Thursday" just as smoothly as "much".

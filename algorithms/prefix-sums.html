Prefix Sums

Precompute running totals once, then get the sum of any range with one subtraction. Plus the prefix-sum and hash map trick for counting runs.

A small café records its takings each day: 5, 2, 6, 3, 1, 4. The owner keeps asking questions. How much from day 3 to day 5? From day 1 to day 4? Day 2 to day 6? Each answer means adding up a stretch of numbers again, and the list of days grows every week.

A car's odometer has the answer. To know how far you drove between two towns, you do not add up every metre of road. You read the odometer at each town and subtract. Keep a running total of the takings, and every "how much between here and there?" becomes one subtraction.

#The idea: running totals, then subtract

Build a second array, prefix, where prefix[i] is the sum of the first i items. It starts with prefix[0] = 0, the sum of no items at all, so it is one longer than the input.

Number the days from 0, as an array does, so days 3 to 5 are items 2 to 4. The sum of items from index l to index r, both included, is everything up to r minus everything before l:

sum(l..r) = prefix[r + 1] − prefix[l]

function buildPrefix(nums) {
  const prefix = [0];
  for (let i = 0; i < nums.length; i++) {
    prefix.push(prefix[i] + nums[i]);
  }
  return prefix;
}
 
// Sum of nums[l..r], both ends included.
function rangeSum(prefix, l, r) {
  return prefix[r + 1] - prefix[l];
}
 
const prefix = buildPrefix([5, 2, 6, 3, 1, 4]); // [0, 5, 7, 13, 16, 17, 21]
rangeSum(prefix, 2, 4); // 10
def build_prefix(nums):
    prefix = [0]
    for i in range(len(nums)):
        prefix.append(prefix[i] + nums[i])
    return prefix
 
# Sum of nums[l..r], both ends included.
def range_sum(prefix, l, r):
    return prefix[r + 1] - prefix[l]
 
prefix = build_prefix([5, 2, 6, 3, 1, 4])  # [0, 5, 7, 13, 16, 17, 21]
range_sum(prefix, 2, 4)  # 10
Key idea

Pay O(n) once to build running totals, and the sum of any range becomes one subtraction: prefix[r + 1] − prefix[l].

#Counting runs with a given total

Prefix sums get stronger next to a hash map. Take a list of daily profits and losses, [2, −1, 3, −2, 2], and ask: how many runs of days in a row add up to exactly 2?

Checking every run is O(n²). A sliding window cannot help, because the losses are negative. But the formula above says a run ending here sums to 2 exactly when an earlier running total equals current running total − 2. So walk once, keep the running total, and keep a map of how many times each running total has appeared. At each day, look up how many earlier totals would make a run of 2.

function countRunsWithSum(nums, k) {
  const seen = new Map([[0, 1]]); // the empty start
  let running = 0;
  let count = 0;
  for (const x of nums) {
    running += x;
    count += seen.get(running - k) ?? 0;
    seen.set(running, (seen.get(running) ?? 0) + 1);
  }
  return count;
}
 
countRunsWithSum([2, -1, 3, -2, 2], 2); // 5
def count_runs_with_sum(nums, k):
    seen = {0: 1}  # the empty start
    running = 0
    count = 0
    for x in nums:
        running += x
        count += seen.get(running - k, 0)
        seen[running] = seen.get(running, 0) + 1
    return count
 
count_runs_with_sum([2, -1, 3, -2, 2], 2)  # 5

#Common mistakes

Off by one in the formula

The prefix array is one longer than the input, so the indexes shift by one. The sum of l..r is prefix[r + 1] − prefix[l], not prefix[r] − prefix[l], which leaves out item r. Test with a range of one item: prefix[l + 1] − prefix[l] must equal nums[l].

Forgetting the starting 0

Without seen = {0: 1}, runs that start at the very first item are never counted, because no earlier running total exists for them. In the example you would get 3 instead of 5.

Changing the data after building

If one value in nums changes, every running total after it is now wrong, and fixing them is O(n). Prefix sums suit data that is read many times and changed rarely. For frequent updates, see Segment and Fenwick Trees.

Tip

The same trick works on a grid. Store, for every cell, the total of the rectangle from the top-left corner to that cell. Any rectangle's sum then takes four lookups.

In the real world

Analytics dashboards that answer "revenue between any two dates" instantly often store cumulative totals per day, then subtract, instead of adding up raw rows on every request.

#Check yourself

Quick check

With prefix = [0, 5, 7, 13, 16, 17, 21], what is the sum of items 1 to 3?

  1. Right. prefix[4] − prefix[1] = 16 − 5 = 11. Check: 2 + 6 + 3 = 11.
  2. Not quite. That is prefix[3] − prefix[1], which leaves out item 3. Use r + 1.
  3. Not quite. That is prefix[4] alone: items 0 to 3. Subtract the items before index 1.

An array has 100,000 numbers and you must answer 10,000 range-sum questions. Roughly how much work does each approach take?

  1. Not quite. Adding each range from scratch can cost up to 100,000 steps per question, 10,000 times.
  2. Right. 10,000 × 100,000 = 1,000,000,000 in the worst case, against 100,000 to build plus 10,000 subtractions.
  3. Not quite. Building is one pass, paid once. After that each question is O(1).

Why does counting runs with total k use prefix sums and a map instead of a sliding window?

  1. Right. With negatives, shrinking a window can raise the sum, so the window cannot decide when to move. The prefix-sum identity works for any numbers.
  2. Not quite. A sliding window is O(n). The problem is that it gives wrong answers here, not that it is slow.
  3. Not quite. A window uses less memory when it applies. Use the map when the window's logic breaks.

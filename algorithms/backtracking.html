Backtracking

Build answers one choice at a time, undo the choice, and try the next. One choose, explore, un-choose template for subsets, permutations and puzzles.

A sandwich shop lets you add any mix of three extras: cheese, egg and tomato. You want to list every sandwich you could order, from plain bread to all three. With three extras you can do it in your head. With twelve there are 4,096, and you need a method that never misses one and never writes one twice.

A careful person does it like this. Add an extra. List everything you can still add on top. When you run out, take that extra back off and try a different one. That "add it, go deeper, take it back" rhythm is backtracking.

#The idea: choose, explore, un-choose

Backtracking builds an answer one decision at a time. You keep a single path: the choices made so far. At every point you do three things for each option still available:

  1. Choose: add the option to the path.
  2. Explore: call yourself recursively to make the remaining decisions.
  3. Un-choose: remove the option, so the path is exactly what it was before, ready for the next option.

Each call is one decision point, and the call stack remembers where you were, as in Recursion. Un-choosing lets every branch share one path.

Key idea

Every backtracking solution is the same loop: for each option, choose it, explore, un-choose it. What changes between problems is only what counts as an option, when to record an answer, and which options to skip.

The calls form a tree. Each node is a path and each edge adds one extra. A call only offers extras after the last one chosen, so "egg then cheese" never shows up as a copy of "cheese then egg".

#Subsets, traced

Write cheese, egg and tomato as C, E and T. Watch the path grow and shrink. It holds one sandwich at a time; the recorded list collects copies.

Look at step 8. After popping T, the path is CE again. Every call leaves the path as it found it, so the caller's loop can carry on as if nothing happened.

All subsets
function subsets(items) {
  const result = [];
  const path = [];
  function explore(start) {
    result.push([...path]); // record a copy, not path itself
    for (let i = start; i < items.length; i++) {
      path.push(items[i]);  // choose
      explore(i + 1);       // explore
      path.pop();           // un-choose
    }
  }
  explore(0);
  return result;
}
 
subsets(["C", "E", "T"]);
// [[], ["C"], ["C","E"], ["C","E","T"], ["C","T"], ["E"], ["E","T"], ["T"]]

#Permutations: same template, different options

Now three friends, Ana, Ben and Cy, need a speaking order. Order matters here. Two things change:

  • The options are everyone not used yet, tracked in a used list.
  • You record only when the path is full. Half an order is not an answer.

By hand: Ana, Ben, Cy is the first full path. Un-choose Cy and Ben, put Cy second, and you get Ana, Cy, Ben. Then Ben goes first, then Cy.

All orderings
function permutations(items) {
  const result = [];
  const path = [];
  const used = new Array(items.length).fill(false);
  function explore() {
    if (path.length === items.length) {
      result.push([...path]);
      return;
    }
    for (let i = 0; i < items.length; i++) {
      if (used[i]) continue;
      used[i] = true;     // choose
      path.push(items[i]);
      explore();          // explore
      path.pop();         // un-choose
      used[i] = false;
    }
  }
  explore();
  return result;
}
 
permutations(["Ana", "Ben", "Cy"]).length; // 6
def permutations(items):
    result = []
    path = []
    used = [False] * len(items)
 
    def explore():
        if len(path) == len(items):
            result.append(path[:])
            return
        for i in range(len(items)):
            if used[i]:
                continue
            used[i] = True          # choose
            path.append(items[i])
            explore()               # explore
            path.pop()              # un-choose
            used[i] = False
 
    explore()
    return result
 
len(permutations(["Ana", "Ben", "Cy"]))  # 6

Choosing now makes two updates, so un-choosing undoes both. Three choices for first place, two for second, one for third: 3 × 2 × 1 = 6 orders.

#A puzzle: prune early

Backtracking pays off most when some choices break a rule. Place 4 queens on a 4 × 4 board so that no two share a row, column or diagonal. Put one queen per row, so each call picks the column for one row.

The new ingredient is the prune: skip any square that is already attacked. A bad partial board is dropped the moment it goes wrong, along with every board that would have grown from it.

To check a square in O(1), keep three sets: used columns, used row - col values (down-right diagonals) and used row + col values (down-left diagonals). Squares (0, 0) and (1, 1) both have row - col = 0, which is why step 2 skipped (1, 1).

Place n queens
function solveQueens(n) {
  const cols = new Set(), down = new Set(), up = new Set();
  const placed = []; // placed[row] = column of that row's queen
  const solutions = [];
  function explore(row) {
    if (row === n) { solutions.push([...placed]); return; }
    for (let col = 0; col < n; col++) {
      // prune: column or diagonal already taken
      if (cols.has(col) || down.has(row - col) || up.has(row + col)) continue;
      // choose
      cols.add(col); down.add(row - col); up.add(row + col);
      placed.push(col);
      explore(row + 1); // explore
      // un-choose
      cols.delete(col); down.delete(row - col); up.delete(row + col);
      placed.pop();
    }
  }
  explore(0);
  return solutions;
}
 
solveQueens(4); // [[1, 3, 0, 2], [2, 0, 3, 1]]
def solve_queens(n):
    cols, down, up = set(), set(), set()
    placed = []  # placed[row] = column of that row's queen
    solutions = []
 
    def explore(row):
        if row == n:
            solutions.append(placed[:])
            return
        for col in range(n):
            if col in cols or row - col in down or row + col in up:
                continue  # prune
            cols.add(col)  # choose
            down.add(row - col)
            up.add(row + col)
            placed.append(col)
            explore(row + 1)  # explore
            cols.remove(col)  # un-choose
            down.remove(row - col)
            up.remove(row + col)
            placed.pop()
 
    explore(0)
    return solutions
 
solve_queens(4)  # [[1, 3, 0, 2], [2, 0, 3, 1]]

#How much does it cost

Backtracking visits every node of its call tree, so count the nodes. Subsets have 2ⁿ, because each item is in or out. Orderings have n! leaves. Copying each answer costs O(n). These numbers explode: 2²⁰ is about a million and 12! is about 479 million. Backtracking is for small inputs, or for problems where pruning cuts most of the tree away.

ApproachTimeSpaceWhy
All subsetsO(n · 2ⁿ)O(n)2ⁿ subsets, each copied in O(n). The path and the call stack are at most n deep, not counting the output.
All orderingsO(n · n!)O(n)n! full paths, each copied in O(n).
n queensO(n!) at mostO(n)At most n choices for row 0, n − 1 for row 1, and so on. Pruning cuts far below that in practice.

#Common mistakes

Recording the path instead of a copy

result.push(path) stores a reference to the one shared list. By the end every un-choose has emptied it, so the result is eight empty lists. Always store a copy: [...path] in JavaScript, path[:] in Python.

Forgetting to undo everything you did

If choosing touches several things, such as used[i] and path, or the three sets in the queens code, un-choosing must undo all of them. Miss one and a queen that is gone still blocks its column, so real answers go missing.

Checking the rules only at the end

Building full boards and testing them afterwards is plain brute force. Check each choice as you make it.

#Check yourself

Quick check

In the subsets code, what goes wrong if the loop starts at 0 instead of start?

  1. Not quite. Starting at 0 offers items that were already chosen, so the path never stops growing.
  2. Right. Right. Each call offers every item again, so the path keeps growing until the program runs out of stack. Even with a check against repeats, CE and EC would both be recorded.
  3. Not quite. Nothing is missed. The trouble is that the search never ends.

A permutation search on 5 items records an answer only when the path is full. How many answers does it record?

  1. Not quite. That is 5 × 5, as if people could be reused.
  2. Not quite. That is 2⁵, the number of subsets. Orderings are counted differently.
  3. Right. 5 × 4 × 3 × 2 × 1 = 120. Each position has one fewer person left to choose from.

Why does backtracking un-choose after the recursive call returns?

  1. Not quite. Undoing is about correctness, not memory.
  2. Right. Yes. The loop is about to try another option at the same decision point, and it must start from the same state.
  3. Not quite. Plain recursion does not undo anything. Backtracking needs it because branches share one path.

#What to practise next

Backtracking tries every option. When you can prove one option is always best, you can skip the rest: that is Greedy Algorithms. When the same smaller question gets asked again and again inside the search, dynamic programming stores the answers instead.

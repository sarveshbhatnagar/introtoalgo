Bellman-Ford and Floyd-Warshall

Find cheapest routes when some costs are negative, catch negative cycles, and build a table of costs between every pair of places, in JS and Python.

A courier drives one-way legs between four depots: S, A, B and C. Each leg costs fuel. One leg is different: whoever drives from B to A carries a paid parcel, and the pay is 4 more than the fuel. So that leg's cost is −4. The courier starts at S and wants the cheapest way to reach each depot.

Try Dijkstra's rule, "settle the closest place first". S→A costs 1 and S→B costs 2, so A is settled first, at 1, and C gets 1 + 3 = 4. Next B reveals S→B→A, which costs 2 − 4 = −2. But A was already "final", so C ends at 4 when it should be 1. With a negative cost, a place that looks far away can lead somewhere cheaper, so settling the closest first is no longer safe.

The heap code in the Dijkstra lesson never marks a place as settled, so here it would push A again and patch C. On other graphs that patching can snowball into an exponential amount of work, and a negative loop makes it run forever.

#Bellman-Ford: relax every edge, every round

Bellman-Ford gives up on choosing a clever order. Each round, it relaxes every edge, in any fixed order: if dist[u] + cost beats dist[v], lower dist[v]. Then it does that again.

Here is why that is enough. After round 1, every cheapest route of one edge is counted. A cheapest route of 2 edges is a 1-edge route plus one more edge, and round 2 relaxes that edge. So after round k, every cheapest route with up to k edges is counted. Without a loop of negative total cost, a cheapest route never visits a place twice, so it has at most V − 1 edges. V − 1 rounds always finish the job.

Edge order affects speed, not correctness. This order was unlucky: the news about A took a full round to reach C. The code stops early when a round changes nothing.

// edges: list of [from, to, cost], one-way. nodes: list of names.
function bellmanFord(nodes, edges, start) {
  const dist = {};
  for (const node of nodes) dist[node] = Infinity;
  dist[start] = 0;
  for (let round = 1; round < nodes.length; round++) { // V - 1 rounds
    let changed = false;
    for (const [u, v, cost] of edges) {
      if (dist[u] + cost < dist[v]) {
        dist[v] = dist[u] + cost;
        changed = true;
      }
    }
    if (!changed) break; // nothing moved: every distance is final
  }
  for (const [u, v, cost] of edges) {
    if (dist[u] + cost < dist[v]) return null; // still improving: negative cycle
  }
  return dist;
}
// bellmanFord(["S", "A", "B", "C"], edges, "S") → { S: 0, A: -2, B: 2, C: 1 }

                changed = True
        if not changed:

    return dist

#Negative cycles

Suppose a new leg C→B appears with cost −2. Now B→A→C→B costs −4 + 3 − 2 = −3. Every lap of that loop makes the courier 3 richer, so there is no cheapest route any more. One more lap is always cheaper.

Bellman-Ford catches this. Without a negative cycle, everything is final after V − 1 rounds. So the code makes one extra pass: if any edge can still lower a distance, a negative loop is to blame, and the function returns null instead of wrong numbers.

In the real world

Currency traders hunt negative cycles. Make each exchange rate r a cost of −log(r), and a loop of trades that ends with more money becomes a negative cycle.

#Floyd-Warshall: every pair at once

Now the dispatcher wants the cheapest cost from every depot to every other. You could run Bellman-Ford from each one. Floyd-Warshall does it with three short loops and one table.

The idea is to allow stopovers one depot at a time. Start with a table of direct legs. Then allow S as a stopover: for every pair i, j, check whether i → S → j is cheaper. Then add A, then B, then C. When you allow depot k, the best route from i to j either avoids k, so the table already has it, or goes through k once: the best i → k plus the best k → j, both already in the table.

// Places are numbered 0..n-1. edges: list of [from, to, cost], one-way.
function floydWarshall(n, edges) {
  const dist = Array.from({ length: n }, (_, i) =>
    Array.from({ length: n }, (_, j) => (i === j ? 0 : Infinity)));
  for (const [u, v, cost] of edges) dist[u][v] = Math.min(dist[u][v], cost);
  for (let k = 0; k < n; k++) {       // allow k as a stopover
    for (let i = 0; i < n; i++) {
      for (let j = 0; j < n; j++) {
        if (dist[i][k] + dist[k][j] < dist[i][j]) {
          dist[i][j] = dist[i][k] + dist[k][j];
        }
      }
    }
  }
  return dist; // a negative dist[i][i] means i is on a negative cycle
}
import math
 
# Places are numbered 0..n-1. edges: list of (from, to, cost), one-way.
def floyd_warshall(n, edges):
    dist = [[0 if i == j else math.inf for j in range(n)] for i in range(n)]
    for u, v, cost in edges:
        dist[u][v] = min(dist[u][v], cost)
    for k in range(n):          # allow k as a stopover
        for i in range(n):
            for j in range(n):
                if dist[i][k] + dist[k][j] < dist[i][j]:
                    dist[i][j] = dist[i][k] + dist[k][j]
    return dist  # a negative dist[i][i] means i is on a negative cycle

Negative cycles show up for free: a loop from i back to i with a negative total puts a negative number on the diagonal.

#Which one to use

ApproachTimeSpaceWhy
BFSO(V + E)O(V)One start, every edge costs the same.
DijkstraO((V + E) log V)O(V + E)One start, no negative costs.
Bellman-FordO(V × E)O(V)One start, negative costs allowed. Up to V − 1 rounds, each touching every edge. Detects negative cycles.
Floyd-WarshallO(V³)O(V²)Every pair. Three nested loops over the places. Fine up to a few hundred places.

#Common mistakes

Putting the k loop inside

In Floyd-Warshall, k must be the outer loop. The method is "finish all routes with stopovers up to k, then allow the next". With k inside, entries are read before the routes they depend on are done, and answers come out too high.

A big number instead of infinity

Some code uses 1e9 to mean "no route". Then 1e9 + (−4) is smaller than 1e9, and an unreachable place suddenly looks reachable. Use real infinity, as above, or skip any edge whose start is still unreached.

Negative costs on two-way roads

An undirected edge with cost −4 is two one-way edges, both −4. There and back is a loop of −8: a negative cycle. Negative costs only make sense on directed graphs.

#Check yourself

Quick check

A graph has 6 places. What is the largest number of rounds Bellman-Ford needs before the distances are final, if there is no negative cycle?

  1. Right. A cheapest route never repeats a place, so it has at most 6 − 1 = 5 edges, and each round extends the correct routes by one edge.
  2. Not quite. The sixth pass is only the check for negative cycles. Real distances are done after 5.
  3. Not quite. The costs change which route wins, not how many edges a cheapest route can have.

After V − 1 rounds, Bellman-Ford's check pass finds that an edge can still lower a distance. What does that mean?

  1. Not quite. V − 1 rounds always suffice when cheapest routes exist. Further improvement means they do not.
  2. Right. Only a negative cycle can keep making routes cheaper forever.
  3. Not quite. Negative edges are fine, as the courier map shows. Only a negative loop breaks things.

You need the cheapest cost between every pair among 200 warehouses, and all costs are positive. Which fits best?

  1. Right. 200³ is 8 million steps: quick, with tiny code. Running Dijkstra 200 times also works, and can win on sparse graphs.
  2. Not quite. One run gives the costs from a single start, not every pair.
  3. Not quite. BFS ignores costs. It finds the fewest legs, not the cheapest route.

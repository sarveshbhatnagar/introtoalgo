Tries

Store words letter by letter in a tree so shared prefixes are kept once. Look up and autocomplete in time set by word length, not word count.

You type su into a search box and suggestions appear: sun, sum, summer. The app checks thousands of words on every keystroke, and scanning the whole list gets slower as it grows.

If the words were filed so everything starting with su sat in one place, suggestions would be two steps away: go to s, then u, and read off what is there. That filing system is a trie.

#The idea: one letter per step

A trie (usually pronounced "try", from retrieval) is a tree where each edge is a letter, so the path from the root to any node spells a prefix. Words that share a beginning share a path: su is stored once, however many words start with it.

Each node holds:

  • children: a map from each letter that can follow this prefix to the next node;
  • isWord: whether a whole word ends here.

The flag matters because a word can be a prefix of another. so and sort both pass through the so node; only the flag says so is a word and sor is not.

#Building and searching a trie

To insert a word, start at the root and take one letter at a time: step into that child, creating it if missing. After the last letter, set the flag.

To search, walk the same way. If a letter has no child, stop: nothing stored starts with that prefix. Otherwise you end on the prefix's node. "Is this a word?" checks its flag. "Does any word start with this?" only needs the node. Autocomplete collects every flagged node below it.

Five inserts, then three questions. Each circle shows the letter on the edge into it. Green nodes have the flag set, with their word written below.

#The code

A map of children works for any alphabet, including capital letters, digits and accented characters.

class TrieNode {
  constructor() {
    this.children = new Map(); // letter -> TrieNode
    this.isWord = false;       // does a word end here?
  }
}
 
class Trie {
  constructor() { this.root = new TrieNode(); }
 
  insert(word) {
    let node = this.root;
    for (const ch of word) {
      if (!node.children.has(ch)) node.children.set(ch, new TrieNode());
      node = node.children.get(ch);
    }
    node.isWord = true; // mark the end of the word
  }
 
  // Follow prefix letter by letter. null if the path breaks.
  find(prefix) {
    let node = this.root;
    for (const ch of prefix) {
      node = node.children.get(ch);
      if (node === undefined) return null;
    }
    return node;
  }
 
  has(word) {
    const node = this.find(word);
    return node !== null && node.isWord;
  }
 
  startsWith(prefix) { return this.find(prefix) !== null; }
}
class TrieNode:
    def __init__(self):
        self.children = {}    # letter -> TrieNode
        self.is_word = False  # does a word end here?
 
class Trie:
    def __init__(self):
        self.root = TrieNode()
 
    def insert(self, word):
        node = self.root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.is_word = True  # mark the end of the word
 
    # Follow prefix letter by letter. None if the path breaks.
    def find(self, prefix):
        node = self.root
        for ch in prefix:
            node = node.children.get(ch)
            if node is None:
                return None
        return node
 
    def has(self, word):
        node = self.find(word)
        return node is not None and node.is_word
 
    def starts_with(self, prefix):
        return self.find(prefix) is not None

Autocomplete is find plus a preorder traversal of the subtree, building each word on the way down:

// Every stored word that begins with prefix.
function complete(trie, prefix) {
  const out = [];
  const start = trie.find(prefix);
  if (start === null) return out;
  const walk = (node, word) => {
    if (node.isWord) out.push(word);
    for (const [ch, child] of node.children) walk(child, word + ch);
  };
  walk(start, prefix);
  return out;
}
 
const trie = new Trie();
for (const w of ["so", "sort", "sun", "sum", "sky"]) trie.insert(w);
complete(trie, "su"); // ["sun", "sum"]
trie.has("sor");      // false
trie.startsWith("sor"); // true
# Every stored word that begins with prefix.
def complete(trie, prefix):
    out = []
    start = trie.find(prefix)
    if start is None:
        return out
 
    def walk(node, word):
        if node.is_word:
            out.append(word)
        for ch, child in node.children.items():
            walk(child, word + ch)
 
    walk(start, prefix)
    return out
 
trie = Trie()
for w in ["so", "sort", "sun", "sum", "sky"]:
    trie.insert(w)
complete(trie, "su")      # ['sun', 'sum']
trie.has("sor")           # False
trie.starts_with("sor")   # True

#Cost

Every operation walks one node per letter. For a word of length L, insert, has and startsWith take O(L) steps, whether the trie holds 5 words or 5 million. Autocomplete adds the size of the subtree it reads.

Memory is at most one node per letter inserted, less with shared prefixes. But each node carries a map, so a trie usually uses more memory than a plain list of the same words.

ApproachTimeSpaceWhy
Hash set of wordsO(L) lookupO(total letters)Great for "is this a word?". A prefix question has to check every word: O(n · L).
TrieO(L) per operationO(total letters)One node per letter. Autocomplete adds the size of the answer.

If you only ask "is this exact word stored?", a hash set is simpler and smaller. Reach for a trie when the questions are about prefixes. If the word list never changes, a sorted array with binary search can also find the range of words with a prefix.

#Common mistakes

Forgetting the end-of-word flag

Without isWord, every prefix looks like a word: after inserting sort, has("sor") says yes. Set the flag in insert and check it in has.

Mixing up has and startsWith

has("sor") is false; startsWith("sor") is true. "Can this still become a word?" wants startsWith: that is how word-search solvers drop a dead path early.

A fixed array of 26 children everywhere

An array of 26 slots per node is fast, but most slots sit empty, and it breaks on capitals, digits or accents. Use a map unless the alphabet is small and fixed.

In the real world

Search boxes, phone keyboards and spell checkers use tries or compressed versions of them. Routers, including the Linux kernel, keep routing tables in a trie over IP address bits to find a packet's longest matching prefix quickly.

#Check yourself

Quick check

The trie holds so, sort, sun, sum and sky. How many new nodes does inserting sold create?

  1. Not quite. s and o already exist, so you walk down them.
  2. Right. Walk s and o, then create l and d, and set the flag on d.
  3. Not quite. Only so is shared. Neither l nor d exists yet.

In the same trie, what does has("su") return?

  1. Not quite. The path only means some word starts with su. That is startsWith.
  2. Right. No word ends at su. Its flag is still false.
  3. Not quite. The walk succeeds; it just ends on a node without the flag.

A trie holds 1 million words. How many steps does has("summer") take, roughly?

  1. Right. One step per letter. The number of stored words does not matter.
  2. Not quite. That is log₂ of a million, binary search over a sorted list.
  3. Not quite. That is scanning a list. A trie never looks at words outside the prefix.

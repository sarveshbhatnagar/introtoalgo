Segment Trees and Fenwick Trees

How segment trees and Fenwick trees answer range queries on changing data in O(log n), when to use each, and what interviewers ask about them.

A segment tree and a Fenwick tree (also called a binary indexed tree) answer range queries, such as the sum of the values from index 2 to index 6, while the values are still being changed. Both handle a query and an update in O(log n) time. You reach for one when a problem mixes many range queries with many updates, and a plain array or a prefix sum array makes one of the two operations too slow.

A prefix sum array answers a range sum in O(1), but changing one value changes every later total, which costs O(n). A plain array has the opposite problem, because an update is O(1) and a range sum is O(n). With a million queries and a million updates either choice is too slow, and these two structures bring each operation down to about 20 steps.

#How a segment tree works

A segment tree is a binary tree in which each node stores the sum of a range of the array. The root covers the whole array, each child covers one half of its parent's range, and the leaves cover single values. A query can then be answered by adding a few stored blocks, and an update only has to fix the nodes on the path from one leaf to the root.

The tree is stored in an array in the same way as a heap, so node i has children 2i + 1 and 2i + 2. For the values 5, 2, 6, 3, 1, 4, 7, 2, node 0 covers indexes 0 to 7 (sum 30), node 1 covers 0 to 3 (sum 16), node 2 covers 4 to 7 (sum 14), and the leaves are nodes 7 to 14.

#Querying a range

To sum indexes 2 to 6, start at the root and compare each node's range with the query range. If the node's range does not overlap the query at all, the node contributes 0 and its children are not visited. If the node's range lies completely inside the query, the node contributes its stored sum and its children are not visited. If the two ranges overlap only partly, the node asks both of its children and adds their answers.

A query is O(log n) because at each level at most two nodes overlap the query partly, namely the ones that hold the two edges of the range. Every other node on that level is either completely inside or completely outside the query, and those stop at once.

#Updating a value

To change one value, replace the leaf and then recompute each ancestor from its two children, walking up to the root. In this example, the value at index 2 was recorded as 6 but should be 11.

The path from a leaf to the root has one node on each level, so an update is O(log n). The code for building the tree, querying it and updating it follows.

Segment tree for range sums
class SegmentTree {
  constructor(values) {
    this.n = values.length;
    this.tree = new Array(4 * this.n).fill(0);
    if (this.n > 0) this.build(values, 0, 0, this.n - 1);
  }
  build(values, node, lo, hi) {
    if (lo === hi) { this.tree[node] = values[lo]; return; }
    const mid = Math.floor((lo + hi) / 2);
    this.build(values, 2 * node + 1, lo, mid);
    this.build(values, 2 * node + 2, mid + 1, hi);
    this.tree[node] = this.tree[2 * node + 1] + this.tree[2 * node + 2];
  }
  // Sum of values[left..right], both included.
  query(left, right, node = 0, lo = 0, hi = this.n - 1) {
    if (right < lo || hi < left) return 0;                 // no overlap
    if (left <= lo && hi <= right) return this.tree[node]; // fully inside
    const mid = Math.floor((lo + hi) / 2);
    return this.query(left, right, 2 * node + 1, lo, mid) +
           this.query(left, right, 2 * node + 2, mid + 1, hi);
  }
  // Set values[index] = value.
  update(index, value, node = 0, lo = 0, hi = this.n - 1) {
    if (lo === hi) { this.tree[node] = value; return; }
    const mid = Math.floor((lo + hi) / 2);
    if (index <= mid) this.update(index, value, 2 * node + 1, lo, mid);
    else this.update(index, value, 2 * node + 2, mid + 1, hi);
    this.tree[node] = this.tree[2 * node + 1] + this.tree[2 * node + 2];
  }
}
class SegmentTree:
    def __init__(self, values):
        self.n = len(values)
        self.tree = [0] * (4 * self.n)
        if self.n > 0:
            self._build(values, 0, 0, self.n - 1)
 
    def _build(self, values, node, lo, hi):
        if lo == hi:
            self.tree[node] = values[lo]
            return
        mid = (lo + hi) // 2
        self._build(values, 2 * node + 1, lo, mid)
        self._build(values, 2 * node + 2, mid + 1, hi)
        self.tree[node] = self.tree[2 * node + 1] + self.tree[2 * node + 2]
 
    def query(self, left, right, node=0, lo=0, hi=None):
        """Sum of values[left..right], both included."""
        if hi is None:
            hi = self.n - 1
        if right < lo or hi < left:
            return 0                      # no overlap
        if left <= lo and hi <= right:
            return self.tree[node]        # fully inside
        mid = (lo + hi) // 2
        return (self.query(left, right, 2 * node + 1, lo, mid) +
                self.query(left, right, 2 * node + 2, mid + 1, hi))
 
    def update(self, index, value, node=0, lo=0, hi=None):
        """Set values[index] = value."""
        if hi is None:
            hi = self.n - 1
        if lo == hi:
            self.tree[node] = value
            return
        mid = (lo + hi) // 2
        if index <= mid:
            self.update(index, value, 2 * node + 1, lo, mid)
        else:
            self.update(index, value, 2 * node + 2, mid + 1, hi)
        self.tree[node] = self.tree[2 * node + 1] + self.tree[2 * node + 2]

Nothing in this code is specific to sums. If the combine step is a minimum and the answer for an empty overlap is infinity instead of 0, the same tree answers range minimum queries. Any operation that gives the same result however the values are grouped can be used, such as sum, minimum, maximum, greatest common divisor or bitwise AND.

#How a Fenwick tree works

For sums, a Fenwick tree gives the same O(log n) bounds with less code and less memory. It is a single array of n + 1 numbers with two short loops, and it has no explicit tree.

The slots are numbered from 1. Slot i stores the sum of the last lowbit(i) items that end at item i, where lowbit(i) is the lowest 1 bit of i, computed as i & -i (see Bit Manipulation). Slot 6 is 110 in binary, so its lowest bit is 2 and it holds items 5 and 6. Slot 7 holds only item 7, and slot 8 holds all eight items.

To get the total of the first i items, add slot i, then move to slot i − lowbit(i), and repeat until the slot is 0. For 7 the slots are 7, 6 and 4. Each step removes the lowest 1 bit, so the loop runs at most about log₂(n) times.

To add a value to item i, add it to slot i, then move to slot i + lowbit(i), which is the next larger block that also covers item i, and repeat while the slot is inside the array. For item 3 the slots are 3, 4 and 8. This loop also runs at most about log₂(n) times. The trace below adds 5 to item 3 and then totals the first 7 items.

The code uses 0-based indexes and shifts them by one inside the class. The sum of left..right is first(right + 1) − first(left), which is the same subtraction that prefix sums use.

Fenwick tree
class Fenwick {
  constructor(n) { this.t = new Array(n + 1).fill(0); }
  add(index, delta) { // values[index] += delta
    for (let i = index + 1; i < this.t.length; i += i & -i) this.t[i] += delta;
  }
  first(count) { // sum of the first count values
    let s = 0;
    for (let i = count; i > 0; i -= i & -i) s += this.t[i];
    return s;
  }
  rangeSum(left, right) { return this.first(right + 1) - this.first(left); }
}
 
const fw = new Fenwick(8);
[5, 2, 6, 3, 1, 4, 7, 2].forEach((v, i) => fw.add(i, v));
fw.add(2, 5);
fw.first(7);       // 33
fw.rangeSum(2, 6); // 26
class Fenwick:
    def __init__(self, n):
        self.t = [0] * (n + 1)
 
    def add(self, index, delta):  # values[index] += delta
        i = index + 1
        while i < len(self.t):
            self.t[i] += delta
            i += i & -i
 
    def first(self, count):  # sum of the first count values
        s, i = 0, count
        while i > 0:
            s += self.t[i]
            i -= i & -i
        return s
 
    def range_sum(self, left, right):
        return self.first(right + 1) - self.first(left)
 
fw = Fenwick(8)
for i, v in enumerate([5, 2, 6, 3, 1, 4, 7, 2]):
    fw.add(i, v)
fw.add(2, 5)
fw.first(7)        # 33
fw.range_sum(2, 6) # 26

#Choosing between a Fenwick tree and a segment tree

Use a Fenwick tree when the query is a sum or a count. It is shorter to write, it needs n + 1 numbers instead of up to 4n, and it is faster in practice. Its range query subtracts one prefix total from another, so it only fits operations that can be undone. Sum and count qualify. Minimum and maximum do not, because knowing the minimum of the first 7 items and of the first 2 items says nothing about the minimum of items 3 to 7.

Use a segment tree for minimum, maximum, greatest common divisor, or any other operation that cannot be subtracted.

#Variants

#Range updates with lazy propagation

Sometimes an update applies to a whole range, such as "add 3 to every value from index 2 to 6". A segment tree can do it in O(log n) with lazy propagation. When an update covers a node's whole range, the node changes its own stored sum and records the pending addition, without touching its children. The pending addition is passed down to the children only when a later query or update has to go below that node. Forgetting to push the pending addition down before visiting the children gives stale sums.

#Counting with a Fenwick tree

A Fenwick tree is also used to count items, which covers a common family of problems such as counting how many earlier values are smaller than the current one, or counting inversions in an array. The tree stores a count for each possible value. For each element you ask for the number of stored values below it, which is a prefix query, and then add 1 at the element's own position. If the values are large, first replace each one by its rank among the sorted distinct values, which is called coordinate compression.

#When neither structure is needed

If the values never change, use prefix sums for range sums, because they are simpler and answer in O(1). If the problem asks for something that is not a range aggregate, such as the k-th smallest value in a range, these trees do not solve it in their basic form.

#Pitfalls

Setting a value instead of adding a change in a Fenwick tree

The add method takes the change, not the new value. To set index 2 from 6 to 11, call add(2, 5). If the problem gives new values, keep a plain copy of the array so that you can compute new − old.

Allocating only 2n entries for a segment tree

The heap-style layout leaves gaps when the length is not a power of 2, so node numbers can go beyond 2n. With 10 items the tree uses node 24, which is more than 2 × 10. Allocate 4n entries.

Returning 0 for an empty overlap when the operation is not a sum

The "no overlap" case must return the identity of the operation, which is 0 for sums, infinity for minimum and negative infinity for maximum. Returning 0 in a minimum tree makes every query that skips a node answer 0.

#In the interview

The signal is a problem that gives you an array and a long list of operations that mix changes to single values with queries about ranges, such as sums, minimums or counts. If all the queries come after all the updates, or there are no updates, a prefix sum array is enough. When both kinds of operation are frequent and a loop over the range would be too slow, say that you need O(log n) for each and choose between a Fenwick tree and a segment tree. For sums choose the Fenwick tree, and for minimum or maximum choose the segment tree.

Interviewers commonly follow up with these questions.

  • "Why is a query O(log n)?" At each level at most two nodes overlap the query range partly, and those are the nodes that hold the edges of the range. Every other node on that level is either fully inside, so it returns a stored sum, or fully outside, so it returns nothing. The tree has about log₂(n) levels.
  • "Can a Fenwick tree find a range minimum?" No. The range query subtracts two prefix results, and a minimum cannot be subtracted. Use a segment tree instead.
  • "How would you add a value to every element in a range?" Use a segment tree with lazy propagation. A node whose range is completely covered records the pending addition and updates its own sum, and the addition is pushed to the children only when a later operation needs to go below that node. Updates and queries both stay O(log n).
  • "How do you build the structure from an initial array?" A segment tree is built recursively in O(n), because each node is computed once from its two children. A Fenwick tree built by n separate adds costs O(n log n), but it can be built in O(n) by copying the array into the slots and then, for each slot i, adding its value to slot i + lowbit(i) if that slot exists.
Quick check

In a segment tree over 1,000,000 values, about how many nodes change on one update?

  1. Right. One node on each level changes, and there are about log₂(1,000,000), which is roughly 20, levels.
  2. Not quite. That is the square root of n, which is the cost of splitting the array into square-root-sized buckets. A segment tree changes only the path to the root.
  3. Not quite. That is roughly what an update costs on average when you keep prefix sums.

Which Fenwick slots does the query for the total of the first 6 items read?

  1. Right. Slot 6 covers items 5 and 6. Since lowbit(6) is 2, the next slot is 4, which covers items 1 to 4, and then the loop reaches 0 and stops.
  2. Not quite. Each step skips a whole block, not a single item.
  3. Not quite. Moving up with i + lowbit(i) is what the add operation does. A query moves down.

You need the smallest value in any range, and the values keep changing. Which structure fits?

  1. Not quite. Minimums cannot be subtracted, so two prefixes do not give a middle range, and each update would cost O(n).
  2. Not quite. A Fenwick range query subtracts two prefix results, which works for sums but not for minimums.
  3. Right. The children are combined with a minimum instead of a sum, and queries and updates both stay O(log n).

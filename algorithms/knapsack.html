Knapsack

Choose which items to pack under a weight limit for the most value. Fill the item-by-capacity table, read back the chosen items, then shrink it to one row.

Your bike trailer holds 5 kg for a weekend market. You could bring honey (2 kg, profit 4), cheese (3 kg, profit 7) and jam (4 kg, profit 10), each whole or not at all. What should you load?

Jam earns the most per kilo, 2.5, so a common rule takes it first. Then 1 kg is left and nothing fits: profit 10. Honey and cheese weigh exactly 5 kg and earn 11. Three items give 8 combinations to check; 40 items give over a trillion. This is the 0/1 knapsack problem: every item is in (1) or out (0).

#Why one index is not enough

Try a state like those in 1D Dynamic Programming: "the best profit from the first i items". To decide on item i, you need to know how much space the earlier items used, and the state does not say. Two packings with equal profit can leave different room.

So put the space into the state too: one row per item and one column per amount of space, like the tables in DP on Grids.

#The five steps

  1. State. best[i][w] is the most profit from the first i items in at most w kg.
  2. Recurrence. Skip item i: best[i − 1][w]. Pack it, if it fits: its value plus the best from earlier items in the space left, value[i] + best[i − 1][w − weight[i]]. Take the larger.
  3. Base cases. best[0][w] = 0: no items, no profit.
  4. Order. Each cell reads only the row above, so fill row by row.
  5. Answer. best[n][W].

The "take" arrow always comes from the row above, so an item is never used twice: once you pack the cheese, the rest of the space holds only earlier items.

#The code

Item-by-capacity table
function bestProfit(weights, values, capacity) {
  const n = weights.length;
  const best = Array.from({ length: n + 1 }, () => new Array(capacity + 1).fill(0));
  for (let i = 1; i <= n; i++) {
    const weight = weights[i - 1]; // row i is item i - 1 in the arrays
    const value = values[i - 1];
    for (let w = 0; w <= capacity; w++) {
      best[i][w] = best[i - 1][w]; // skip the item
      if (weight <= w) {
        best[i][w] = Math.max(best[i][w], value + best[i - 1][w - weight]); // take it
      }
    }
  }
  return best[n][capacity];
}
 
bestProfit([2, 3, 4], [4, 7, 10], 5); // 11

#One row is enough, if you go backwards

Each row reads only the row above, so keep one array and overwrite it item by item. The catch: "take" reads best[w − weight], a cell to the left. Loop w upward and that cell is already overwritten for the current item, so the item gets packed twice. Loop downward and every cell to the left still holds the old row.

One row, filled right to left
function bestProfitOneRow(weights, values, capacity) {
  const best = new Array(capacity + 1).fill(0);
  for (let i = 0; i < weights.length; i++) {
    // High to low, so best[w - weights[i]] is still from the previous item.
    for (let w = capacity; w >= weights[i]; w--) {
      best[w] = Math.max(best[w], values[i] + best[w - weights[i]]);
    }
  }
  return best[capacity];
}
def best_profit_one_row(weights, values, capacity):
    best = [0] * (capacity + 1)
    for weight, value in zip(weights, values):
        # High to low, so best[w - weight] is still from the previous item.
        for w in range(capacity, weight - 1, -1):
            best[w] = max(best[w], value + best[w - weight])
    return best[capacity]
Key idea

When a choice uses up a shared resource, put the amount left into the state: one dimension for "which items have I considered", one for "how much room is left".

ApproachTimeSpaceWhy
Try every subsetO(2ⁿ × n)O(n)Each item is in or out; each subset takes up to n steps to add up.
Full tableO(n × W)O(n × W)Two options per cell. You can walk back to list the items.
One rowO(n × W)O(W)Same work, but no walking back.

The cost depends on the capacity W, not just the item count. Three items and 5 kg is 4 × 6 = 24 cells. In grams the limit is 5,000: 4 × 5,001 cells for the same answer. With 20 items and a capacity in the billions the table is hopeless, while trying all 2²⁰ (about a million) subsets is quick.

#Common mistakes

Looping upward in the one-row version

With honey alone (2 kg, profit 4) and 4 kg of space, an upward loop sets best[2] = 4, then best[4] = 4 + best[2] = 8: two boxes from one. That answers the unlimited-copies problem instead, like the coin table in Introduction to Dynamic Programming, which loops upward on purpose.

Packing by profit per kilo

Packing by value per weight is correct only if you may cut items into pieces, like pouring out part of a sack of rice. For whole items it can strand space, as the jam did. See Greedy Algorithms.

Mixing up row numbers and item positions

Row 0 means "no items", so row i is the item at position i − 1. Reading weights[i] skips the first item and runs past the last.

In the real world

The same shape appears whenever a budget goes on all-or-nothing choices, such as picking features that fit a team's hours for a release.

#Check yourself

Quick check

Items: (1 kg, profit 3) and (3 kg, profit 5). Capacity 3 kg. What is best[2][3]?

  1. Not quite. Both items weigh 4 kg. Only 3 kg fits.
  2. Right. Skip the 3 kg item: best[1][3] = 3. Take it: 5 + best[1][0] = 5.
  3. Not quite. That is the skip option. Taking the 3 kg item earns more.

Why does the "take" option read best[i − 1][…] and not best[i][…]?

  1. Not quite. Cells to the left in row i are filled. Reading them would be possible, and wrong.
  2. Right. The remaining space holds only earlier items. Reading row i would let item i appear again.
  3. Not quite. Both reads cost the same. The row decides which problem you solve.

A packing problem has 30 items and a capacity of 50. Roughly how many cells does the full table have?

  1. Right. (30 + 1) × (50 + 1) = 1,581 cells.
  2. Not quite. That is roughly 2³⁰, the brute-force subset count.
  3. Not quite. The table multiplies items by capacities; it does not add them.

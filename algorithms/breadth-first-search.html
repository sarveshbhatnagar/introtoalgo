Breadth-First Search

How breadth-first search uses a queue to find the fewest-edges path in an unweighted graph or grid, its variants, and what interviewers ask about it.

Breadth-first search (BFS) is a way to visit every node of a graph in order of its distance from a starting node: first the start, then every node one edge away, then every node two edges away, and so on. Because of that order, the first time BFS reaches a node it has found a path with the fewest edges. You use it whenever a problem asks for the minimum number of steps, moves or hops in a graph where every step costs the same.

Without BFS you would have to compare many routes. A depth-first walk, for example, can reach a node by a long winding route first, and it would have to keep searching to find out whether a shorter one exists. BFS never has that problem, because it only reaches a node by a longer route after it has already reached it by every shorter one.

#How BFS works

BFS keeps a queue of nodes that have been discovered but not yet processed. It takes a node from the front of the queue and adds that node's undiscovered neighbours to the back. Because the queue is first in, first out, every node at distance 1 is processed before any node at distance 2, since the distance-2 nodes are only added while processing distance-1 nodes.

A graph can contain cycles (see Graph Basics), so BFS also keeps a set of nodes it has already seen. A node goes into the seen set at the moment it is added to the queue, not when it is taken out.

  1. Put the start node in the queue, mark it seen, and give it distance 0.
  2. Take the node at the front of the queue.
  3. For each neighbour that has not been seen, mark it seen, set its distance to the current node's distance plus 1, and add it to the back of the queue.
  4. Repeat from step 2 until the queue is empty.

#Code

The code below also stores each node's parent, which is the node it was discovered from. To recover the route to a goal, follow the parents from the goal back to the start and reverse the result.

// graph: adjacency list, e.g. { A: ["B", "C"], B: ["A", "D"], ... }
function bfs(graph, start) {
  const dist = { [start]: 0 }; // also our "seen" set
  const parent = { [start]: null };
  const queue = [start];
  let head = 0; // index of the front: O(1) dequeue
  while (head < queue.length) {
    const node = queue[head++];
    for (const next of graph[node]) {
      if (next in dist) continue; // already seen
      dist[next] = dist[node] + 1;
      parent[next] = node;
      queue.push(next);
    }
  }
  return { dist, parent };
}
 
function pathTo(parent, goal) {
  if (!(goal in parent)) return null; // unreachable
  const path = [];
  for (let at = goal; at !== null; at = parent[at]) path.push(at);
  return path.reverse();
}
// pathTo(bfs(graph, "A").parent, "G") → ["A", "B", "D", "F", "G"]
from collections import deque
 
# graph: adjacency list, e.g. {"A": ["B", "C"], "B": ["A", "D"], ...}
def bfs(graph, start):
    dist = {start: 0}  # also our "seen" set
    parent = {start: None}
    queue = deque([start])
    while queue:
        node = queue.popleft()
        for nxt in graph[node]:
            if nxt in dist:
                continue  # already seen
            dist[nxt] = dist[node] + 1
            parent[nxt] = node
            queue.append(nxt)
    return dist, parent
 
def path_to(parent, goal):
    if goal not in parent:
        return None  # unreachable
    path = []
    at = goal
    while at is not None:
        path.append(at)
        at = parent[at]
    return path[::-1]
# path_to(bfs(graph, "A")[1], "G") → ['A', 'B', 'D', 'F', 'G']

#Cost of BFS

TimeO(V + E)
SpaceO(V)

Each node joins the queue at most once, and each neighbour list is read once, so every edge is looked at twice in an undirected graph. The queue, dist and parent hold at most V entries.

#BFS on a grid

Finding the fewest moves through a maze is the same problem, since a grid is a graph in which each open cell is connected to its open neighbours above, below, left and right (see Graph Basics). There is no adjacency list. You compute the neighbours from the row and column, and you skip any that are outside the grid or are walls. Instead of a dist map, use a 2D array of the same size as the grid, filled with -1 to mean "not seen yet".

const DIRS = [[-1, 0], [1, 0], [0, -1], [0, 1]];
 
// grid: array of strings, "#" is a wall. Start top-left, exit bottom-right.
function stepsToExit(grid) {
  const rows = grid.length, cols = grid[0].length;
  const dist = grid.map((row) => new Array(row.length).fill(-1));
  dist[0][0] = 0;
  const queue = [[0, 0]];
  let head = 0;
  while (head < queue.length) {
    const [r, c] = queue[head++];
    if (r === rows - 1 && c === cols - 1) return dist[r][c];
    for (const [dr, dc] of DIRS) {
      const nr = r + dr, nc = c + dc;
      if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
      if (grid[nr][nc] === "#" || dist[nr][nc] !== -1) continue;
      dist[nr][nc] = dist[r][c] + 1;
      queue.push([nr, nc]);
    }
  }
  return -1; // the exit cannot be reached
}
 
stepsToExit(["...#.", ".#...", ".#.#.", "...#."]); // 7
from collections import deque
 
DIRS = [(-1, 0), (1, 0), (0, -1), (0, 1)]
 
# grid: list of strings, "#" is a wall. Start top-left, exit bottom-right.
def steps_to_exit(grid):
    rows, cols = len(grid), len(grid[0])
    dist = [[-1] * cols for _ in range(rows)]
    dist[0][0] = 0
    queue = deque([(0, 0)])
    while queue:
        r, c = queue.popleft()
        if (r, c) == (rows - 1, cols - 1):
            return dist[r][c]
        for dr, dc in DIRS:
            nr, nc = r + dr, c + dc
            if not (0 <= nr < rows and 0 <= nc < cols):
                continue
            if grid[nr][nc] == "#" or dist[nr][nc] != -1:
                continue
            dist[nr][nc] = dist[r][c] + 1
            queue.append((nr, nc))
    return -1  # the exit cannot be reached
 
steps_to_exit(["...#.", ".#...", ".#.#.", "...#."])  # 7

A grid with R rows and C columns has R × C cells and each has at most 4 neighbours, so the time and the space are both O(R × C).

#Variants

#Starting from several nodes at once

To find how far each cell is from the nearest one of several sources, such as the nearest exit, fire or hospital, put all the sources in the queue at distance 0 before the loop starts. The waves then grow from every source at the same time, and each cell is claimed by whichever source is closest. This is one BFS instead of one per source, so the cost stays O(V + E) however many sources there are. Problems such as "how many minutes until every orange has rotted" work this way.

#Level by level

Sometimes the answer is the number of waves rather than a distance for each node, or you need to handle one wave at a time, as in "return the values of a tree row by row". Take the queue's current length at the start of each outer iteration, process exactly that many nodes, and then increase a level counter. Nodes added during the iteration belong to the next wave and are not processed until the next iteration. This replaces the dist array when only the number of levels matters.

#Searching a graph that is never written down

Many BFS problems have no graph in the input. Each state of a puzzle or a word is a node, and the allowed moves define the edges. In word ladder problems the nodes are words and two words are connected if they differ by one letter. In a sliding-tile puzzle or a lock with four rotating wheels, a node is a whole arrangement and an edge is one move. You generate a node's neighbours when you take it from the queue, and the seen set holds the states already generated, usually as strings or tuples. The cost is the number of reachable states, which can be large, so state the size of the state space when you give the complexity.

#Searching from both ends

If you know both the start and the goal, you can run one BFS from each and stop when the two searches meet. When each node has about b neighbours and the shortest path has d edges, a single search reaches roughly b to the power d nodes, while two searches that each go half way reach about twice b to the power d/2. This helps a lot on large implicit graphs such as word ladders, and it needs edges that can be followed in both directions.

#When BFS does not apply

BFS counts edges, so it is only correct when every edge costs the same. If edges have different costs, such as roads of 2 and 30 minutes, the path with the fewest roads can be the slowest. Use Dijkstra's algorithm for non-negative weights. If the weights are only 0 and 1, a variant called 0-1 BFS keeps a double-ended queue, putting 0-cost neighbours at the front and 1-cost neighbours at the back, and runs in O(V + E).

For "is this reachable?" and "how many connected pieces are there?", BFS works, but depth-first search is just as correct and shorter to write recursively. BFS is the wrong tool when you need every path, or need to explore one branch completely before trying another, as in backtracking.

#Pitfalls

Marking a node seen when it leaves the queue

If you mark a node seen only when you take it out, it can be added several times before that happens. On the bus map, B and C would each add D. On a large grid, a cell next to several frontier cells is added once by each of them, and the queue can grow far beyond the number of cells. Mark the node seen, and set its distance, at the moment you add it to the queue.

Using shift() or pop(0) as the dequeue

In JavaScript, queue.shift() moves every remaining element, so each call is O(n) and BFS becomes O(V²) on large inputs. Keep a head index into the array instead, as the code above does. In Python, use collections.deque with popleft(), and do not use list.pop(0).

Returning a distance when the goal was never reached

If the queue empties without the goal ever being reached, the goal is not connected to the start. Return -1 or null as the problem specifies, instead of the initial value of the distance array, and in the path code check that the goal is in parent before following it.

#In the interview

The signals that a problem needs BFS are a request for the minimum number of steps, moves, hops, turns or operations, where every step costs the same, and a structure that is a graph, a grid or a set of states connected by moves. Phrases such as "shortest path", "nearest", "fewest moves" and "minimum number of mutations" all point to it. Problems that ask for the values of a tree level by level also use it. Say which node or state is the vertex and what an edge is, because that is the first thing the interviewer checks.

Questions to expect:

  • "Why does BFS find the shortest path?" It takes nodes from the queue in order of distance from the start, because nodes at distance k are all added before any node at distance k + 1. So the first time a node is reached, no shorter route exists. This only holds when all edges cost the same.
  • "What if the edges have weights?" BFS is no longer correct. Use Dijkstra's algorithm for non-negative weights. If the weights are only 0 and 1, use 0-1 BFS with a double-ended queue.
  • "How do you return the path and not just its length?" Store each node's parent when you add it to the queue. When you reach the goal, follow the parents back to the start and reverse the list.
  • "What are the time and space complexity?" O(V + E) time and O(V) space with adjacency lists, or O(R × C) on a grid. With an adjacency matrix, finding a node's neighbours takes O(V), so the time becomes O(V²).
  • "BFS or DFS here?" Choose BFS when the answer depends on the shortest distance. Choose DFS when you only need to know whether something is reachable or to count components. DFS uses less memory on a wide, shallow graph, because BFS has to hold a whole wave in the queue.
Quick check

Graph: { P: [Q, R], Q: [P, S], R: [P, S, T], S: [Q, R], T: [R] }. In what order does BFS from P take nodes out of the queue?

  1. Right. P adds Q and R. Q adds S. R adds T, because S has already been seen. The distances are 0, 1, 1, 2 and 2.
  2. Not quite. This goes deep from Q before finishing P's neighbours, which is depth-first order.
  3. Not quite. Q was added to the queue before R, so Q comes out first.

Why does BFS mark a node seen when it joins the queue instead of when it leaves?

  1. Not quite. The first copy to come out of the queue would still have the right distance. The real problem is wasted work.
  2. Right. If the mark is made late, several neighbours can add the same node, which makes the queue much larger on dense graphs and grids.
  3. Not quite. A queue can hold duplicates. Preventing them is the job of the seen set.

A grid is 1,000 × 1,000. At most how many cells does BFS take out of the queue?

  1. Not quite. That is roughly the number of border cells. BFS can reach every open cell in the grid.
  2. Right. Each cell enters the queue at most once, so the limit is R × C = 1,000,000.
  3. Not quite. That would mean processing every cell once for every other cell. BFS never processes a cell twice.

Roads between towns have different travel times. Which algorithm finds the fastest route from one town?

  1. Not quite. The route with the fewest roads can take longer than a route with more, shorter roads.
  2. Right. It takes the town with the smallest total travel time so far, which works for non-negative weights.
  3. Not quite. Depth-first search does not process nodes in order of cost, so it gives no guarantee about the fastest route.

#What to practise next

Depth-first search explores one branch as far as it goes before backing up, which makes it the simpler choice for connectivity and counting components. For graphs with weighted edges, continue with Dijkstra's algorithm.

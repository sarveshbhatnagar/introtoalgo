Depth-First Search

Walk a graph by going as deep as you can, then backing up. Write DFS with recursion or a stack, and use it to count connected pieces and islands in a grid.

You are exploring a cave with a ball of string tied to the entrance. At every fork you take the first passage you have not tried and keep going, unrolling string behind you. At a dead end, or where every passage leads somewhere you have been, you wind the string back to the last fork with an untried passage and take it. When the string is fully wound back at the entrance, you have seen the whole cave.

That is depth-first search (DFS). Where BFS spreads out in rings, DFS commits to one route and follows it as deep as it goes before trying anything else.

#The idea: go deep, then back up

The string is a record of how to get back. In code, recursion gives you that record for free: each call waits on the call stack while its child explores, exactly as in Recursion. A node's DFS is:

  1. Mark the node seen.
  2. For each neighbour that is not seen yet, run DFS on it, all the way, before looking at the next neighbour.

The seen mark stops you from going round a cycle forever, as it did in BFS.

#Trace it on the same bus map

This is the bus map from Graph Basics again, with the same alphabetical neighbour lists and the same start, A. The labels show visit order, and the highlighted edges are the string.

Both searches visit every stop once. Each draws a tree on the graph: for every node, the edge it first arrived by. The trees have very different shapes.

Key idea

BFS uses a queue and finishes each distance before the next, so it finds shortest paths. DFS uses a stack (often the call stack) and follows one branch to the end. It is short to write, but it promises nothing about path length.

#The code

Recursive
// graph: adjacency list, e.g. { A: ["B", "C"], B: ["A", "D"], ... }
function dfs(graph, start) {
  const seen = new Set();
  const order = [];
  function visit(node) {
    seen.add(node);
    order.push(node);
    for (const next of graph[node]) {
      if (!seen.has(next)) visit(next);
    }
  }
  visit(start);
  return order;
}
// dfs(graph, "A") → ["A", "B", "D", "C", "E", "F", "G"]
# graph: adjacency list, e.g. {"A": ["B", "C"], "B": ["A", "D"], ...}

    order = []
 
    def visit(node):

        order.append(node)

            if nxt not in seen:

    return order
# dfs(graph, "A") → ['A', 'B', 'D', 'C', 'E', 'F', 'G']

You can replace the call stack with a stack of your own. Pop a node, skip it if it is already seen, otherwise mark it and push its neighbours. Push them in reverse so the first neighbour comes off the stack first; then the order matches the recursive version.

Iterative, with your own stack
function dfsIterative(graph, start) {
  const seen = new Set();
  const order = [];
  const stack = [start];
  while (stack.length > 0) {
    const node = stack.pop();
    if (seen.has(node)) continue; // pushed twice, already handled
    seen.add(node);
    order.push(node);
    const nbrs = graph[node];
    for (let i = nbrs.length - 1; i >= 0; i--) {
      if (!seen.has(nbrs[i])) stack.push(nbrs[i]);
    }
  }
  return order;
}
def dfs_iterative(graph, start):
    seen = set()
    order = []
    stack = [start]
    while stack:
        node = stack.pop()
        if node in seen:
            continue  # pushed twice, already handled
        seen.add(node)
        order.append(node)
        for nxt in reversed(graph[node]):
            if nxt not in seen:
                stack.append(nxt)
    return order

Recursive DFSO(V + E)O(V)Each node is visited once and its list read once. The seen set and the call stack can each reach V.

#Counting islands in a grid

The most common use of DFS is counting connected components: the separate pieces of a graph. Scan every node. Whenever you find one that is not seen yet, you have found a new piece. Count it, then run DFS from it to mark the whole piece seen, so you never count it again.

On a grid this is the "islands" question: land cells (#) that touch up, down, left or right belong to the same island. The DFS that marks an island is often called a flood fill, like the paint bucket in a drawing app.

// grid: array of strings. "#" is land, "." is water.
function countIslands(grid) {
  const rows = grid.length, cols = grid[0].length;
  const seen = grid.map((row) => new Array(row.length).fill(false));
  function fill(r, c) {
    if (r < 0 || r >= rows || c < 0 || c >= cols) return; // off the map
    if (grid[r][c] !== "#" || seen[r][c]) return;         // water, or done
    seen[r][c] = true;
    fill(r - 1, c); fill(r + 1, c); fill(r, c - 1); fill(r, c + 1);
  }
  let islands = 0;
  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (grid[r][c] === "#" && !seen[r][c]) {
        islands++;  // a piece nobody has reached yet
        fill(r, c); // mark all of it
      }
    }
  }
  return islands;
}
 
countIslands(["##..#", "#...#", "..#..", "##..."]); // 4
# grid: list of strings. "#" is land, "." is water.
def count_islands(grid):
    rows, cols = len(grid), len(grid[0])
    seen = [[False] * cols for _ in range(rows)]
 
    def fill(r, c):
        if not (0 <= r < rows and 0 <= c < cols):
            return  # off the map
        if grid[r][c] != "#" or seen[r][c]:
            return  # water, or done
        seen[r][c] = True
        fill(r - 1, c); fill(r + 1, c); fill(r, c - 1); fill(r, c + 1)
 
    islands = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == "#" and not seen[r][c]:
                islands += 1  # a piece nobody has reached yet
                fill(r, c)    # mark all of it
    return islands
 
count_islands(["##..#", "#...#", "..#..", "##..."])  # 4

The outer loops touch every cell once, and fill marks each land cell once and looks at its 4 sides. Total: O(R × C) time, however many islands there are. BFS would work too; the recursive DFS is shorter to write.

#Common mistakes

Marking seen too late

Mark a node seen as the first thing in its call, before looping over its neighbours. If you mark it after, A visits B, B looks back at A, A is not marked yet, and the two call each other until the stack overflows.

Running out of stack on big grids

A 1,000 × 1,000 grid that is all land makes recursive DFS one million calls deep. Python stops at about 1,000 by default and raises RecursionError; JavaScript engines throw "Maximum call stack size exceeded" somewhere in the thousands to tens of thousands. For large inputs, use the iterative version with your own stack, or BFS.

Expecting DFS to find the shortest route

DFS takes whatever route its neighbour order leads it down. On the bus map it reached G by a 6-edge route when a 4-edge one exists. If the question says "fewest" or "shortest", use BFS.

In the real world

Garbage collectors find unused memory with a graph walk: start from the variables in use, follow every reference, and anything never reached can be freed.

#Check yourself

Quick check

Graph: { P: [Q, R], Q: [P, S], R: [P, S, T], S: [Q, R], T: [R] }. In what order does recursive DFS from P visit the nodes?

  1. Not quite. That is the BFS order: it finishes P's neighbours before going deeper.
  2. Right. P goes to Q, Q to S (P is seen), S to R (Q is seen), R to T (P and S are seen).
  3. Not quite. DFS takes neighbours in list order, and Q comes before R in P's list.

How many islands are in the grid ["#.#", ".#.", "#.#"]?

  1. Not quite. The land cells only touch at corners. Diagonal neighbours do not count.
  2. Right. Each of the 5 land cells has water above, below, left and right of it, so each is its own island.
  3. Not quite. The middle cell counts too. It is land with no land neighbours, so it is an island by itself.

Why does the iterative DFS check seen after popping, even though it also checks before pushing?

  1. Not quite. In the bus map, C is pushed by A and again by D before either copy is popped. Without the check after popping, C would be visited twice.
  2. Right. Right. The check before pushing only filters nodes already visited. A node waiting on the stack can be pushed again, so the second copy must be skipped when it comes off.
  3. Not quite. No version of DFS promises shortest paths. The check only prevents visiting a node twice.

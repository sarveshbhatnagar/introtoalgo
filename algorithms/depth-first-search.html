Depth-First Search

How depth-first search visits a graph by following one path to its end before backing up, its recursive and iterative forms, and what interviewers ask.

Depth-first search (DFS) is a way to visit every node reachable from a starting node in a graph by following one path as far as it goes and only then backing up to try the next option. It answers questions about reachability and structure, such as whether one node can reach another, how many separate pieces a graph has, and whether it contains a cycle. You reach for it when you need to explore everything, and the order or length of the paths does not matter.

Without a systematic method, a search through a graph either misses nodes or goes around a cycle forever. DFS avoids both by never entering a node twice.

#How depth-first search works

DFS is defined recursively. To run DFS on a node, you mark the node as seen, and then for each neighbour that is not yet seen you run DFS on that neighbour completely before you look at the next one. When a node has no unseen neighbours left, its call returns and the search continues from the node that called it. The seen mark is what prevents the search from circling forever in a graph that has cycles. The call stack of recursion remembers the path from the start to the current node, which is how the search knows where to back up to.

The edges that the search used to discover each node form a tree, called the DFS tree. The figure compares it with the tree that BFS builds on the same graph.

#The code

The recursive version is the shortest way to write DFS. It returns the nodes in the order they were visited.

Recursive
// graph: adjacency list, e.g. { A: ["B", "C"], B: ["A", "D"], ... }
function dfs(graph, start) {
  const seen = new Set();
  const order = [];
  function visit(node) {
    seen.add(node);
    order.push(node);
    for (const next of graph[node]) {
      if (!seen.has(next)) visit(next);
    }
  }
  visit(start);
  return order;
}
// dfs(graph, "A") → ["A", "B", "D", "C", "E", "F", "G"]
# graph: adjacency list, e.g. {"A": ["B", "C"], "B": ["A", "D"], ...}

#Variants

#Iterative DFS with your own stack

You can replace the call stack with an explicit stack. This is the right choice when the graph is deep enough to overflow the call stack. You pop a node, skip it if it has already been seen, and otherwise mark it, record it and push its unseen neighbours. The neighbours are pushed in reverse order so that the first neighbour is popped first, which gives the same visit order as the recursive version.

The check for seen nodes happens when a node is popped, as well as when it is pushed. A node can be pushed more than once before it is popped, because it may be a neighbour of several nodes that are still on the stack. On the bus map, both A and D push C. The second copy is skipped when it is popped.

Iterative, with your own stack
function dfsIterative(graph, start) {
  const seen = new Set();
  const order = [];
  const stack = [start];
  while (stack.length > 0) {
    const node = stack.pop();
    if (seen.has(node)) continue; // pushed twice, already handled
    seen.add(node);
    order.push(node);
    const nbrs = graph[node];
    for (let i = nbrs.length - 1; i >= 0; i--) {
      if (!seen.has(nbrs[i])) stack.push(nbrs[i]);
    }
  }
  return order;
}
def dfs_iterative(graph, start):
    seen = set()
    order = []
    stack = [start]
    while stack:
        node = stack.pop()
        if node in seen:
            continue  # pushed twice, already handled
        seen.add(node)
        order.append(node)
        for nxt in reversed(graph[node]):
            if nxt not in seen:
                stack.append(nxt)
    return order

#Counting connected components and islands in a grid

A connected component is a set of nodes that can all reach each other. To count them, you scan every node, and each node that has not been seen starts a new component. You add one to the count and run DFS from that node, which marks the whole component as seen so that none of its other nodes starts another count.

On a grid, this is the classic "number of islands" problem. Each land cell is a node, and it is connected to the land cells directly above, below, left and right of it. The DFS that marks one island is often called a flood fill, like the paint bucket tool in an image editor. Cells that touch only at a corner are not connected, which is why islands 3 and 4 in the figure are separate.

// grid: array of strings. "#" is land, "." is water.
function countIslands(grid) {
  const rows = grid.length, cols = grid[0].length;
  const seen = grid.map((row) => new Array(row.length).fill(false));
  function fill(r, c) {
    if (r < 0 || r >= rows || c < 0 || c >= cols) return; // off the map
    if (grid[r][c] !== "#" || seen[r][c]) return;         // water, or done
    seen[r][c] = true;
    fill(r - 1, c); fill(r + 1, c); fill(r, c - 1); fill(r, c + 1);
  }
  let islands = 0;
  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (grid[r][c] === "#" && !seen[r][c]) {
        islands++;  // a piece nobody has reached yet
        fill(r, c); // mark all of it
      }
    }
  }
  return islands;
}
 
countIslands(["##..#", "#...#", "..#..", "##..."]); // 4
# grid: list of strings. "#" is land, "." is water.
def count_islands(grid):
    rows, cols = len(grid), len(grid[0])
    seen = [[False] * cols for _ in range(rows)]
 
    def fill(r, c):
        if not (0 <= r < rows and 0 <= c < cols):
            return  # off the map
        if grid[r][c] != "#" or seen[r][c]:
            return  # water, or done
        seen[r][c] = True
        fill(r - 1, c); fill(r + 1, c); fill(r, c - 1); fill(r, c + 1)
 
    islands = 0
    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == "#" and not seen[r][c]:
                islands += 1  # a piece nobody has reached yet
                fill(r, c)    # mark all of it
    return islands
 
count_islands(["##..#", "#...#", "..#..", "##..."])  # 4

Every cell is looked at once by the outer loops, and each land cell is filled once, with four neighbour checks, so the time is O(R × C) for a grid of R rows and C columns. The seen array and the recursion take O(R × C) space in the worst case.

#Detecting a cycle in a directed graph

In a directed graph, a seen set is not enough to find a cycle, because reaching a node that was seen earlier is normal when two different paths lead to it. A cycle exists only when the search reaches a node that is still on the current path. To tell these cases apart, each node gets one of three states: unvisited, in progress (its call has started but not returned) or done. If an edge leads to an in-progress node, that node is an ancestor of the current one, so the edge closes a cycle.

Cycle in a directed graph
function hasCycle(graph) {
  const state = new Map(); // missing = unvisited, 1 = in progress, 2 = done
  function visit(node) {
    state.set(node, 1);
    for (const next of graph[node]) {
      if (state.get(next) === 1) return true;
      if (!state.has(next) && visit(next)) return true;
    }
    state.set(node, 2);
    return false;
  }
  return Object.keys(graph).some((n) => !state.has(n) && visit(n));
}
def has_cycle(graph):
    state = {}  # missing = unvisited, 1 = in progress, 2 = done
 
    def visit(node):
        state[node] = 1
        for nxt in graph[node]:
            if state.get(nxt) == 1:
                return True
            if nxt not in state and visit(nxt):
                return True
        state[node] = 2
        return False
 
    return any(n not in state and visit(n) for n in graph)

For an undirected graph the rule is different. Every edge looks like a cycle because the neighbour you came from is always seen, so you ignore the parent and report a cycle only when you reach a seen node that is not the parent. In a directed graph, DFS also supports topological sort, which orders the nodes by the moment their calls return.

#When DFS is the wrong tool

DFS does not find shortest paths. It follows whatever route its neighbour order produces, and on the bus map it reached G after 6 edges when 4 were enough. For the fewest edges, use BFS, and for the lowest total weight on a weighted graph, use Dijkstra's algorithm.

#Pitfalls

Marking a node as seen too late

Mark a node as seen before you loop over its neighbours, not after. If you mark it afterwards, A visits B, B sees that A is not marked yet and visits A again, and the two calls keep calling each other until the stack overflows.

Stack overflow on large inputs

A 1,000 × 1,000 grid that is all land makes recursive DFS one million calls deep. Python stops at about 1,000 calls by default and raises RecursionError, and JavaScript engines throw "Maximum call stack size exceeded" somewhere between thousands and tens of thousands of calls. For large inputs, use the iterative version.

Using a seen set to find a cycle in a directed graph

A node that was seen earlier is not proof of a cycle in a directed graph. In the graph with edges A to B, A to C and B to C, the search reaches C twice and there is no cycle. Use the three states described above, so that only an edge to an in-progress node counts.

#In the interview

Signals that a problem needs DFS include a grid or a graph where you must find connected regions, count groups, or fill an area. Others are questions about whether a path or a cycle exists, problems that ask you to try every route and keep the ones that work (which is backtracking), and anything that describes tasks with prerequisites. Problems about a tree usually also use DFS, because a tree is a graph with no cycles, so no seen set is needed. If the statement says "minimum number of steps" or "shortest", the signal points to BFS instead.

These are the follow-up questions interviewers commonly ask.

#What happens if the input is huge or deeply nested?

Recursive DFS can overflow the call stack, because its depth can be as large as the longest path. The usual answer is to switch to an explicit stack, which is limited only by memory.

#How do you find the shortest path with DFS?

You do not, in the general case. DFS can be made to try every path and keep the shortest, but that takes exponential time, so the answer is to use BFS for unweighted graphs.

#How do you detect a cycle?

In an undirected graph, you report a cycle when you reach a seen node that is not the parent of the current node. In a directed graph, you track which nodes are on the current path and report a cycle when an edge leads back to one of them.

#Can you do it without recursion?

Yes. Push the start node on a stack, then repeatedly pop a node, skip it if it has been seen, mark it, and push its unseen neighbours.

#What is the time complexity, and does it depend on how the graph is stored?

With an adjacency list, DFS takes O(V + E) time, because each node is entered once and each node's neighbour list is read once. With an adjacency matrix, finding the neighbours of a node means scanning a whole row of V entries, so the total becomes O(V²). On a sparse graph that is much slower, so say which representation you are assuming.

#How do you return the path, not only whether one exists?

Keep a map from each node to the node it was reached from, and set it when the search first enters a node. When the target is reached, follow the map backwards to the start and reverse the result. The path is valid but not necessarily the shortest.

Quick check

Graph: { P: [Q, R], Q: [P, S], R: [P, S, T], S: [Q, R], T: [R] }. In what order does recursive DFS from P visit the nodes?

  1. Not quite. That is the BFS order. DFS goes from Q to S before it returns to P to try R.
  2. Right. The search goes from P to Q, from Q to S, from S to R and from R to T, skipping nodes that were already seen.
  3. Not quite. Q comes before R in P's neighbour list, so the search goes to Q first.

How many islands are in the grid ["#.#", ".#.", "#.#"]?

  1. Not quite. The land cells touch only at corners, and diagonal neighbours do not count.
  2. Right. Each of the 5 land cells has water on all four sides, so each one is its own island.
  3. Not quite. The middle cell is also an island on its own, which makes 5.

Why does iterative DFS check seen after popping a node, when it already checked before pushing it?

  1. Not quite. On the bus map, A and D both push C before either copy is popped. Without the second check, C would be visited twice.
  2. Right. The check before pushing only filters out nodes that were already visited. A node that is still waiting on the stack can be pushed again, so the extra copy has to be skipped when it is popped.
  3. Not quite. DFS never guarantees shortest paths, whatever checks it uses.

A directed graph has edges A to B, A to C and B to C. Does recursive DFS from A that only checks a seen set find a cycle?

  1. Not quite. Reaching a seen node by a second path is not a cycle in a directed graph. There is no way to get from C back to A.
  2. Right. C is reached through B and then again from A, but C is already finished when the second edge is checked, and no edge leads back to a node on the current path.
  3. Not quite. The number of outgoing edges has no connection to cycles.

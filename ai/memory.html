Memory

Models do not remember between calls. Learn how apps fake memory with saved notes and summaries, and how to decide what to save, update and load.

Your family doctor sees hundreds of people and does not remember you. But a minute before you walk in, they read your file: allergies, medication, what you agreed last time. A good file feels like memory. An empty file means starting over. A file that still says you smoke, ten years after you quit, is worse than either.

AI apps with "memory" work the same way. The model does not learn from your conversation. The app keeps a file and slips the right parts into the context before each call.

#Where memory actually lives

A model's weights are fixed while you use it, so every kind of memory is the app storing text and sending some back later. Three common layers:

  • The conversation, resent on every call. It lasts until the chat ends or the window trims it.
  • A running summary that replaces old turns in a long chat. It keeps the gist in far fewer tokens, but can lose details.
  • Long-term notes saved across chats: "vegetarian", "prefers short answers", "working on the billing project". Load a small set every time; search a large set with the same retrieval tools as documents.

Every memory system makes two decisions, over and over:

  1. Write: what is worth saving, and does it replace something already saved?
  2. Read: which saved notes belong in the context for this call?
Key idea

Memory is context chosen earlier. Like any context, it can be irrelevant, stale or wrong, and it costs space every time it is loaded.

#A memory over three sessions

A small note store keyed by topic, so a new fact on a topic replaces the old one, across three chats:

Step 4 matters most. An append-only store would give session 3 both "lives in Leeds" and "moved to Bristol", and the model would sometimes pick the wrong one.

#The store in code

class Memory {
  constructor() {
    this.notes = new Map(); // topic -> { fact, saved }
  }
  remember(topic, fact, saved) {
    this.notes.set(topic, { fact, saved }); // newer replaces older
  }
  forget(topic) {
    this.notes.delete(topic);
  }
  recall(topics) {
    return topics
      .filter((t) => this.notes.has(t))
      .map((t) => `- ${t}: ${this.notes.get(t).fact} (saved ${this.notes.get(t).saved})`)
      .join("\n");
  }
}
 
const memory = new Memory();
memory.remember("diet", "vegetarian", "March");
memory.remember("city", "Leeds", "March");
memory.remember("city", "Bristol", "June");
console.log(memory.recall(["city"])); // - city: Bristol (saved June)
class Memory:
    def __init__(self):
        self.notes = {}  # topic -> (fact, saved)
 
    def remember(self, topic, fact, saved):
        self.notes[topic] = (fact, saved)  # newer replaces older
 
    def forget(self, topic):
        self.notes.pop(topic, None)
 
    def recall(self, topics):
        return "\n".join(
            f"- {t}: {self.notes[t][0]} (saved {self.notes[t][1]})"
            for t in topics if t in self.notes
        )
 
memory = Memory()
memory.remember("diet", "vegetarian", "March")
memory.remember("city", "Leeds", "March")
memory.remember("city", "Bristol", "June")
print(memory.recall(["city"]))  # - city: Bristol (saved June)

Real systems are messier: usually a model reads the conversation and proposes notes, so it can save the wrong thing, and loading uses similarity search rather than exact topics. The shape stays the same: write with replacement, read selectively, keep the date.

#Common mistakes

Saving everything

Storing every passing remark fills memory with noise: moods, one-off tasks, jokes taken literally. Each loaded note costs tokens and can mislead. Save lasting facts, preferences and decisions.

Appending instead of updating

Append-only notes pile up contradictions. Key notes by topic so newer facts replace older ones, and keep dates so staleness shows.

Hidden memory

Users should be able to see, correct and delete what is remembered about them. Model-written memory can be wrong or sensitive; one nobody can inspect is a bug, and often a privacy problem (Privacy and Security).

#Try it yourself

Try it: What is worth remembering

A user tells a general-purpose assistant these things in one chat. For each, decide: long-term note, this chat only, or never store. Give a reason.

  1. "I work night shifts as a nurse."
  2. "Ugh, I'm so tired today."
  3. "Please always keep answers short, I read them on my phone."
  4. "My sister is visiting this weekend."
  5. "Here's my online banking password so you can check my balance: …"
Show a sample answer
  1. Save. A lasting fact that shapes answers, such as meal timing or sleep advice. Keep it visible and removable.
  2. This chat only. True today, false tomorrow. Saved moods make future replies oddly fixated on them.
  3. Save. A clear, lasting preference about every answer: exactly what long-term memory is for.
  4. This chat only, or save with an expiry date: useful this week, wrong next week.
  5. Never store. Secrets do not belong in memory, or ideally the conversation. A good assistant should tell the user not to share it.

Save what is lasting, useful and safe. When in doubt, ask: "Want me to remember that?"

#Check yourself

Quick check

An assistant with a memory feature recalls your favourite programming language in a brand-new chat. How?

  1. Not quite. Chatting does not change the model's weights.
  2. Right. Memory is saved text loaded back into the context.
  3. Not quite. Reliable recall across chats comes from a stored note.

A memory store holds "works at a bakery" from January and "works at a bookshop" from May. Best design fix?

  1. Not quite. The model must guess which is current, and sometimes guesses wrong.
  2. Right. Updating instead of appending removes the contradiction at the source.
  3. Not quite. That removes every good note too.

What is the main trade-off of replacing old chat turns with a running summary?

  1. Not quite. The point of a summary is to use fewer tokens.
  2. Right. Whatever the summary leaves out is gone from the context.
  3. Not quite. Summaries are just shorter text. No training happens.

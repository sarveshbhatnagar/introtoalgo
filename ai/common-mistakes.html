Common Mistakes

The mistakes people make most when working with AI every day, the patterns underneath them, and the small habits that prevent each one.

Sam has an afternoon to write the quarterly report for their manager, and an AI assistant to help. By 3:30 the report is sent. By 4:00 the manager has replied: the headline growth figure is wrong, and one of the quoted sources does not say what the report claims.

No single step was reckless. Each was a small shortcut that felt reasonable at the time. That is what the common mistakes look like in practice: several small errors that stack.

#One afternoon, six mistakes

Step through Sam's afternoon. Each step names the shortcut and the habit that would have caught it.

#The patterns underneath

Most everyday mistakes fall into four groups. Earlier lessons cover each one in depth; here is the short version, so you can recognise them as they happen.

PatternLooks likeThe habit
Under-askingOne-line requests for big jobs; no goal or definition of doneWrite a brief
Over-trustingFluent text accepted as true; numbers and links not checkedVerify claims in proportion to stakes
Over-sharingWhole files, logs or exports pasted "for context"Paste less, redact the rest
Over-delegatingHuge diffs accepted; learning outsourced; judgment handed overSmall steps; you do the thinking
Key idea

The assistant does the drafting. You stay responsible for the goal, the inputs, the checks and the decision to use the result.

#Four mistakes worth a closer look

#The regenerate loop

Pressing regenerate feels like progress because something new appears each time. But if the prompt does not change, you are drawing again from the same spread of likely answers (Sampling and Temperature explains why replies vary). After two tries, stop and say what is wrong.

Even here, check the result: (470,000 − 412,000) ÷ 412,000 is 14.1%. If the reply says anything else, the reply is wrong.

#Using AI where a plain tool is better

Adding up a column, sorting a list, finding every line that matches a pattern, converting a date format: a spreadsheet, a script or a search box does these exactly, every time. A language model does them approximately. Use the assistant to write the formula or the script, then let the tool do the work.

#Set and forget

An automation that worked in testing can drift: the inputs change, the provider updates the model, a new kind of request shows up. Keep a small sample of real outputs under review every week, and rerun your test set when anything changes. Failures that nobody looks at are failures that pile up.

#All-or-nothing trust

Some people trust everything after a few good answers. Others give up after one bad one. Both skip the useful middle: trust that depends on the task. An assistant can be very reliable at rewording your email and unreliable at quoting case law. Learn where your tools are strong by checking, and adjust how much you check as you learn.

Blaming the tool for a missing brief

When a result disappoints, reread your request first. If a capable stranger could not have done better with the same words, the fix is in the request, not in a different tool.

Hiding that you used AI when it matters

For routine drafting it rarely matters. For anything others will rely on, such as figures, legal text or code going to production, say what was AI-assisted and what you checked. It tells reviewers where to look, and it is often a rule at work or school.

Fixing the symptom, keeping the habit

Sam could correct the growth figure and move on. The useful fix is the habit behind it: arithmetic goes to a tool, and every number gets recomputed before sending.

#Try it yourself

Try it: Spot the mistakes

Read this description of how someone used an AI assistant at work. List every mistake you can find and the habit that would prevent it.

Show a sample answer
  1. Pasted the .env file. That file usually holds secrets. Paste only the code involved, with secrets replaced. If a real key went in, rotate it.
  2. "Fix the discount bug" with no detail. No description of the bug, the expected behaviour or the files involved. Write a brief: what is wrong, an example input and the expected output, which files to change.
  3. Accepted a 14-file change. Far too much to review. Ask for the smallest fix, in one place, and read the diff.
  4. "Make the tests pass". This invites the model to change the tests. Edits to tests are changes to the contract and need a reason.
  5. Green meant done. The tests had been changed, so passing them proved little. Check what changed in the test files before trusting the run.
  6. Merged with no time to watch it. Not an AI mistake as such, but AI-assisted changes deserve the same care as any other: merge when someone can notice and fix problems.

#Check yourself

Quick check

You have regenerated a reply four times and every version is slightly off in the same way. What is the best next step?

  1. Not quite. The prompt has not changed, so you are sampling from the same spread of answers. More tries rarely fix a consistent problem.
  2. Right. A consistent problem means something is missing from the request. Naming it changes what the model aims for.
  3. Not quite. Possible, but the same unclear request will usually produce the same kind of answer elsewhere.

You need the average of 400 values in a spreadsheet. What is the best use of an AI assistant?

  1. Not quite. The model may get it slightly wrong, and checking means doing the sum anyway.
  2. Right. The tool does the arithmetic exactly. The assistant helps where it is strong: knowing the formula.
  3. Not quite. Too broad. It is useful for writing formulas and code; it just should not be the calculator.

An AI-drafted summary you sent to a client contains a wrong date. Who is responsible?

  1. Not quite. The provider supplied a tool. Choosing to send its output was your decision.
  2. Right. Using an assistant does not move responsibility. That is why checks happen before anything leaves your hands.
  3. Not quite. Expected mistakes are exactly the ones you are expected to check for.

#What to practise next

Write your own five-line checklist from this module: brief, paste less, small steps, verify, own it. Keep it next to your assistant for a week. Before you let an AI agent act on its own, reread Guardrails: the same habits apply to every step an agent takes.

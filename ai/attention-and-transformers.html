Attention and Transformers

How each word in a sentence gathers meaning from the words before it. Attention traced with small numbers, then stacked into a transformer.

"Sam made soup and ate it." You know instantly that "it" is the soup, not Sam. You looked back, picked the words that mattered, and borrowed their meaning.

A language model must too. After tokenization, every token becomes a vector, a list of numbers that stands for its meaning. Alone, the vector for "it" says almost nothing; it must pick up information from "soup". That mechanism is attention, the core of the transformer, the design behind most of today's LLMs.

#The idea: ask, match, borrow

Each word holds up three things:

  • A query: what am I looking for? For "it", roughly "a thing mentioned earlier".
  • A key: what do I offer? For "soup", roughly "I am a thing, a food".
  • A value: the information I hand over if picked.

Each word compares its query with every key it can see; a good match scores high. Scores become shares that add up to 1, and the word collects a blend of everyone's values, weighted by those shares.

#Work it through with small numbers

Real vectors have thousands of numbers. Here each has two: pretend the first means "is a thing" and the second "is a person". Matching uses the dot product: multiply numbers in the same positions and add. The query for "it" is [2, -1]: it wants a thing and is put off by a person.

#The code

One attention step for one word, as traced. Real models also divide each score by the square root of the key vector's length before the softmax, so long vectors' big dot products do not put almost everything on one word. With two numbers per vector it is left out.

const dot = (a, b) => a.reduce((sum, x, i) => sum + x * b[i], 0);
 
function softmax(scores) {
  const biggest = Math.max(...scores); // subtract the max so exp() cannot overflow
  const exps = scores.map((s) => Math.exp(s - biggest));
  const total = exps.reduce((a, b) => a + b, 0);
  return exps.map((e) => e / total);
}
 
function attend(query, keys, values) {
  const weights = softmax(keys.map((k) => dot(query, k))); // match, then share
  const out = new Array(values[0].length).fill(0);
  weights.forEach((w, j) => {
    values[j].forEach((v, i) => { out[i] += w * v; }); // blend the values
  });
  return { weights, out };
}
 
const keys = [[0, 2], [0.5, 0], [2, 0], [0, 0], [1, 0], [0.5, 0]];
const values = [[0, 1], [0, 0], [1, 0], [0, 0], [0.5, 0], [0, 0]];
attend([2, -1], keys, values).out; // about [0.85, 0.00]
import math
 
def dot(a, b):
    return sum(x * y for x, y in zip(a, b))
 
def softmax(scores):
    biggest = max(scores)  # subtract the max so exp() cannot overflow
    exps = [math.exp(s - biggest) for s in scores]
    total = sum(exps)
    return [e / total for e in exps]
 
def attend(query, keys, values):
    weights = softmax([dot(query, k) for k in keys])  # match, then share
    out = [0.0] * len(values[0])
    for w, value in zip(weights, values):
        for i, v in enumerate(value):
            out[i] += w * v  # blend the values
    return weights, out
 
keys = [[0, 2], [0.5, 0], [2, 0], [0, 0], [1, 0], [0.5, 0]]
values = [[0, 1], [0, 0], [1, 0], [0, 0], [0.5, 0], [0, 0]]
attend([2, -1], keys, values)[1]  # about [0.85, 0.00]

Here the queries, keys and values were typed in by hand. In a real model, each comes from multiplying the word's current vector by a grid of numbers (a matrix) learned in training. Nobody writes rules like "pronouns look for things". Since a word's vector changes with context, the same word can ask different questions in different sentences.

#From one attention step to a transformer

A transformer repeats one block many times. Each block does two things to every token:

  1. Attention: gather information from the visible tokens, as above.
  2. Feed-forward: a small neural network transforms each token's vector on its own.

Each block adds its result to the vector rather than replacing it. After the last block, the vector at the final position becomes chances for the next token, and the loop from What Is an LLM picks one.

  • Many heads. Each block runs several attention steps side by side, called heads, each with its own learned numbers. A few get a nameable job, like linking a pronoun to its noun. Most do not.
  • Looking back only. A token attends to itself and earlier tokens, never later ones, in training too.
  • Word order. Attention alone cannot tell "dog bites man" from "man bites dog", so position information is mixed into the vectors.
Key idea

Attention lets every token build its meaning from the tokens it can see, weighted by relevance. A transformer stacks many rounds of it, so meaning gets richer layer by layer.

#Cost: every token looks at every other

With n tokens, each compares itself with up to n others, so one attention step does about n²/2 comparisons. Double the text and the work quadruples.

ApproachTimeSpaceWhy
Read a whole textO(n²)O(n²)Every token scores every earlier token. Space is for storing the scores; optimised implementations compute them in blocks to avoid that.
Add one new tokenO(n)O(n)Models keep earlier tokens' keys and values in memory, so a new token only scores against them.

This is one reason for the context window limit.

#Common mistakes

Reading attention as &quot;what the model is thinking about&quot;

Attention weights show where one head gathered information, not why the model gave an answer: many other heads and layers play a part. Treat them as a hint, not proof.

Thinking the toy numbers are how it really looks

Real vectors are long, and their numbers rarely line up with single human ideas like "thing". The mechanism is as shown; the meanings are learned and only partly understood.

Assuming the model reads ahead

If the clue that settles an ambiguous word comes after it, only later tokens can use it. So the order of information in your prompt can matter.

#Try it yourself

Try it: Be the attention head

For each sentence, which earlier word should the last word attend to most, and which second? Give rough shares summing to about 1, and name the deciding clue.

Show a sample answer
  1. them: keys about 0.7, grabbed about 0.15, the rest small. "them" is plural, and "keys" is the only plural thing.
  2. laughed: he about 0.5, Ben about 0.3, joke about 0.1. "laughed" needs a doer; "he" points to Ben, whose meaning an earlier layer may already have moved into "he".
  3. slippery: glass and shelf around 0.4 each. Either could be slippery, so the model may spread its attention or lean on what is common in its training text.

When the text does not decide, no attention pattern can make the answer certain.

#Check yourself

Quick check

A query is [1, 3] and a key is [2, 1]. What is the attention score?

  1. Right. 1 × 2 + 3 × 1 = 5. Multiply matching positions and add.
  2. Not quite. That adds all four numbers. Multiply matching positions first.
  3. Not quite. That forgets to add. A score is a single number.

Why does attention apply softmax to the scores?

  1. Right. The shares say how much of each value to blend in; the biggest score gets the biggest share.
  2. Not quite. Every word gets some share; "it" still took 0.11 from "ate".
  3. Not quite. Nothing is sorted; only the weights change.

Text A has 1,000 tokens, text B 2,000. Roughly how much more work is one attention step on B?

  1. Not quite. Twice as many tokens, each with twice as many to compare with.
  2. Right. Comparisons grow with n², so doubling n multiplies the work by about 4.
  3. Not quite. The model is fixed, but the number of token pairs grows with the text.

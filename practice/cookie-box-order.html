Cookie Box Order

Mediumdynamic programmingAlso known as Coin Change (fewest coins)

A bakery never sells loose cookies. They only come in boxes of a few fixed sizes, say 1, 6 and 10, and the shop has plenty of each. A school orders exactly 12 cookies for a class party: no more, no fewer.

Every box needs a ribbon and a label, so the baker wants to fill the order with as few boxes as possible.

Your task

Write fewestBoxes(sizes, count). sizes lists the box sizes; you may use any size as many times as you like. Return the smallest number of boxes whose sizes add up to exactly count.

If no mix of boxes adds up to exactly count, return -1. An order of 0 cookies needs 0 boxes.

fewestBoxes(sizes: int[], count: int) → int

Examples

Example 1
Input
sizes = [1, 6, 10]
count = 12
Output
2
Why

Two boxes of 6 make 12. Grabbing the biggest box first gives 10 + 1 + 1, which is 3 boxes. Biggest-first is not always best.

Example 2
Input
sizes = [4, 9]
count = 14
Output
-1
Why

With no 9-box you would need 14 / 4, which is not whole. With one 9-box, 5 is left, which 4s cannot make. Two 9-boxes are already too many. So 14 is impossible.

Constraints

  • 1 ≤ sizes.length ≤ 12
  • 1 ≤ sizes[i] ≤ 1,000, all sizes different
  • 0 ≤ count ≤ 10,000
Start with brute force

Recursively try every box as the next one until you hit the exact count or overshoot. The number of sequences explodes: with sizes 1, 2 and 5 and a count of 100 there are far more than a billion of them, and the same remainders like "40 cookies left" are solved again and again.

The greedy shortcut, always taking the biggest box that fits, is fast but wrong for sizes like [1, 6, 10].

Hints

0 of 4 shown
  1. Hint 1

    In the first example, the order of 12 must include some last box. If that last box is a 6, how many cookies did the boxes before it hold?

  2. Hint 2

    If the last box has size s, the rest is the best way to pack count - s cookies. Try every size as the last box and keep the cheapest: fewest(c) = 1 + min over s of fewest(c - s).

  3. Hint 3

    Many orders share the same smaller amounts. Solve them once each: build an array where best[c] is the fewest boxes for exactly c cookies, for every c from 0 up to count.

  4. Hint 4

    Set best[0] = 0 and every other entry to infinity (meaning "impossible so far"). For each c from 1 up, look at each size s ≤ c and set best[c] = min(best[c], best[c - s] + 1). At the end, infinity means -1.

How to solve it

Any packing has a last box. If its size is s, the other boxes must be the best packing of c - s. So the best for c is 1 plus the smallest best[c - s] over all sizes. Fill best from 0 upward so the smaller amounts are always ready.

Trace sizes [1, 6, 10], count 12. Only the interesting entries are shown:

  1. best[0] = 0. best[1] to best[5] can only use 1-boxes: 1, 2, 3, 4, 5.
  2. best[6]: last box 1 gives best[5] + 1 = 6; last box 6 gives best[0] + 1 = 1. So 1.
  3. best[10]: last box 10 gives best[0] + 1 = 1.
  4. best[11]: last box 1 gives best[10] + 1 = 2. (Last box 6 gives best[5] + 1 = 6.)
  5. best[12]: last box 1 gives best[11] + 1 = 3; last box 6 gives best[6] + 1 = 2; last box 10 gives best[2] + 1 = 3. So 2.

The table compares every option at each amount, which is exactly what greedy skips.

Reference solution
function fewestBoxes(sizes, count) {
  // best[c] = fewest boxes for exactly c cookies (Infinity = impossible)
  const best = new Array(count + 1).fill(Infinity);
  best[0] = 0;
  for (let c = 1; c <= count; c++) {
    for (const s of sizes) {
      // try s as the last box
      if (s <= c && best[c - s] + 1 < best[c]) best[c] = best[c - s] + 1;
    }
  }
  return best[count] === Infinity ? -1 : best[count];
}
def fewest_boxes(sizes, count):
    INF = float("inf")
    # best[c] = fewest boxes for exactly c cookies (INF = impossible)
    best = [0] + [INF] * count
    for c in range(1, count + 1):
        for s in sizes:
            # try s as the last box
            if s <= c and best[c - s] + 1 < best[c]:
                best[c] = best[c - s] + 1
    return -1 if best[count] == INF else best[count]
TimeO(count × k)For each of the count + 1 amounts, try each of the k box sizes once.
SpaceO(count)One table entry per amount from 0 to count.
What to take away

When items can be reused and you need an exact total with the fewest pieces, build a table over all totals from 0 up, and get each total from "one more piece" on top of a smaller total. It is the knapsack pattern with unlimited copies of each item.

Postcode Stretch on the Van

Mediumbinary searchAlso known as Find First and Last Position of Element in Sorted Array

A delivery van is loaded so the parcels sit on one long rack, sorted by postcode. Many parcels share a postcode, so they form a stretch of neighbours on the rack.

When the driver turns into a new postcode area, the tablet should light up exactly that stretch: the first and the last parcel for that postcode. If no parcel is for this area, it lights nothing.

Your task

Write findStretch(postcodes, code). postcodes is sorted in non-decreasing order. Return [first, last]: the smallest and largest index holding code. If code is not present (or the list is empty), return [-1, -1].

Aim for O(log n) even when one postcode fills most of the rack.

findStretch(postcodes: int[], code: int) → int[]

Examples

Example 1
Input
postcodes = [2040, 2040, 3115, 3115, 3115, 3120, 4500]
code = 3115
Output
[2, 4]
Why

Postcode 3115 fills indexes 2, 3 and 4. Index 1 is still 2040 and index 5 is already 3120, so the stretch is [2, 4].

Example 2
Input
postcodes = [2040, 2040, 3115, 3115, 3115, 3120, 4500]
code = 3200
Output
[-1, -1]
Why

3200 would sit between 3120 and 4500, but no parcel has it, so nothing lights up.

Constraints

  • 0 ≤ postcodes.length ≤ 100,000
  • 1000 ≤ postcodes[i], code ≤ 99,999
  • postcodes is sorted in non-decreasing order.
Start with brute force

Scan the rack and remember the first and last index where the postcode matches. Or binary search for any match and then walk left and right to the edges of the stretch.

Both are O(n) in the worst case. If 99,000 of 100,000 parcels share the postcode, the walk outward visits nearly all of them. Two boundary searches need about 34 looks in total, no matter how long the stretch is.

Hints

0 of 4 shown
  1. Hint 1

    A normal binary search for 3115 in the first example might land on index 3. Is that enough to know where the stretch starts and ends?

  2. Hint 2

    You could walk outwards from index 3, but if 90,000 parcels share the postcode that walk is slow. You need the two edges directly.

  3. Hint 3

    The start of the stretch is the first index with a value of at least code. The end is one before the first index with a value greater than code. Both are "first index where a condition becomes true".

  4. Hint 4

    Write one helper firstIndex(cond) with the lower-bound loop (lo = 0, hi = n, hi = mid when true, lo = mid + 1 otherwise). Call it for value >= code and for value > code. If the first result is out of range or does not hold code, return [-1, -1].

Walkthrough and solution

Unlocks when you pass every test. Stuck for a while? Looking is fine too, as long as you then close it and write the code yourself.

How to solve it

Do not look for the postcode. Look for the two edges of its stretch, each with its own binary search.

Trace [2040, 2040, 3115, 3115, 3115, 3120, 4500] with code 3115.

First search, condition v >= 3115:

  1. lo = 0, hi = 7, mid = 3: 3115 qualifies. hi = 3.
  2. lo = 0, hi = 3, mid = 1: 2040 does not. lo = 2.
  3. lo = 2, hi = 3, mid = 2: 3115 qualifies. hi = 2. Stop: first = 2, and it really holds 3115.

Second search, condition v > 3115:

  1. lo = 0, hi = 7, mid = 3: 3115 does not qualify. lo = 4.
  2. lo = 4, hi = 7, mid = 5: 3120 qualifies. hi = 5.
  3. lo = 4, hi = 5, mid = 4: 3115 does not. lo = 5. Stop: the stretch ends at 5 - 1 = 4.

The answer is [2, 4]. The check after the first search matters: when the code is missing, the first search still returns a position (where the code would go), so you must confirm that position actually holds it.

Reference solution
function findStretch(postcodes, code) {
  // first index where isTrue(value) holds, or n if none
  const firstIndex = (isTrue) => {
    let lo = 0, hi = postcodes.length;
    while (lo < hi) {
      const mid = Math.floor((lo + hi) / 2);
      if (isTrue(postcodes[mid])) hi = mid;
      else lo = mid + 1;
    }
    return lo;
  };
  const first = firstIndex((v) => v >= code);
  if (first === postcodes.length || postcodes[first] !== code) return [-1, -1];
  const afterLast = firstIndex((v) => v > code);
  return [first, afterLast - 1];
}

TimeO(log n)Two binary searches, each halving the range every round.
SpaceO(1)A few indexes.
What to take away

To find the range of a value in a sorted list, search twice for boundaries: the first index with value >= x and the first with value > x. These are bisect_left and bisect_right in Python, and the range is [left, right - 1].

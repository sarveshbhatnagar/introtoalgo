Shortest Steep Climb

Mediumsliding windowAlso known as Minimum Size Subarray Sum

A cycling coach plans hill training on a long mountain road. The road is split into segments of equal length, and the map lists how many metres each segment climbs, in order. The road only goes up, so every number is positive.

For today's drill, a rider must climb at least target metres without stopping, over as few segments as possible. The coach wants the shortest unbroken stretch of road that climbs that much.

Your task

Write shortestClimb(gains, target). Return the smallest number of consecutive segments whose gains add up to at least target.

If no stretch climbs enough, not even the whole road, return 0.

shortestClimb(gains: int[], target: int) → int

Examples

Example 1
Input
gains = [30, 10, 60, 20, 40, 50]
target = 100
Output
3
Why

Segments 4 and 5 climb 40 + 50 = 90, just short. The three segments 3 to 5 climb 20 + 40 + 50 = 110, and segments 0 to 2 climb exactly 100, which counts. No two neighbouring segments reach 100 (the largest pair is 90), so the answer is 3.

Example 2
Input
gains = [5, 5, 5]
target = 20
Output
0
Why

The whole road only climbs 15 metres. No stretch reaches 20, so return 0.

Constraints

  • 0 ≤ gains.length ≤ 10,000
  • 1 ≤ gains[i] ≤ 10,000
  • 1 ≤ target ≤ 1,000,000,000
Start with brute force

For every starting segment, add segments one by one until the total reaches target, and record how many it took. Keep the smallest count.

That is up to n steps for each of n starts. With 10,000 segments and a large target it is about 50 million additions, and each start re-adds almost the same segments as the start before it.

Hints

0 of 4 shown
  1. Hint 1

    In the first example, start at segment 0 and keep adding segments until you reach 100. You stop at segment 2. Now, if you also drop segment 0, do you still have enough?

  2. Hint 2

    Once a stretch is long enough, the only way to find a shorter one with the same right end is to remove segments from the left. Because every gain is positive, removing one always lowers the total.

  3. Hint 3

    So use a window: grow it on the right until it climbs enough, then shrink it from the left for as long as it still climbs enough, recording the length each time.

  4. Hint 4

    Keep left and a running total. For each right: add gains[right]. Then, while total ≥ target, record right - left + 1 if it is smaller than the best, subtract gains[left] and move left forward.

Walkthrough and solution

How to solve it

Because every gain is positive, adding a segment always raises the total and removing one always lowers it. That makes a sliding window safe: grow the right edge until the stretch is steep enough, then pull in the left edge as far as you can while it stays steep enough.

Trace [30, 10, 60, 20, 40, 50] with target 100:

  1. Add 30, 10, 60: total 100 at right = 2. Enough. Length 3, best = 3. Drop 30: total 70. Not enough, stop shrinking.
  2. Add 20: total 90. Not enough.
  3. Add 40: total 130, window is segments 1 to 4. Length 4, not better. Drop 10: total 120, length 3 (segments 2 to 4), not better. Drop 60: total 60. Stop.
  4. Add 50: total 110, segments 3 to 5. Length 3, not better. Drop 20: total 90. Stop.

The answer is 3. Each segment entered the window once and left at most once, so the whole thing is about 2n steps. Note the window idea depends on the gains being positive: with negative numbers, dropping a segment could raise the total and the shrinking rule would be wrong.

Reference solution
function shortestClimb(gains, target) {
  let left = 0, total = 0, best = 0;
  for (let right = 0; right < gains.length; right++) {
    total += gains[right];
    // Shrink from the left while the stretch still climbs enough.
    while (total >= target) {
      const len = right - left + 1;
      if (best === 0 || len < best) best = len;
      total -= gains[left];
      left++;
    }
  }
  return best;
}
def shortest_climb(gains, target):
    left = total = best = 0
    for right, g in enumerate(gains):
        total += g
        # Shrink from the left while the stretch still climbs enough.
        while total >= target:
            length = right - left + 1
            if best == 0 or length < best:
                best = length
            total -= gains[left]
            left += 1
    return best
TimeO(n)right moves n times and left moves at most n times in total.
SpaceO(1)Two indexes, a running total and the best length.
What to take away

For "shortest stretch that reaches at least X" on non-negative numbers, grow the window until it is valid, then shrink it from the left while it stays valid, recording the size each time. Shortest-window problems shrink inside the loop; longest-window problems shrink only to restore validity.

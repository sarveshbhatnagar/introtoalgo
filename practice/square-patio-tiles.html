Square Patio Tiles

Easybinary searchAlso known as Sqrt(x)

You have a pile of identical square paving tiles left over from a job. You want to lay them as one square patio, as large as possible. A patio with side 4 needs 4 × 4 = 16 tiles. Tiles that do not fit go back in the shed.

Given the number of tiles, how long can the side of the patio be?

Your task

Write largestSide(tiles). Return the largest whole number k with k × k ≤ tiles. With 0 tiles the answer is 0.

Do not use a built-in square root or power function. Find k by searching.

largestSide(tiles: int) → int

Examples

Example 1
Input
tiles = 17
Output
4
Why

A side of 4 uses 16 tiles, and 1 is left over. A side of 5 would need 25, which you do not have. So 4.

Example 2
Input
tiles = 36
Output
6
Why

6 × 6 = 36 exactly, so every tile is used.

Constraints

  • 0 ≤ tiles ≤ 2,000,000,000
Start with brute force

Try side 1, 2, 3, … and stop at the first one whose square is more than tiles. The answer is one less.

That takes about √tiles steps. For 2,000,000,000 tiles that is 44,721 steps. Not terrible, but binary search needs about 31, and the same idea scales to problems where a linear scan is far too slow.

Hints

0 of 4 shown
  1. Hint 1

    Write down sides 0, 1, 2, 3, 4, 5, 6 and mark each one "fits" or "too big" for 17 tiles. What pattern do the marks make?

  2. Hint 2

    Every side up to some point fits, and every side after it is too big. The answer is the last side that fits. That is a sorted yes/no row, even though nobody gave you a list.

  3. Hint 3

    Binary search over side lengths from 0 to tiles. For a middle side, the check is just mid * mid <= tiles. If it fits, the answer is mid or larger. If not, it is smaller.

  4. Hint 4

    Keep lo = 0, hi = tiles. While lo < hi, take the upper middle, mid = floor((lo + hi + 1) / 2). If it fits, lo = mid; else hi = mid - 1. The upper middle stops the loop from getting stuck when hi = lo + 1.

Walkthrough and solution

Unlocks when you pass every test. Stuck for a while? Looking is fine too, as long as you then close it and write the code yourself.

How to solve it

There is no list here, but there is still a sorted row of yes/no answers: "does a side of k fit?" is yes for small k and no for large k. Binary search finds the last yes.

Trace 17 tiles:

  1. lo = 0, hi = 17, mid = 9. 81 > 17, too big. hi = 8.
  2. lo = 0, hi = 8, mid = 4. 16 ≤ 17, fits. lo = 4.
  3. lo = 4, hi = 8, mid = 6. 36, too big. hi = 5.
  4. lo = 4, hi = 5, mid = 5. 25, too big. hi = 4.
  5. lo = hi = 4. Return 4.

Look at step 4. With the usual lower middle, mid would be 4, it would fit, lo would stay 4, and the loop would never end. When the "yes" branch sets lo = mid, round the middle up.

In languages with 32-bit integers, mid * mid can overflow for large mid. There, compare mid <= tiles / mid instead. JavaScript and Python numbers are big enough for this range.

Reference solution
function largestSide(tiles) {
  let lo = 0, hi = tiles; // the answer is in [lo, hi]
  while (lo < hi) {
    const mid = Math.floor((lo + hi + 1) / 2); // upper middle
    if (mid * mid <= tiles) lo = mid; // mid fits: answer is mid or bigger
    else hi = mid - 1;                // too big: answer is smaller
  }
  return lo;
}
def largest_side(tiles):
    lo, hi = 0, tiles  # the answer is in [lo, hi]
    while lo < hi:
        mid = (lo + hi + 1) // 2  # upper middle
        if mid * mid <= tiles:
            lo = mid  # mid fits: answer is mid or bigger
        else:
            hi = mid - 1  # too big: answer is smaller
    return lo
TimeO(log n)The range of candidate sides halves each round, about 31 rounds for 2 billion.
SpaceO(1)A few numbers.
What to take away

Binary search does not need an array. If you can ask a yes/no question about a number, and the answers switch from yes to no only once, search the numbers directly. To find the last yes, set lo = mid on yes and use the upper middle.
